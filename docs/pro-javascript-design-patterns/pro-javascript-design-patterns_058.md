# 构建与组合：从零开始制作组合模式

## 理解组合模式

组合模式是一种结构型设计模式，它创建了一个层次结构来处理对象，使得客户端可以一致地处理单个对象和对象的组合。

组合模式允许你将对象组合成树形结构来表示整体-部分的层次关系。它让客户端可以统一处理单个对象和对象的组合。

简单来说，组合模式就像是一个树形结构，其中的节点可以是叶子节点（`leaf`）或复合节点（`composite`）。叶子节点执行具体的操作，而复合节点则将操作委派给其子节点。

## 组合模式的组成部分

### 组件的结构

在组合模式中，对象分为两种类型：叶子（`leaf`）和复合节点（`composite`），如图 3-1 所示。

复合节点是一个递归定义，但正是这种递归使得组合模式如此强大。一个复合节点由其他复合节点和叶子节点组成。只有叶子节点不包含子对象。

叶子节点是组合模式中最基本的单元，它是执行操作的对象。

## 使用组合模式

你只能在满足以下条件时使用组合模式：

-   你希望执行操作的对象是一组具有层次结构的对象，这种层次结构在开发时可能是未知的。
-   你想要执行的操作是一组子对象，或者是对这些子对象的一个子集。

组合模式擅长在大量对象上执行操作。它被设计用来组织对象并将操作从一层传递到下一层。这使得对象可以更松散地耦合，并且可以使用多个类或实例进行互换。

生成的代码将更加模块化和更易于维护。

## 组件树

组件树是一种层次结构，用于组织 UI 组件。类似于文件系统，树中的每个节点都可以包含子节点，根节点位于树的顶部。

图 1：展示了 UI 组件的层次结构。

### 关于组件树

组件树中的每个节点都是一个组件实例，所有组件实例共享相同的接口。这意味着组件树中的每个节点都包含对子节点的引用，而叶子节点则没有子节点。因为所有对象都继承自同一个接口，它们可以被统一处理——所有子节点都支持相同的方法和属性。

例如，一个 UI 框架可能有一个顶层的 `Window`（窗口）组件，它包含一个 `Panel`（面板）组件，面板中又包含 `Button`（按钮）和 `TextField`（文本字段）组件。这种树形结构使得事件的传播或属性的继承变得容易。

### 更新组件树

当 UI 需要更新时，框架会遍历组件树、比较新旧状态，并只更新需要变化的部分。这个过程称为“协调”（Reconciliation）。在 React 这样的框架中，`render()` 函数返回一个组件树，而框架则负责将其高效地转换为 DOM 操作。

React 的 `Virtual DOM`（虚拟 DOM）就是一个组件树的轻量级表示。当状态改变时，React 会生成一个新的虚拟 DOM 树，并与旧的树进行比较（diffing），然后只更新实际变化的部分。

## 使用组件树的好处

### 封装性

每个组件封装了其自身的状态和行为。这使得代码更模块化、更易于维护。例如，一个 `Button` 组件管理自己的点击事件和样式，不会影响页面上的其他按钮。

### 可复用性

组件可以多次复用。你可以定义一个 `UserCard`（用户卡片）组件，然后在用户列表、搜索结果等多个地方使用它。这减少了重复代码，并确保了 UI 的一致性。

### 可组合性

组件可以组合成更复杂的 UI。例如，一个 `Form`（表单）组件可以由 `InputField`（输入框）、`Dropdown`（下拉菜单）和 `SubmitButton`（提交按钮）组合而成。这种组合能力使得构建复杂的用户界面变得更加直观。

# Java 类

## 什么是封装

封装是面向对象编程的四大基本概念之一。它的核心思想是将数据和操作数据的方法绑定在一起，并对外隐藏实现细节。

在 Java 中，封装的主要实现方式是通过`class`（类）来定义数据结构，并将相关的变量和方法组织在一起。

## 封装的优点

封装的主要优点是提高了代码的可维护性和安全性。通过封装，我们可以控制对类内部数据的访问权限，避免外部代码直接修改对象的内部状态。

具体来说，封装带来的好处包括：
- **数据隐藏**：将类的内部实现细节隐藏起来，只暴露必要的接口。
- **提高安全性**：防止外部代码意外或恶意地修改对象的状态。
- **降低耦合度**：减少类与类之间的直接依赖，提高代码的模块化程度。
- **便于维护**：当内部实现发生变化时，只要接口不变，就不会影响外部代码。

## 访问修饰符

Java 提供了一系列访问修饰符来控制类、变量和方法的可见性。常见的访问修饰符包括：

- `public`：任何地方都可以访问。
- `protected`：同一个包内或子类可以访问。
- `default`（没有修饰符）：同一个包内可以访问。
- `private`：只有同一个类内部可以访问。

通过合理使用这些修饰符，我们可以实现不同级别的封装。

## 示例

```java
public class Person {
    private String name;
    private int age;
    
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
    
    public String getName() {
        return this.name;
    }
    
    public int getAge() {
        return this.age;
    }
}
```

在上面的例子中，`name`和`age`被声明为`private`，外部无法直接访问它们。只能通过`getName()`和`getAge()`这样的公共方法来获取这些私有变量的值。

## Getter 和 Setter 方法

封装通常通过 getter 和 setter 方法来实现。Getter 方法用于获取私有变量的值，而 setter 方法用于设置私有变量的值。

```java
public class Person {
    private String name;
    private int age;
    
    public String getName() {
        return this.name;
    }
    
    public void setName(String name) {
        this.name = name;
    }
    
    public int getAge() {
        return this.age;
    }
    
    public void setAge(int age) {
        this.age = age;
    }
}
```

通过 getter 和 setter 方法，我们可以在设置或获取变量值时添加额外的逻辑，例如数据验证或计算。

## 可变性与不可变性

可变性（Mutability）是指对象的状态在创建后是否可以改变。在 Java 中，我们可以在类定义后通过 getter 和 setter 方法来修改对象的状态。

与此相对的是不可变性（Immutability）。不可变对象在创建后其状态不能被修改。Java 中的`String`类就是一个典型的不可变类。

不可变对象有许多优点，例如线程安全、易于调试和缓存。在 Java 中，可以通过将类的所有字段声明为`final`，并且不提供任何 setter 方法来创建不可变类。

在 Java 中，可以通过将类的所有字段声明为`final`，并且不提供任何 setter 方法来创建不可变类。这种方式可以确保对象的状态在创建后不会被修改。

不可变性并不是在所有情况下都是最优的选择，它有一个明显的缺点：如果需要修改对象的状态，必须创建一个新的对象，这可能会导致性能开销。因此，在需要频繁修改对象状态的场景下，可变对象可能是更好的选择。

## 封装与继承

封装与继承是面向对象编程的两个重要概念。通过继承，子类可以继承父类的属性和方法。但是，封装要求我们控制对类内部数据的访问权限，因此我们需要根据实际情况选择合适的访问修饰符。

在继承中，`protected`修饰符允许子类访问父类的成员，而`private`修饰的成员则不能被继承。因此，在设计类时，需要权衡封装性和继承性的需求。

### 接口与抽象类

接口和抽象类是 Java 中实现封装和抽象的两种重要方式。它们都允许我们定义方法的签名，而不提供具体实现。这样，外部代码只需要知道接口或抽象类的方法签名，而不需要关心具体的实现细节。

接口是完全抽象的，它只包含方法的声明，不包含任何实现。抽象类则可以包含抽象方法和具体方法。通过使用接口和抽象类，我们可以实现更高层次的封装，将实现细节完全隐藏起来。

## 总结

封装是 Java 面向对象编程的核心概念之一。它提供了一种机制，让我们可以将数据和操作数据的方法绑定在一起，并控制外部对这些数据的访问权限。通过合理使用访问修饰符、getter 和 setter 方法、接口和抽象类等技术，我们可以创建健壮、可维护、可扩展的 Java 程序。封装不仅提高了代码的安全性和可维护性，还为多人协作开发提供了基础。

#### 接口 vs 抽象类

在面向对象编程中，接口和抽象类是两种用于定义对象间交互方式的工具。它们在 Java 中扮演着重要的角色。

#### 抽象类

抽象类是面向对象编程中的一个核心概念。它允许你定义一些方法的签名，而将具体的实现留给子类来完成。**接口 vs 抽象类** 设计原则正是基于这一思想：接口应该定义“做什么”，而抽象类则关注于“如何做”。在 Java 中，抽象类通过 `abstract` 关键字来声明，并且可以包含具体的方法实现。

#### 设计原则：针对接口编程，而非针对实现

核心设计原则是：你应当依赖接口（如 `Comparable`），而不是具体的实现类。这允许你基于对象提供的功能（通过接口定义的）来编写代码，而不是依赖它们的具体类型。例如，一个包含 `sort(List)` 方法的类可以处理任何实现了 `Comparable` 接口的对象，因为所有实现该接口的对象都承诺提供 `compareTo()` 方法。

这样，你可以根据功能对对象进行分组，而不是根据它们的具体类。例如，一个包含 `compareTo()` 方法的类集合可以互换使用，因为它们都遵循相同的约定。

#### 什么是接口

接口是 Java 中一个极其灵活且强大的概念。它提供了一种指定对象应具有哪些方法的方式，但并不指定如何实现这些方法。它只是暗示（或至少是提示）了这些方法的语义。例如，如果一个接口包含一个名为 `setName` 的方法，你可以合理地认为该接口的实现应该接受一个字符串参数并将其赋值给一个变量。

这允许你基于对象提供的功能对对象进行分组。例如，一个包含 `compareTo()` 方法的类集合可以互换使用，因为它们都遵循相同的约定。一个实现了 `Comparable` 接口的类可以在 `Collections.sort()` 或对象比较器中使用，如果它们都实现了该接口的 `compareTo()` 方法。

#### 接口在 Java 中的演变

最早期的 Java 接口非常严格，它们只能声明方法签名，而不能包含任何实现代码。从 Java 8 开始，接口可以包含 `default` 方法和 `static` 方法。这些方法可以包含具体的实现逻辑，这使得在不破坏现有实现的类的情况下更容易地扩展接口。从 Java 9 开始，接口还可以包含 `private` 方法，用于在接口内部共享代码。

#### 接口 vs 抽象类

接口和抽象类都用于在 Java 中实现抽象。它们之间的主要区别在于：一个类可以实现多个接口，但只能继承（`extends`）一个抽象类。这种区别反映了它们在设计上的不同用途：抽象类用于定义类层次结构中的共享状态和行为，而接口则用于定义类型间的契约和能力。

#### 使用接口的优势

使用接口的关键优势在于它们促进了松散耦合。如果一个类依赖于一个接口，你可以轻松地切换其具体实现，而无需修改依赖于该接口的代码。此外，接口使得代码更容易测试，因为你可以轻松地创建模拟对象。

接口还限制了错误的发生范围。如果代码中的错误不是由接口定义的方法引起的，而是由某个具体实现中的方法引起的，那么错误就会被限制在该实现内部，使得调试变得更加容易。如果你对一个接口进行添加操作，你可以依赖这样一个事实：你将会看到一个错误消息，如果你的某个类没有该添加的操作的话。

#### 测试与调试更方便

使用接口使得测试和调试变得更加容易。像 Java 这种弱类型语言（相对而言），追踪类型不匹配错误是很困难的。使用接口使得这些错误更容易被发现，因为任何对接口的更改都必须同步反映到所有实现该接口的类中。如果你向一个接口添加了一个操作，你可以依赖这样一个事实：如果你的某个类没有该操作，你会立即看到错误。

使用接口并非没有缺点。Java 是一种极其灵活的语言，部分原因是它是松散类型的。使用接口是一种部分强制执行类型安全的方式。使用接口是一种松散耦合的编程方式，因为它允许不相关的对象被统一处理。它也让你的代码更加稳定，因为任何对一个接口的修改都必须同样对所有实现它的类进行修改。如果你为接口添加了一个操作，你可以依赖这样一个事实：如果其中一个类没有该操作，你会立即看到错误。

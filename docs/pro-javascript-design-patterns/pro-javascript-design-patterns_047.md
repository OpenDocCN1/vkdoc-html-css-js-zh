# 前言

## 阅读指南

本文档介绍如何使用**工厂方法**模式创建`List.of()`和`Map.of()`等集合实例，以及如何利用该模式简化代码结构。

## 核心概念

### 什么是工厂方法模式？

**工厂方法**是一种创建型设计模式，它提供了一种在不指定具体类的情况下创建对象的方法。在 Java 的集合框架中，`List`和`Map`接口的工厂方法（如`List.of()`、`Map.of()`）就是该模式的典型应用。

### 主要优势

- **解耦**：将对象创建与使用分离
- **灵活性**：允许子类决定实例化哪个类
- **简洁性**：减少构造函数调用，提升代码可读性

## 核心 API 说明

### `List.of()`

`List.of()`是 Java 9 引入的静态工厂方法，用于创建不可变的列表。它接受任意数量的参数，并返回包含这些元素的只读列表。

### `Map.of()`

`Map.of()`用于创建不可变映射，接受键值对作为参数（最多支持 10 对键值对）。

### 使用示例

**创建不可变列表：**

```java
List<String> list = List.of("Apple", "Banana", "Cherry");
```

**创建不可变映射：**

```java
Map<String, Integer> map = Map.of("Apple", 1, "Banana", 2);
```

## Session 类方法说明

### `SimpleSession`

- `post` 方法：执行 `for (var i = 0; i < storedRequests.length; i++)` 循环。如果 `storedRequests[i]` 存在，则发送请求并返回。
- `prototype` 的 `request` 方法：如果 `this.request` 存在，则发送请求并返回；如果当前有等待中的请求，则返回 `this`。
- `request` 方法：如果 `this.request` 存在，则发送请求并返回。

### `AppendableSession`

- `request` 方法：如果当前有等待中的请求，则返回 `this`；否则发送请求并返回。
- `prototype` 的 `request` 方法：如果当前有等待中的请求，则返回 `this`。

### `CachedSession`

- `prototype` 的 `request` 方法：执行 `for (var i = 0; i < storedRequests.length; i++)` 循环。如果 `storedRequests[i]` 存在，则发送请求并返回；如果当前有等待中的请求，则返回 `this`。
- `request` 方法：执行 `for (var i = 0; i < storedRequests.length; i++)` 循环。如果 `storedRequests[i]` 存在，则发送请求并返回；如果当前有等待中的请求，则发送请求并返回。

# 工厂方法模式详解

## 创建不可变映射

```java
Map<String, Integer> map = Map.of("key1", 1, "key2", 2, "key3", 3);
```

## 深入理解

### 为什么使用工厂方法而非构造函数？

使用`List.of()`和`Map.of()`等工厂方法的主要优势在于代码清晰度和简洁性。相比于传统的`new ArrayList<>()`和`new HashMap<>()`，工厂方法允许您在一个地方集中管理所有实例化代码，从而提高代码可维护性。

### 与生成器模式的区别

| 特性 | 工厂方法 | 生成器 |
|------|----------------|---------|
| 适用场景 | 创建简单对象 | 创建复杂对象 |
| 代码量 | 较少 | 较多 |
| 灵活性 | 中等 | 高 |

## 完整示例

以下是使用`工厂方法`模式创建集合实例的完整代码示例：

```java
// 创建 List 实例
List<String> list = List.of("a", "b", "c");

// 创建 Map 实例
Map<String, Integer> map = Map.of("key1", 1, "key2", 2);
```

## 最佳实践

### 何时使用工厂方法？

- 当您需要创建不可变集合时
- 当创建逻辑相对简单时
- 当您希望避免编写大量构造函数时

### 注意事项

- 工厂方法创建的集合不可修改
- 工厂方法适用于小型集合（不超过 10 个元素）
- 对于大型集合，建议使用`ArrayList`或`HashMap`的构造函数

## 进阶主题

### 自定义工厂方法

您也可以创建自己的工厂方法：

```java
public class MyFactory {
    public static MyObject create() {
        return new MyObject();
    }
}
```

### 测试中的工厂方法

在单元测试中使用工厂方法可以简化测试对象的创建：

```java
@Test
public void testListCreation() {
    List<String> list = List.of("test");
    assertEquals(1, list.size());
}
```

## 结论

`工厂方法`模式是 Java 集合框架中一个强大且实用的工具。它简化了不可变集合的创建过程，提供了更清晰、更安全的代码结构。通过本文档中的示例和最佳实践，您可以更有效地利用这一模式来管理对象创建逻辑。

**桥梁模式**

在 API 的实现世界中，桥梁模式非常有用。事实上，它们可能是在构建 JavaScript API 时最被低估的模式之一。如果你正在构建一个 JavaScript API，可以使用此模式来确保依赖的类和对象与其松散耦合。

正如“四人帮”在《设计模式》中所定义的，桥梁模式应将`抽象`与它的`实现`解耦，以便两者可以独立变化。在进行事件驱动编程时，桥梁模式也非常有益，这是一种在 JavaScript 中经常使用的编程风格。

如果你正在进入 JavaScript API 开发领域，你很可能需要创建大量的 getter、setter、请求和其他基于动作的方法。无论它们是用于创建 Web 服务 API，还是简单的访问器和修改器方法，桥梁模式都将帮助你保持 API 代码的整洁和实现的清晰。

**示例：事件监听器**

桥梁模式最常见和实用的用例之一是事件监听器。假设你有一个名为 `getBeerById` 的 API 函数，它根据标识符返回啤酒数据。实际上，在任何 Web 应用程序中，你希望这些数据能在用户执行诸如点击元素等操作时被获取。你点击的元素很可能包含啤酒的 ID，要么存储在元素自身的 `ID` 中，要么在其他自定义属性中。以下是一种实现方法：

添加事件监听器 `onClick` 来调用 `getBeerById` 函数。

```javascript
var id = this.id;
asyncRequest('GET', 'beer.uri?id=' + id, function(resp) {
    // Callback response.
    console.log('Requested Beer: ' + resp.responseText);
});
```

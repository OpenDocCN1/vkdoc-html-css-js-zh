## 清单组件

每个扩展程序都有一个名为`manifest.json`的 JSON 格式清单文件，它向 Chrome 浏览器提供扩展程序的重要信息。为此，您需要在清单中声明扩展程序将要使用的功能（例如输入类型——浏览器操作、快捷键等），并定义其对应的值。

除此之外，Google Chrome 扩展程序框架还提供了大量 API，可用于访问 Chrome 浏览器的实用功能，例如`bookmarks`、`tabs`、`history`等。要使用这些功能，您还需要在清单中`声明`它们的用途。本章后续主题将详细说明清单的更多细节。

在编写本书时，要创建最简单的有效 Google Chrome 扩展程序（不执行任何操作），只需一个包含清单文件的文件夹，清单文件需包含以下必需属性（也将在第 1 章中讨论）。

- `manifest_version` — 指示清单文件格式的版本（编写本书时为 2）
- `name` — 指示扩展程序的名称，例如`HelloBrowserAction`
- `version` — 指示扩展程序的版本，例如`1.2`

## 扩展程序运行时

在本节中，您将从开发者的角度了解扩展程序开发。具体来说，您将了解`扩展程序运行时`（不要与扩展程序框架提供的实际运行时 API 混淆，即`chrome.runtime` API）。

现在您已经明白扩展程序的逻辑是用 JavaScript 编写的。鉴于 JavaScript 的事件驱动特性，您可能会好奇扩展程序的生命周期。例如，考虑到用于创建扩展程序的各种输入组件，您可能会考虑监听这些输入触发的事件，然后做出相应响应。

扩展程序框架中的每个输入组件（ContentUI 除外）都有一些关联事件（例如，Browser-Action 和 Page-Action 输入组件分别关联以下事件——`chrome.browserAction.onClicked`事件和`chrome.pageAction.onClicked`事件）。要监听这些事件，您需要附加`监听器`函数。这些函数在代表扩展程序运行时的脚本组件中创建（并分配给事件）。

因此，当扩展程序在浏览器中加载时，首先读取清单以授予访问某些 API（例如`tabs` API）的权限。然后，视图和脚本被加载。最后，监听器函数被分配给输入组件。

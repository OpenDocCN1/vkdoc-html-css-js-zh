# 前瞻断言

*前瞻断言*会匹配字符，但匹配成功后会将操作回退。前瞻断言分为两种类型：*肯定型*和*否定型*。

当我们的匹配项**必须紧跟在**某个特定模式之后时，我们使用肯定型前瞻断言。

当我们的匹配项**不应紧跟**某个特定模式时，我们使用*否定型前瞻断言*。表 8-1 展示了其语法。

**表 8-1** 前瞻断言语法

| 前瞻断言类型 | PCRE 语法 | Perl 6 语法 |
| --- | --- | --- |
| 肯定型 | `(?=pattern)` | `<?before pattern>` |
| 否定型 | `(?!pattern)` | `<!before pattern>` |
| 单词边界 | `\b` | `>>` |

这些语法可能不太美观，尤其是在否定断言的情况下。不过，依我的经验来看，只要多用用就会习惯的。在此之前，请随身携带你的速查手册。

与 `(?:pattern)` 类似，前瞻断言不会捕获子字符串。

由于前瞻断言可以包含任何字面量或元字符，因此在前瞻断言内部定义的捕获组将会捕获匹配到的字符串。事实上，这是捕获前瞻断言值的唯一方法。

`/a(?=.c)b/` 中的前瞻断言 `(?=.c)` 会按以下方式匹配字符串 `abc`：

1.  首先读取 `a`。
2.  然后进入前瞻断言，记下索引 1（指向 `abc` 中的字符 `b`）。
3.  在前瞻断言内部，我们匹配了任意字符 `b`。
4.  在前瞻断言内部，我们匹配了字符 `c`。
5.  由于前瞻断言成功，我们成功退出该结构，并回退到字符串中的位置 1。
6.  我们匹配字符串中的字符 `b`。
7.  正则表达式匹配成功，返回从位置 0 开始的子字符串 `ab`。单词边界的作用类似于肯定型前瞻断言。

**示例 1**：使用 PCRE 方言，在字符串中匹配 `list`、`lost` 或 `lust`，要求匹配的字符串必须结束一个非空白字符序列。

**解决方案：**

我们只需在匹配序列的末尾使用一个单词边界锚点即可。

```
/l[iou]st\b/
```

**示例 2**：假设以下锦标赛分类数据以 JavaScript 模板字面量的形式给出：

```
const classification = `
1st D.Okada (5) 97Pts
2nd J.Newtown (27) 78Pts
`;
```

创建一个正则表达式来匹配所有分数。一个分数是文本 `Pt` 前面的一个非负整数。

**解决方案：**

`/\d+/` 可以匹配由数字序列组成的正整数。由于我们需要匹配所有分数，因此必须对表达式应用 `g` 修饰符：`/\d+/g`。让我们列出表达式中的所有数字。

```
> let regex = /\d+/g;
> let result = null;
> while ( result = regex.exec( classification ) ) {
console.log( result[0] );
}
```

现在，我们应用一个前瞻断言来仅匹配分数。前瞻断言语法是 `(?=Pt)`。

```
> regex = /\d+(?=Pt)/g;
> while ( result = regex.exec( classification ) ) {
console.log( result[0] );
}
```

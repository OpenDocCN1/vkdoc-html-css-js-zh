# 11. 使用正则表达式解析 HTML 代码和 URL 查询字符串

在本章中，我们将使用 JavaScript 解析 HTML 文档并处理 URL 的查询字符串。

## 解析 HTML 标签

**练习 1**：假设给定了一个 HTML 文档。使用正则表达式提取所有`<td>`标签，并将其内容打印到控制台。你可以假设`<td>`标签内包含任何内容（包括换行符）。`<td>`标签可能含有属性。

**示例输入：**

```javascript
const table = `

text 1
text 2

text trés

text 4 first line
text 4 second line

`;
```

**解决方案：**

在处理多行正则表达式时，值得使用新的 ES2018 `s`（`dotall`）标志，将整个文本视为单行。由于需要匹配多个表格单元格，我们肯定需要使用 `g` 标志将正则表达式声明为全局匹配。

```javascript
/.*/gs.exec( table )
```

我们还添加想要匹配的开始和结束标签。注意，匹配表格单元格元素有四种不同的选择：`<td>`、`<Td>`、`<tD>` 和 `<TD>`。通过使用 `i` 标志将正则表达式声明为不区分大小写，我们可以用一个表达式匹配所有情况，无需任何多选结构或字符集。当匹配结束标签 `</td>` 时，请确保转义斜杠。

```javascript
/.*/gis.exec( table )
```

执行此表达式后，你会发现三个表格单元格被作为一个结果返回了。造成这个错误的原因有几个。

- 首先，`.*` 是贪婪的，它会匹配所有字符，包括其他 `</td>` 标志和 `<td>` 标志。只有在逐字符回溯并解除最后一个 `</td>` 标签的字符循环后，匹配到的字符串才会减少。

- 其次，`<td class="first">` 不会被这个正则表达式匹配，因为根据我们的表达式，在 `<td>` 标签的 `d` 之后必须紧跟一个大于号。

我们可以轻松解决这两个问题。

对于第一个问题，我们可以通过在其后添加一个 `?` 来让贪婪的 `.*` 循环变为懒惰模式。这种机制会尝试进行最小匹配。另一种解决方案是将 `.` 改为 `[^<]`，但这种方案意味着我们不能在 `<td>` 内部嵌套标签，所以这并非一个好主意。

第二个问题可以通过匹配 `td` 和 `>` 之间的所有字符来解决。在这种情况下，我们知道要匹配的字符与 `>` 不同。因此，我们在 `[^>]*` 循环中匹配任意数量的非大于号字符。

```javascript
/]*>.*?/gis.exec( table )
```

我们还需要一个更改：我们必须捕获标签的内容，以便访问并将其打印到控制台。

```javascript
let regex = /]*>(.*?)/gis
let contents = '';
while ( contents = regex.exec( table ) ) {
console.log( contents[1] );
}
```

注意，最后一个表格单元格的内容被捕获为`undefined`。

# 构建表达式

正则表达式写在起始斜杠和结束斜杠字符之间：`/re/`。

如你在第 1 章所见，此表达式匹配包含 `re` 的字符串。

某些编程语言允许或要求你使用不同的表示法。例如，在 JavaScript 中，你可以使用以下形式定义正则表达式 `/re/`：

```
> const regex = new RegExp( 're' );
> regex
/re/
```

在 PHP 和 Python 中，你必须使用字符串或原始字符串将正则表达式传递给函数。以下是一个 Python 示例：

```
import re
regex = re.compile(r"xy+")
```

除非要处理特定语言中的特定示例，否则本书将坚持使用 `/re/` 表示法。

## 字面字符与元字符

正则表达式中的`字面字符`匹配自身。表达式 `/a/` 匹配任何包含字符 `a` 的字符串。

例如，表达式 `/a/` 匹配字符串 `"andrea"`，因为该字符串的第一个和最后一个字母都是 `a`。匹配通常伴随执行过程中的简化。在执行时，正则引擎只定位字符串的第一个字符，即 `a`。由于该字符与表达式匹配，匹配完成；无需读取字符串的其余部分。

表达式 `/a/` 不匹配字符串 `"ABCDEA"`，因为在读取整个字符串后，我们没有找到任何小写字符 `a`。

所有大小写字母字符和所有数字字符都可用作字面字符。根据正则表达式方言的不同，某些其他字符也可用于匹配自身。例如，`!`、`%`、`=` 和 `_` 在大多数方言中都可作为字面字符使用。

`.`、`*`、`^`、`$`、`[` 和 `]` 等字符在几乎所有方言中都不是字面字符。它们是`元字符`。元字符负责表示一种操作，类似于编程语言中的关键字。表 2-1 描述了元字符。

**表 2-1**

| 元字符 | 语义 |
| --- | --- |
| `.` | 任意字符 |
| `*` | 重复：匹配任意次数 |
| `^` | 两种语义：(1) 否定，(2) 锚点，匹配字符串或行的开头 |
| `$` | 锚点，匹配字符串或行的结尾 |
| `[]` | 字符集 |

在编程语言系列 PCRE 中，保留了更多字符，如表 2-2 所示。

**表 2-2**

| PCRE 元字符 | 语义 |
| --- | --- |
| `&#124;` | 可选执行（或） |
| `?` | 表达式中的可选部分 |
| `+` | 至少匹配一次 |
| `{}` | 指定表达式必须匹配字符串次数的范围 |
| `()` | 分组字符 (1) 或提取子串 (2) |

在 VIM 和 EMACS 中，你必须对字符 `|`、`?`、`{`、`}`、`(` 和 `)` 进行转义，才能将它们用作运算符。

如果你想使用任何保留字符，必须使用反斜杠对其进行转义。

空白字符的处理较为复杂。在自由文本中搜索模式时，输入你想要查找的确切空白字符通常并不方便。不幸的是，在大多数方言中，一个空格匹配一个空格，`\n` 字符匹配换行符，`\t` 字符匹配制表符。这种处理方式的问题在于，搜索表达式中确切的空白字符变得至关重要。

这种方法让我想起自己一次奇怪的前端经历。我创建了一个帮助用户解析 CSV 文件的用户界面。在该界面中，有一个用于输入 CSV 分隔符的字段。有一次，一位管理员打电话给我。他向我展示，他在文本字段中粘贴了一个制表符空白字符，因此他的 CSV 分隔符变成了制表符。不幸的是，输入字段被修剪了，制表符无法保存，因为输入字段必须至少包含一个空白字符。

空白字符往往是一团乱麻。

稍后你将了解到，可以在正则表达式末尾添加标志。这些标志可能会影响你对空白字符的处理方式。

在某些情况下，输入字符串会被拆分为多行，正则表达式需要匹配每一行。在其他情况下，输入字符串可能包含换行符，这些换行符可以被正则表达式匹配。这意味着某些标志可能会改变匹配换行符的行为。

Perl 6 方言对空白字符的处理方式与任何其他方言完全不同。Perl 6 忽略正则表达式中的所有空白字符，这使得空白字符不像在其他方言中那样令人费解。稍后你将看到，忽略空白字符的好处是，你可以以任何想要的方式格式化正则表达式。当空白字符无关紧要时，以下是等价的：

```
/first second third/
/
first
second
third
/
```

正则表达式中的一个空白字符匹配被测试字符串中的任意空白字符序列。

某些 PCRE 正则表达式的 `x` 或扩展模式标志会开启相同的格式化模式。请注意，此标志并非在所有 PCRE 语言中都可用。

```
/(?x)
first
second
third
/
```

总结一下，要小心空白字符的异常情况。避免在正则表达式中使用空白字符。一旦我介绍了命名字符类，你将很快学会如何正确处理空白字符。

## 任意字符类

在某些情况下，你会查找任意字符。枚举所有可能的字符确实没有意义。

在所有正则表达式方言中，`.` 符号表示一个任意字符。例如，`/..e/` 表示一个以 `e` 结尾的三字母序列。

不幸的是，在不同的方言中，`.` 字符的定义不同，因为它可能包含也可能不包含换行符。

*   Perl 6 遵循 BRE 和 ERE 定义的命令行正则格式。换句话说，`.` 表示任何字符，包括换行符。

*   在 PCRE 语言家族所代表的所有其他语言中，`.` 字符表示除换行符外的任何字符。因此，必须显式指定匹配换行符。EMACS 和 VIM 遵循此方法。

出于可维护性考虑，建议显式指定你感兴趣匹配的字符类型。你将在第 6 章学习如何做到这一点。在此之前，使用 `[.\n]` 可以确保你将换行符与任意字符类一起包含在内。

## 基本连接

在所有编程语言中，三个必要的控制元素是`顺序`、`选择`和`迭代`。连接负责顺序执行。

你已经在多处使用了连接。首先，在第 1 章定义 `/re/` 正则表达式时使用了它。你将 `/re/` 解读为：匹配字符 `r`，*然后*匹配字符 `e`。

在构建正则表达式时，你可以连接任意正则表达式序列。

## 可选执行

现在你已经知道如何进行顺序执行，接下来我们进入选择。让我们回忆一下第 1 章中的示例，如下所示：

```
BRE:              不支持 or 运算符
EMACS,VIM:        /0\|1\|2/
ERE,PCRE,Perl 6:  /0|1|2/
```

你已经了解到 `|` 或 `\|` 运算符指定了可选路径。`/0|1|2/` 匹配一个为 `0` *或* `1` *或* `2` 的字符。

以下是一些示例：

*   `/java|php|perl/` 匹配包含 `java` *或* `php` *或* `perl` 的字符串。

*   `/....|a|the/` 匹配任何长度至少为四个字符的字符串，*或*包含字符 `a`，*或*包含子串 `the`。

管道运算符在正则表达式中的所有运算符中优先级最低。

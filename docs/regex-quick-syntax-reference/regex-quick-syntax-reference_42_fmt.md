# 10. 优化正则表达式

你已经学会了所有优化正则表达式执行的工具；因此，本章将作为你目前所学知识的总结。

你了解到正则表达式的执行可以通过两种类型的自动机来建模：确定性和非确定性的有限状态自动机。

非确定性自动机的执行时间可以按其步骤数进行指数级衡量。这种复杂性源于回溯的需要。

从非确定性自动机创建确定性有限状态自动机也具有指数级复杂度。

在大多数执行环境中，正则表达式虚拟机遵循非确定性模型。这是因为匹配成功可能比匹配失败快得多。我们可能只需 `n` 步就能匹配输入，其中 `n` 是输入的大小。如果我们让执行变成确定性的，状态空间可能会爆炸，最终可能导致 `O(2^n)` 的复杂度。

使用非确定性模型会带来一些后果。在优化正则表达式时，我们将利用这些后果。

## 优化技术总结

由于复杂性源于回溯，优化技术的预期目标就是尽量减少回溯。我们将考虑几种实现方法：

-   使字符类更具体
-   重复字符类循环
-   使用占有量词修饰符
-   使用原子组
-   重构以实现优化

某些编译器会对你的正则表达式执行自动优化。一般的规则是，大多数情况下需要你自己来处理。

## 使字符类更具体

我们的敌人是 `.*` 模式，因为在最坏的情况下，你可能最终需要回溯的次数等同于输入的长度。

例如，假设你想要捕获微模板标签 `${` 和 `}` 之间的标识符名称。在这个例子中，我们假设要查找形式为 `${ id }` 的模式，其中 `id` 不能包含空白字符。以下扩展的 PCRE 表达式可以做到这一点：

```
/(?x)
\$\{  # 匹配开始标签 ${
\s*   # 贪婪地匹配所有空白
(.+?) # 最小匹配我们的标识符
\s*   # 贪婪地匹配所有剩余的空白
\}    # 匹配结束标签
/
```

注意扩展模式 `(?x)`。记住，以 `(?x)` 开头的正则表达式会使空白字符不匹配自身，并允许你在表达式中放置注释，注释以 `#` 字符开头，直到遇到换行符。

由于我们要查找标识符字符，我们可以确定这些字符既不是空白字符，也不是右花括号。因此，在这里使用任意字符类是一种奢侈的做法。我们可以通过将 `.+?` 更改为更具体的字符类 `[^\s\}]` 来使表达式更具确定性。

```
/(?x)
\$\{        # 匹配开始标签 ${
\s*         # 贪婪地匹配所有空白
([^\s\}]+)  # 贪婪匹配我们的标识符
\s*         # 贪婪地匹配所有剩余的空白
\}          # 匹配结束标签
/
```

注意，现在我们可以使用贪婪量词修饰符了，因为使用贪婪还是懒惰已经无关紧要。事实上，最佳选择是直接使用占有量词修饰符，但我们也先别太急于求成。

### 提示

使用分支结构或字符类时，分支结构中所有可能的选择都不能以紧随其后的字符作为开头。

避免使用 `[xy]*x`。请更好地理解需求，因为几乎总是有更简单的解决方案：`/[xy]*x/` 会匹配输入中只包含 `x` 和 `y` 字符且以 `x` 结尾的子串。如果我们只是检查是否存在这样的模式，检查 `/y*x/` 就足够了。

如果我们的任务是验证 `/^[xy]*x$/`，请使用 `/^(y*+x)*+$/`。我们以占有方式匹配任意数量的 `y` 字符，后跟一个 `x`。我们尽可能多地查找这种模式。由于我们到处都使用了占有匹配，这个表达式中完全没有回溯。为了能够使用占有量词循环，我们必须通过将 `x` 从字符集 `[xy]` 中分离出来，从而消除该字符集。

## 重复字符类循环

避免重复相同的字符类循环，无论你使用的是贪婪版本还是懒惰版本。

```
/(?x)
\$\{   # 匹配开始标签 ${
\s*    # 贪婪地匹配所有空白
(.+?)  # 最小匹配我们的标识符
\s*    # 贪婪地匹配所有剩余的空白
\}     # 匹配结束标签
/
```

在这里，`(\s*)(.+?)(\s*)` 是麻烦的根源。如果由于任何原因，我们在输入字符串中找不到 `}` 字符，正则表达式将陷入回溯地狱，它会尝试每一种可能的组合，将空白字符序列分配到某个 `\s*` 模式或 `.+?` 模式中。

你已经见过一个消除这种回溯地狱的可行解决方案。

```
/(?x)
\$\{        # 匹配开始标签 ${
\s*         # 贪婪地匹配所有空白
([^\s\}]+)  # 贪婪匹配我们的标识符
\s*         # 贪婪地匹配所有剩余的空白
\}          # 匹配结束标签
/
```

通过使中间的字符类与其他两个字符类不同，我们不会允许正则表达式虚拟机进行无谓的“堂吉诃德风车大战”，去试图确定我们的空白字符应该属于哪里。

为了完全消除所有回溯，我们可以使用下一种技巧。

## 尽可能使用占有量词修饰符

占有量词修饰符根据定义从不回溯；它们直接匹配失败。作为消除回溯的代价，我们通过根本不探索回溯分支来限制状态空间。

```
/(?x)
\$\{        # 匹配开始标签 ${
\s*+        # 贪婪地匹配所有空白（占有）
([^\s\}]+)  # 贪婪匹配我们的标识符
\s*+        # 贪婪地匹配所有剩余的空白（占有）
\}          # 匹配结束标签
/
```

这里，正则表达式引擎甚至不会尝试对 `\s*+` 模式进行回溯。这是因为我们作为人类知道，如果不存在 `}`，那么如何匹配空白字符都无关紧要。因此，我们可以简单地加速匹配失败的过程。

记住发现添加占有量词修饰符机会的规则：

-   如果紧跟占有量词循环之后的字符，与该循环内部模式的第一个字符互斥，那么你可以考虑使用占有量词循环。

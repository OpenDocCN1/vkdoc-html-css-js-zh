# 1. 正则表达式入门

我至今仍记得当初尝试学习正则表达式时的糟糕经历。事实上，我曾为自己不使用正则表达式而感到自豪。我总是能找到笨拙的变通方法或代码片段。我将自己缺乏专业知识的责任投射到正则表达式晦涩难读的特性上，并以此为由进行指责。这个过程一直持续到我准备好面对真相：正则表达式非常强大，能为你节省大量时间和精力，避免许多令人头疼的问题。

转眼几年过去了。与我共事的人也遇到了同样的问题。有些人懂正则表达式，有些人则讨厌它。在讨厌正则表达式的群体中，常见的情况是，他们实际上很喜欢自己第一门编程语言的语法和文法。有些开发者甚至上过形式语言课程。因此，我把展示一条从"被否认的知识"通向掌握正则表达式之路，作为自己的首要任务。

## 为什么正则表达式很重要？

在当今世界，我们需要处理大量数据。访问数据并非主要问题，筛选数据才是。正则表达式为你提供了一种过滤器，你可以用它从已有的海量数据块中提取相关信息。例如，假设你有一个包含 4GB 电影数据的 XML 文件。正则表达式使你能查询这个 XML 文本，从而找出所有在 2016 年于布达佩斯拍摄的电影等等。

正则表达式是软件开发人员的必备技能。

在前端开发中，我们经常使用正则表达式来验证输入。许多小功能用正则表达式实现也更简单，例如拆分字符串、解析输入和模式匹配。

在编写后端代码时，尤其是在数据科学领域，我们经常使用正则表达式来搜索、替换和处理数据。在 IT 基础设施中，正则表达式有许多用例。`VIM` 和 `EMACS` 也支持正则表达式，用于查找命令以及编辑文本文件。

正则表达式无处不在。这些技能在你的 IT 工程职业生涯中会派上用场。

## 什么是正则表达式？

正则表达式（`regexes`）来源于形式语言理论。理论上，正则表达式是一个定义搜索模式的有限字符序列。我们经常使用这些搜索模式来：

-   测试字符串是否匹配某个搜索表达式
-   在字符串中查找某些字符
-   替换字符串中与正则表达式匹配的子串
-   处理并格式化用户输入
-   从服务器日志、配置文件和文本文件中提取信息
-   在 Web 应用程序和终端中验证输入

一个典型的正则表达式任务是匹配。我现在将使用 JavaScript 向你展示如何"试用"正则表达式，因为几乎每个人都有浏览器可以使用。在浏览器中，你需要打开开发者工具。在谷歌 Chrome 浏览器中，你可以右键点击网页并选择"检查"来做到这一点。在开发者工具内，选择"控制台"选项卡来输入并求值你的 JavaScript 表达式。

假设有一个 JavaScript 正则表达式 `/re/`。这个表达式在字符串中查找一个模式：有一个 `r` 字符，后面跟着一个 `e` 字符。为简单起见，假设我们的字符串是区分大小写的。

```javascript
const s1 = 'Regex';
const s2 = 'regular expression';
```

在 JavaScript 中，字符串有一个 `match` 方法。该方法需要一个正则表达式作为参数，并返回关于第一个匹配的一些数据。

```javascript
> s1.match( /re/ )
null
> s2.match( /re/ )
["re", index: 0, input: "regular expression"]
```

正则表达式是写在两个斜杠（`/`）字符之间的表达式。表达式 `/re/` 查找一个 `r` 字符后跟一个 `e` 字符。

打个比方，想象你在浏览器中加载了一个网站，按下 `Ctrl+F` 或 `Cmd+F` 在屏幕上查找网站内的子串，然后开始输入 `re`。正则表达式 `/re/` 在指定字符串内做着同样的事情，只是结果区分大小写。

注意，`'Regex'` 不包含子串 `'re'`。因此，没有匹配到任何内容。

字符串 `'regular expression'` 包含两次子串 `'re'`：一次在位置 0，一次在位置 11。为了确定匹配，JavaScript 正则表达式引擎只返回索引 0 处的第一个匹配，然后终止。

JavaScript 允许你反过来使用语法，通过测试正则表达式。

```javascript
> /re/.test( s1 )
false
> /re/.test( s2 )
true
```

返回值是一个简单的布尔值。大多数情况下，你不需要更多，因此测试正则表达式就足够了。

每种编程语言的內建正则表达式支持都有不同的语法。你可以学习它们，或者使用在线生成器（如 [`https://regex101.com/`](https://regex101.com/)）生成相应的正则表达式代码。

# 正则表达式的挫败感源于缺乏行动

许多软件开发人员认为正则表达式：

- 难以理解
- 难以编写
- 难以修改
- 难以测试
- 难以调试

正如我在本章引言中所提到的，缺乏理解往往伴随着指责。我们倾向于将这五个问题归咎于正则表达式。

为了弄清楚这种指责存在的原因，让我们探索一下普通开发人员（并非双关语）与正则表达式打交道的过程。当接触不熟悉的事物时，我们大多数人都会默认采用这种探索方式。对于正则表达式来说，任务似乎过于简单：我们只需要创建一个简短的表达式，对吗？嗯，这种观点往往大错特错。

反复试错所花费的时间，往往比直接解决问题、弥补知识空白要多得多。然而，大多数开发人员却一遍又一遍地采用试错法。毕竟，如果只需复制粘贴一小段代码就能解决问题，何必费心去学习正则表达式复杂的机制呢？更何况，乍一看，深入学习正则表达式的来龙去脉似乎就太难了。

因此，我的使命是向你展示：

- 学习正则表达式比你想象的要容易得多
- 掌握正则表达式很有趣
- 掌握正则表达式在你软件开发生涯的许多领域都大有裨益

你仍然可以轻松掌握正则表达式，使其完全按照你的意图执行。这种精通源于理解正确的理论并大量练习。

## 正则表达式是命令式的

正则表达式被广泛误解。每当听到有人说正则表达式是声明式的，请尽快远离那个教程或博客。正则表达式是一种命令式语言。如果你想将正则表达式理解为声明式的，你很可能会失败。

根据定义，正则表达式指定一种搜索模式。虽然这句话没错，但很容易被误解，因为你并没有指定一个声明式结构。在现实世界中，你指定的是指令序列，其行为类似于命令式编程语言中的函数。你使用命令和循环，向正则表达式传递参数，可能在正则表达式内部传递参数，返回结果，甚至可能产生副作用。

将正则表达式作为命令式语言来学习有一个很大的优势。如果你曾接触过至少一种编程语言，那么你几乎已经知道了理解正则表达式所需的一切。你只是还不熟悉正则表达式的语法。一旦你熟悉了这种奇特的语言，一切都会豁然开朗。

## 正则表达式的语言家族

当我说到正则表达式时，实际上指的是不同方言组成的家族。类似于遗传学，正则表达式不断进化，新的变种也定期出现。尽管大多数语言中的原则保持不变，但每种方言都带来了一些不同之处。

正则表达式的标准化始于 POSIX 标准 1003.2 中的 `BRE`（基本正则表达式）。该标准用于 `ed` 和 `sed` 编辑器，以及 `grep` 命令。

正则表达式的第一次重大演变是 `ERE`（扩展正则表达式）语法的出现。这种语法用于，例如，`egrep` 和 `notepad++`。

为了完整性，我还会提及 `SRE`（简单正则表达式）方言，该方言已被弃用，转而推荐使用 `BRE`。

一些编辑器如 EMACS 和 VIM 拥有自己的方言。就 VIM 而言，其方言可以通过标志进行自定义，这种技术甚至产生了更多的变种。这些方言是在 `ERE` 基础上构建的。

大多数编程语言中使用的正则表达式都基于 `PCRE`（Perl 兼容正则表达式）方言。每种编程语言都有其自己的缩写和差异。这些编程语言包括 PHP、JavaScript、Java、C#、C++、Python、R、直到版本 5 的 Perl 等。

更复杂的是，Perl 6 采用了一套完全不同的正则表达式规则。Perl 6 的语法通常更易读，但代价是你必须学习一种不同的语言。

举个例子，我们来编写一个用于匹配至少包含一个非数字字符的字符串的正则表达式。

| 方言 | 表达式 |
| --- | --- |
| `BRE`, `ERE`, EMACS, VIM, `PCRE` | `/[⁰¹²³⁴⁵⁶⁷⁸⁹]/` |
| Perl 6 | `/<-[0123456789]><-[0123456789]>/` |

如你所见，在这个具体例子中，除了 Perl 6 之外，所有方言看起来都一样。不过多纠结于细节，我们来理解一下这个表达式在 `BRE`、`ERE`、EMACS、VIM 和 `PCRE` 中的含义。

- `[0123456789]` 匹配数字字符集中的一个字符。
- 枚举中的 `^` 对字符列表取反。这意味着 `[⁰¹²³⁴⁵⁶⁷⁸⁹]` 匹配任何不是数字的字符。
- 由于正则表达式可能匹配测试字符串中的任意字符，只要在测试字符串中找到一个非数字字符，就确定匹配。因此，`123.45` 匹配该正则表达式，而 `000` 则不匹配。

Perl 6 语法的工作原理相同；只是语法不同。

现在，让我们编写一个使用正则表达式的 `or` 运算符来匹配字符 `0`、`1` 或 `2` 的正则表达式。

```
BRE:               不支持 or 运算符
ERE,PCRE,Perl 6:   /0|1|2/
EMACS,VIM:         /0\|1\|2/
```

等效的 `BRE` 表达式是 `/[012]/`，它使用字符集。你将在第 6 章中详细了解字符集。

由于研究六种方言和许多不同的变种会花费很长时间，我强烈建议你专注于一种特定的方言，并仅围绕你在实践中使用的这一种方言来练习技能。你可以之后再回头研究其他方言。对于 `PCRE` 方言，不同的语言会给你带来不同的变种。我个人发现，用多种编程语言构建和执行正则表达式是非常有益的。这样一来，我就能更容易地从不同角度巩固我的正则表达式知识。

## 总结

在本章中，我将正则表达式定义为定义搜索模式的有限字符序列。作为示例，你看到了一个简单的 JavaScript 正则表达式在控制台中的测试执行情况。尽管测试的正则表达式很简单，但人们常常难以构建和理解正则表达式。这是因为正则表达式代表了一种紧凑的命令式语言，因此通常不直观。更复杂的是，正则表达式由多种语言构成，这意味着 JavaScript 语法与 Perl 6 中使用的语法完全不同。

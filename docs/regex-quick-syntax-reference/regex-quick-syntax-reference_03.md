# 正则表达式语法 101

学习新工具时，你总得从某个地方开始。

本章的目标是为你提供正则表达式语法的一个基本子集，供你练习。然而，学习所有语法并非高效之举，因为说实话，一次性学习所有高级正则表达式语法对任何人来说都太多了。

# 构建表达式

正则表达式写在起始斜杠和结束斜杠字符之间：`/re/`。

如你在第 1 章所见，此表达式匹配包含 `re` 的字符串。

某些编程语言允许或要求你使用不同的表示法。例如，在 JavaScript 中，你可以使用以下形式定义正则表达式 `/re/`：

```
> const regex = new RegExp( 're' );
> regex
/re/
```

在 PHP 和 Python 中，你必须使用字符串或原始字符串将正则表达式传递给函数。以下是一个 Python 示例：

```
import re
regex = re.compile(r"xy+")
```

除非要处理特定语言中的特定示例，否则本书将坚持使用 `/re/` 表示法。

## 字面字符与元字符

正则表达式中的`字面字符`匹配自身。表达式 `/a/` 匹配任何包含字符 `a` 的字符串。

例如，表达式 `/a/` 匹配字符串 `"andrea"`，因为该字符串的第一个和最后一个字母都是 `a`。匹配通常伴随执行过程中的简化。在执行时，正则引擎只定位字符串的第一个字符，即 `a`。由于该字符与表达式匹配，匹配完成；无需读取字符串的其余部分。

表达式 `/a/` 不匹配字符串 `"ABCDEA"`，因为在读取整个字符串后，我们没有找到任何小写字符 `a`。

所有大小写字母字符和所有数字字符都可用作字面字符。根据正则表达式方言的不同，某些其他字符也可用于匹配自身。例如，`!`、`%`、`=` 和 `_` 在大多数方言中都可作为字面字符使用。

`.`、`*`、`^`、`$`、`[` 和 `]` 等字符在几乎所有方言中都不是字面字符。它们是`元字符`。元字符负责表示一种操作，类似于编程语言中的关键字。表 2-1 描述了元字符。

**表 2-1**

| 元字符 | 语义 |
| --- | --- |
| `.` | 任意字符 |
| `*` | 重复：匹配任意次数 |
| `^` | 两种语义：(1) 否定，(2) 锚点，匹配字符串或行的开头 |
| `$` | 锚点，匹配字符串或行的结尾 |
| `[]` | 字符集 |

在编程语言系列 PCRE 中，保留了更多字符，如表 2-2 所示。

**表 2-2**

| PCRE 元字符 | 语义 |
| --- | --- |
| `&#124;` | 可选执行（或） |
| `?` | 表达式中的可选部分 |
| `+` | 至少匹配一次 |
| `{}` | 指定表达式必须匹配字符串次数的范围 |
| `()` | 分组字符 (1) 或提取子串 (2) |

在 VIM 和 EMACS 中，你必须对字符 `|`、`?`、`{`、`}`、`(` 和 `)` 进行转义，才能将它们用作运算符。

如果你想使用任何保留字符，必须使用反斜杠对其进行转义。

空白字符的处理较为复杂。在自由文本中搜索模式时，输入你想要查找的确切空白字符通常并不方便。不幸的是，在大多数方言中，一个空格匹配一个空格，`\n` 字符匹配换行符，`\t` 字符匹配制表符。这种处理方式的问题在于，搜索表达式中确切的空白字符变得至关重要。

这种方法让我想起自己一次奇怪的前端经历。我创建了一个帮助用户解析 CSV 文件的用户界面。在该界面中，有一个用于输入 CSV 分隔符的字段。有一次，一位管理员打电话给我。他向我展示，他在文本字段中粘贴了一个制表符空白字符，因此他的 CSV 分隔符变成了制表符。不幸的是，输入字段被修剪了，制表符无法保存，因为输入字段必须至少包含一个空白字符。

空白字符往往是一团乱麻。

稍后你将了解到，可以在正则表达式末尾添加标志。这些标志可能会影响你对空白字符的处理方式。

在某些情况下，输入字符串会被拆分为多行，正则表达式需要匹配每一行。在其他情况下，输入字符串可能包含换行符，这些换行符可以被正则表达式匹配。这意味着某些标志可能会改变匹配换行符的行为。

Perl 6 方言对空白字符的处理方式与任何其他方言完全不同。Perl 6 忽略正则表达式中的所有空白字符，这使得空白字符不像在其他方言中那样令人费解。稍后你将看到，忽略空白字符的好处是，你可以以任何想要的方式格式化正则表达式。当空白字符无关紧要时，以下是等价的：

```
/first second third/
/
first
second
third
/
```

正则表达式中的一个空白字符匹配被测试字符串中的任意空白字符序列。

某些 PCRE 正则表达式的 `x` 或扩展模式标志会开启相同的格式化模式。请注意，此标志并非在所有 PCRE 语言中都可用。

```
/(?x)
first
second
third
/
```

总结一下，要小心空白字符的异常情况。避免在正则表达式中使用空白字符。一旦我介绍了命名字符类，你将很快学会如何正确处理空白字符。

## 任意字符类

在某些情况下，你会查找任意字符。枚举所有可能的字符确实没有意义。

在所有正则表达式方言中，`.` 符号表示一个任意字符。例如，`/..e/` 表示一个以 `e` 结尾的三字母序列。

不幸的是，在不同的方言中，`.` 字符的定义不同，因为它可能包含也可能不包含换行符。

*   Perl 6 遵循 BRE 和 ERE 定义的命令行正则格式。换句话说，`.` 表示任何字符，包括换行符。

*   在 PCRE 语言家族所代表的所有其他语言中，`.` 字符表示除换行符外的任何字符。因此，必须显式指定匹配换行符。EMACS 和 VIM 遵循此方法。

出于可维护性考虑，建议显式指定你感兴趣匹配的字符类型。你将在第 6 章学习如何做到这一点。在此之前，使用 `[.\n]` 可以确保你将换行符与任意字符类一起包含在内。

## 基本连接

在所有编程语言中，三个必要的控制元素是`顺序`、`选择`和`迭代`。连接负责顺序执行。

你已经在多处使用了连接。首先，在第 1 章定义 `/re/` 正则表达式时使用了它。你将 `/re/` 解读为：匹配字符 `r`，*然后*匹配字符 `e`。

在构建正则表达式时，你可以连接任意正则表达式序列。

## 可选执行

现在你已经知道如何进行顺序执行，接下来我们进入选择。让我们回忆一下第 1 章中的示例，如下所示：

```
BRE:              不支持 or 运算符
EMACS,VIM:        /0\|1\|2/
ERE,PCRE,Perl 6:  /0|1|2/
```

你已经了解到 `|` 或 `\|` 运算符指定了可选路径。`/0|1|2/` 匹配一个为 `0` *或* `1` *或* `2` 的字符。

以下是一些示例：

*   `/java|php|perl/` 匹配包含 `java` *或* `php` *或* `perl` 的字符串。

*   `/....|a|the/` 匹配任何长度至少为四个字符的字符串，*或*包含字符 `a`，*或*包含子串 `the`。

管道运算符在正则表达式中的所有运算符中优先级最低。

# 运算符优先级与括号

连接运算的优先级高于选择运算。你可以将连接运算视为乘法，将选择运算视为加法。在表达式`/a`|`the/`中无需使用括号，因为连接运算的优先级更高。同理，计算`1 + 2 * 3 = 1 + 6 = 7`时也不需要括号。

有时你需要覆盖默认的优先级规则，此时括号就派上了用场。你可以使用括号对低优先级的表达式进行分组。

例如，表达式`/list`|`lost`|`lust/`可以简化为`/l(i`|`o`|`u)st/`。你可以使用任意数量的嵌套括号进行分组。

在`VIM`和`EMACS`中，不要忘记对括号进行转义。

为完整起见，需注意括号的用法可能产生重载。括号将用于从正则表达式中`捕获`子字符串。你将在后续阶段探索这一用例。

括号是元字符，不会消耗正则表达式测试字符串中的任何字符。还有许多其他命令也不会在字符串内部进行遍历。例如，下一节你将学习到同样不消耗字符的定位起始锚点和结束锚点。

# 定位起始锚点和结束锚点

在某些方言（如 JavaScript）中，`^`和`$`符号表示待匹配字符串的起始和结束。而在其他环境（如 EMACS 和 VIM）中，`^`和`$`符号表示待匹配行的起始和结束。

## 在 BRE、ERE、多数基于 PCRE 的语言以及 Perl 6 中

* `/^x/` 匹配以`x`开头的字符串。
* `/x$/` 匹配以`x`结尾的字符串。
* `/^x$/` 匹配只包含字符`'x'`的字符串。

在某些基于 PCRE 的语言中，上述字符仅表示行的边界断言。例如在 Ruby 中：

* `/^x/` 匹配以`x`开头的行。
* `/x$/` 匹配以`x`结尾的行。
* `/\Ax/` 匹配以`x`开头的字符串。
* `/x\z/` 匹配以`x`结尾的字符串。

当`^`和`$`对行边界进行限制时，在多数基于 PCRE 的语言中，对于包含多行的字符串，你可以分别使用`\A`和`\z`或`\Z`字符。

这不是通用规则，因为在 JavaScript 中，`\A`表示字面字符`A`。JavaScript 使用单词边界断言`\b`来测试单词的起始或结束。

* `/\bx/` 匹配以`x`开头的单词。
* `/x\b/` 匹配以`x`结尾的单词。

此外，在 JavaScript 中，多行修饰符`m`会重新定义`^`和`$`，使其分别匹配行的起始和结束。你将在下一章学习多行修饰符。

## 在 EMACS 中

* ``/\`x/`` 匹配以`x`开头的字符串。
* `/^x/` 匹配以`x`开头的行。
* `/x\'/` 匹配以`x`结尾的字符串。
* `/x$/` 匹配以`x`结尾的行。

## 在 VIM 中

* `/\%^x/` 匹配以`x`开头的字符串。
* `/^x/` 匹配以`x`开头的行。
* `/x\%$/` 匹配以`x`结尾的字符串。
* `/x$/` 匹配以`x`结尾的行。

## 在 Perl 6 中

* `/^x/` 匹配以`x`开头的字符串。
* `/x$/` 匹配以`x`结尾的字符串。
* `/^^x/` 匹配以`x`开头的行。
* `/x$$/` 匹配以`x`结尾的行。

你可以得出结论：定位起始锚点和结束锚点字符在不同方言中的行为可能完全不同。在依赖这些断言前，务必查阅文档并测试你的代码。

### 练习 1

在 JavaScript 中，`/^list`|`lost`|`lust$/`会匹配以下哪些字符串？为什么？

* `list,`
* `lostlist,`
* `listlist,`
* `lustlist?`

### 解答

令人惊讶的答案是，前三个字符串都能匹配。以下是验证结果：

```
> 'list'.match( /^list|lost|lust$/ )
["list", index: 0, input: "list"]
> 'lostlist'.match( /^list|lost|lust$/ )
["lost", index: 0, input: "lostlist"]
> 'listlist'.match( /^list|lost|lust$/ )
["list", index: 0, input: "listlist"]
> 'lustlist'.match( /^list|lost|lust$/ )
null
```

你可能错误地认为该正则表达式只匹配字符串`'list'`、`'lost'`和`'lust'`，而非其他内容，因为字符串的起始和结束都被锚定了。

如果你期望只有`list`能匹配该正则表达式，请回忆选择运算一节中的内容：管道运算符在正则表达式中是所有运算符中优先级最低的。

`|`运算符优先级最低，这意味着`^`和`$`的绑定优先级更高。如果使用括号来突出自然优先级，你会得到以下表达式：

```
/(^list)|lost|(lust$)/
```

该表达式解读如下：匹配任何满足以下任一条件的字符串：

* 以`list`开头
* 包含`lost`
* 以`lust`结尾

第二个字符串`'lostlist'`能匹配，因为它包含`lost`。第三个字符串`'listlist'`能匹配，因为它以`list`开头。

第四个字符串`'lustlist'`不匹配，因为它不以`list`开头，不包含`lost`，也不以`lust`结尾。

如果你想将匹配范围限定为仅`list`、`lost`和`lust`，则必须使用括号。

```
/^(list|lost|lust)$/
```

添加括号后，只有第一个字符串能匹配该表达式。

```
> 'list'.match( /^(list|lost|lust)$/ )
["list", index: 0, input: "list"]
> 'lostlist'.match( /^(list|lost|lust)$/ )
null
> 'listlist'.match( /^(list|lost|lust)$/ )
null
> 'lustlist'.match( /^(list|lost|lust)$/ )
null
```

当将锚点字符与`|`一起使用时，务必使用括号标明你预期的优先级，即使你的意图显而易见，甚至括号的使用是冗余的。这样，你的表达式将更易于维护。

# 修饰符

可以为正则表达式添加不同的修饰符，以改变表达式的解释和执行方式。修饰符通常写在表达式结尾之后。

坏消息是，不同的正则表达式实现带有不同的修饰符。好消息是，在使用某种语言之前，你可以查找并熟悉该语言中可用的修饰符。

表 2-3 展示了一些修饰符的示例。

**表 2-3** 修饰符

| 修饰符 | 语义 |
| --- | --- |
| `g` | 全局匹配，在首次匹配后不会停止返回。 |
| `m` | 多行匹配，使`^`和`$`匹配行的起始和结束，而非整个字符串的起始和结束。 |
| `s` | 单行模式。字符`.`匹配所有字符，包括`\n`。 |
| `i` | 不区分大小写匹配。 |
| `x` | 忽略空白字符。此选项启用自由间距模式。 |
| `u` | 使用完整 Unicode 匹配。 |

这些标志并非通用。例如，`x`标志在 JavaScript 中不可用。`g`标志在 PHP 中不可用，因为全局模式只能通过调用不同的匹配器函数来访问。

让我们在 JavaScript 控制台中查看不区分大小写模式的效果：

```
> /re/.test( 'Regex' );
false
> /re/i.test( 'Regex' );
true
```

不区分大小写模式将字符串视为不区分大小写，使序列`Re`与正则表达式`/re/i`匹配。

目前，你可以认为`/re/i`与`/(r|R)(e|E)/`是等价的。这并不完全准确，原因有二，且会影响效率：

* 稍后你将学习一种更优的方式来表示字符集，例如表示集合`{r, R}`中的字符。

* 你将学习括号用于捕获子字符串的次要功能，这可能会大幅降低正则表达式的速度。

在本节中不必担心性能问题。重点在于掌握正确的语法。

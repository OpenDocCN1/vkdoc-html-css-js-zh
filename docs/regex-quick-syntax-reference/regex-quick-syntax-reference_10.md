# 9. 维护正则表达式

在行业中，编写和维护正则表达式常常令人心生畏惧。这是因为随着表达式变得庞大，阅读难度也随之增加。

这让我想起了健身房里的一个词 `Fluessigkeitsliebhaberei`，意思是“热爱流体”。就这么一个词，毫无意义。德语单词很长，有时非常长。

`Rindfleischetikettierungsueberwachungsaufgabenuebertragungsgesetz` 是另一个例子。大多数读者习惯于阅读短单词。然后突然出现这样一个长词，我们所有的速读技巧都派不上用场了。

软件开发人员习惯于阅读代码。但代码通常包含大量空白字符。下面的 `PCRE` 表达式就像是一个超长的德语单词：

```
/^(?=.*[A-Z].*[A-Z])(?=.*[!@#$&*])(?=.*[0-9].*[0-9])(?=.*[a-z].*[a-z]).{8,}$/
```

这远不是我见过的最糟糕的正则表达式，但要解读它仍然需要时间。如果我们能给它周围添加一些空白字符呢？

默认情况下，只有 `Perl 6` 允许使用空白字符进行格式化。不幸的是，在其他方言中，空白字符是匹配自身的字面量字符。

不过，也并非无计可施。在本章中，我们将把那些看似无法阅读、杂乱无章的正则表达式转化为可维护的代码。我们将探讨创建可维护正则表达式的可行方案。

# 扩展模式

PCRE 及部分 ERE 语言支持扩展模式。其语法如下：

```
/(?x) 正则       # 注释行 1
主体       # 注释行 2
处于       # 注释行 3
扩展       # 注释行 4
模式       # 注释行 5
/
```

在扩展模式下，空白字符不匹配任何内容，仅用于格式化。井号（`#`）表示注释的开始，持续到行尾。

`(?x)` 应位于正则表达式的开头。你不能在表达式中间才开启扩展模式。实际上，`(?x)` 是一个正则标志或修饰符。在某些方言或正则库中，除了使用 `/a/i`，你也可以使用 `/(i)a/` 这种结构。将正则修饰符置于前方的优势在于可读性。当表达式较长时，阅读者更希望在阅读表达式本身之前先了解其修饰符。

我强烈推荐开启扩展模式。回顾以下表达式：

```
/^(?=.*[A-Z].*[A-Z])(?=.*[!@#$&*])(?=.*[0-9].*[0-9])(?=.*[a-z].*[a-z]).{8,}$/
```

以下是同一表达式的扩展模式等效形式：

```
/(?x)
^                  # 起始锚点
(?=.*[A-Z].*[A-Z]) # 至少两个大写字母
(?=.*[!@#$&*])     # 且至少一个特殊字符
(?=.*[0-9].*[0-9]) # 且至少两个数字
(?=.*[a-z].*[a-z]) # 且至少两个小写字母
.{8,}              # 字符串长度至少为 8 个字符
$                  # 结束锚点
/
```

信不信由你，这与前面的单行表达式是相同的。

遗憾的是，并非所有方言都支持扩展模式。例如，在 EMACS 和 VIM 中就没有。在 JavaScript 中也不支持扩展模式，但你可以使用 `XRegExp` 库^((53)) 来开启扩展模式。

```
const regex = new XRegExp( '                                   \
^                   # 起始锚点                             \
(?=.*[A-Z].*[A-Z])  # 至少两个大写字母                     \
(?=.*[!@#$&*])      # 且至少一个特殊字符                    \
(?=.*\\d.*\\d)      # 且至少两个数字                       \
(?=.*[a-z].*[a-z])  # 且至少两个小写字母                    \
.{8,}               # 字符串长度至少为 8 个字符             \
$                   # 结束锚点                             \
');
```

使用 `XRegExp` 构造函数时，不要忘记转义反斜杠。为了说明这一点，我使用了 `\\d` 而不是 `[0-9]`。

即使没有扩展模式，如果你能跳出常规思维，也可以让你的代码更易于维护。例如，使用 JavaScript 的 `RegExp` 构造函数并结合 JavaScript 语法，你可以编写出易于阅读的代码。

```
const regex = new RegExp(
'^'                  + // 起始锚点
'(?=.*[A-Z].*[A-Z])' + // 至少两个大写字母
'(?=.*[!@#$&*])'     + // 且至少一个特殊字符
'(?=.*\\d.*\\d)'     + // 且至少两个数字
'(?=.*[a-z].*[a-z])'   + // 且至少两个小写字母
'.{8,}'               + // 字符串长度至少为 8 个字符
'$'                    // 结束锚点
);
```

# 正则子程序

少数正则方言提供了子程序。子程序类似于编程语言中的函数。如果你不将整个表达式写成一个整体，而是将表达式的某些部分抽象为子程序，那么你的正则表达式将更具可读性。你的表达式也会更加 DRY（不要重复自己）。毕竟，在同一个表达式中复制粘贴同一个子程序三四次，并不易于维护。

子程序在表达式中的任何位置被调用时都会执行。如果子程序匹配成功，则正则表达式的执行继续正常进行。如果子程序匹配失败，则会发生回溯。

## PCRE 子程序

在 PCRE 的情况下，请查阅你的正则宿主语言的文档。并非所有 PCRE 语言都支持子程序。例如，在 JavaScript 中，我建议使用 `XRegExp` 库来增强正则表达式的表达能力。

```
var time = XRegExp.build('(?x)^ {{hours}} ({{minutes}}) $', {
hours: XRegExp.build('{{h12}} : | {{h24}}', {
h12: /1[0-2]|0?[1-9]/,
h24: /2[0-3]|[01][0-9]/
}, 'x'),
minutes: /^[0-5][0-9]$/
});
```

`{{hours}}`、`{{minutes}}`、`{{h12}}` 和 `{{h24}}` 这些占位符会在各自的位置插入子表达式。

`XRegExp` 的子程序看起来有点复杂。通用的 PCRE 子程序语法则相对易读一些。

```
(?(DEFINE)
(?
# 子程序 1 的主体
)
(?
# 子程序 2 的主体
)
)
```

表达式中的 `DEFINE` 部分从不匹配任何内容。它用于声明你的子程序。

在表达式中使用 `(?&SUBROUTINE1)` 来匹配它。

让我们看一个示例，匹配一个货币符号和一个可能包含整数部分和小数部分的价格。我们假设小数部分最多可以有两位数字。

```
/(?x) (?&货币) (?&价格)
(?(DEFINE)
(? [\$\€] )
(?    \d++ \.?+ \d{0,2} )
)
/
```

## Perl 6 子程序

Perl 6 的子程序语法比 PCRE 语法更简洁，但其工作方式与 PCRE 版本大致相同。

你可以通过以下方式声明 Perl 6 子程序：

```
/
:my regex 子程序 1 {
# 子程序 1 的主体
}
:my regex 子程序 2 {
# 子程序 2 的主体
}
/
```

你可以在 Perl 6 表达式中使用 `<子程序 1>` 来调用子程序。

让我们重写你在"PCRE 子程序"部分看到的同一个货币示例。

```
/(?x) (?&货币) (?&价格)
(?(DEFINE)
(?  [\$\€] )
(?     \d++ \.?+ \d**0..2 )
)
/
```

## 扩展模式、子程序和抽象化

*抽象化* 是指识别可重用代码并将其提取到一处。我们可以创建子程序来抽象正则表达式中重复的功能片段，并且可以根据需要多次重用它们。子程序对于编写可维护的 DRY 正则表达式至关重要。

借助扩展模式的优势，你就能告别冗长且难以维护的正则谜题。你甚至可以清晰无比地编写长达数千字符的正则表达式。想象一下，在阅读本书之前，你可能会连一个 20 字符的表达式都读起来费劲。

# 命名捕获组

在 PCRE 中，我们使用 `\1`、`\2` 等来提取捕获组的值。捕获组的编号基于其左括号从左到右出现的顺序。

现在我们正竭尽全力使正则表达式易于维护。试想一下，如果有人决定在正则表达式中添加一对括号，会发生什么？你是否遇到过这种情况？如果是，你就知道这有多不方便了。一个更改可能会影响表达式中所有捕获组的引用。这违背了可维护性的原则，因为表达式内部括号的位置与处理捕获组值的正则表达式周边代码之间存在紧耦合。

本节的首要目标是固定捕获组的名称。次要目标是让这些名称具有语义含义。

如果你的方言支持命名捕获，请使用它们以提高可维护性。

## EMACS 命名捕获组

EMACS 使得固定捕获组的编号成为可能：`\(?1: .* \)`。这个名称没有语义，因为我们仍然必须依赖数字。

## PCRE 命名捕获组

在 PCRE 中，我们可以为捕获组使用专有名称：`(?<VARIABLE_NAME> .* )`。在支持命名捕获组的语言中，可以在正则表达式周围的代码中使用这些名称来提取这些捕获组。

例如，在 Python 中，我们已经学到 `match.group( 1 )` 会返回第一个捕获组的值。除了数字，我们也可以传递命名捕获组的名称。`match.group( 'VARIABLE_NAME' )` 会提取名称为 `VARIABLE_NAME` 的捕获组。

在 JavaScript 中，ES2018 引入了命名捕获组。让我们来解决在捕获组章节中看到的例子，它匹配了标签的价格和货币符号。这次，我们的解决方案将是可维护的，因为我们将使用命名捕获组。

**练习 1**：假设我们想要从以下格式的字符串中提取货币符号、数字价格以及带有货币符号的完整价格：

```
Price: €19.00
```

匹配此字符串的正则表达式如下：

```
/^Price: [€\$]\d\d\.\d\d$/
```

我们必须对美元符号进行转义，因为 `$` 是一个元字符，表示字符串结尾或行尾锚点。我们还必须对点号进行转义，因为它是一个元字符，表示任意一个字符。

在添加一些括号来捕获我们想要的值之后，正则表达式如下：

```
/^Price: (([€\$])(\d\d\.\d\d))$/
```

我们有三组捕获组来访问数据，如表 9-1 所示。

| 捕获组编号 | 数据 |
| --- | --- |
| 1 | 完整价格 |
| 2 | 货币符号 |
| 3 | 数字价格 |

从可维护性的角度来看，使用索引 `1`、`2` 和 `3` 来引用这些捕获组并不是一个好主意。

例如，想象一下，需求发生了变化，`Price` 可能是多语言的，你必须以出现的语言捕获价格文本。

```
/^(Price|Preis): (([€\$])(\d\d\.\d\d))$/
```

瞧。捕获组 `1`、`2` 和 `3` 分别变成了 `2`、`3` 和 `4`。你必须重写所有处理这些值的代码。

这就是为什么对编号捕获组感到厌倦是一种健康的感觉。让我们使用捕获组来提高代码的可维护性。我们的捕获组将如表 9-2 所示。

| 捕获组编号 | 数据 |
| --- | --- |
| `<fullPrice>` | 完整价格 |
| `<currency>` | 货币符号 |
| `<numPrice>` | 数字价格 |

我们将使用语法 `(?<name>content)` 来匹配捕获组名称中的 `content`。

```
/^Price: (?<fullPrice>(?<currency>[€\$])(?<numPrice>\d\d\.\d\d))$/
```

要创建一个命名捕获组，我们只需在左括号后写一个问号，然后将捕获组名称放在尖括号中。

这样就完成了。让我们执行这个解决方案。

```
console.table(
/^Price: (?<fullPrice>(?<currency>[€\$])(?<numPrice>\d\d\.\d\d))$/
.exec('Price: $15.99')
.groups
)
> (index)   Value
currency  "$"
numPrice  "15.99"
fullPrice "$15.99"
```

尽管你仍然可以用数字索引 `1`、`2` 和 `3` 来引用捕获组，但如果你访问 `groups` 属性，也可以使用它们的标签名称。

最后但同样重要的是，可以使用格式 `\k<groupName>` 对捕获组名称进行反向引用。

命名捕获组使你的表达式更具可维护性。这就是它们的目的。

## Perl 6 命名捕获组

语法是 `$<VARIABLE_NAME>=( .* )`。你可以在代码中使用 `$<VARIABLE_NAME>` 来检索其值。

## 案例研究：用于 JavaScript 的 XRegExp 库

XRegExp 是一个强大的库，它使 JavaScript 正则表达式更具表现力和可维护性。如果你经常需要使用正则表达式（这里没有双关语），那么我强烈建议在你的应用程序中包含 XRegExp。

你可以在 `xregexp.com` 上阅读该库的文档，并从 GitHub 克隆它。^(⁵⁴) 你也可以使用命令 `npm i xregexp` 从 `npm` 安装 XRegExp。

让我们选择后者，在一个空文件夹中使用 `npm` 在本地安装 XRegExp。

现在安装完成，我们可以打开文本编辑器（我使用的是 `atom.io`），在根目录下创建一个空的 `.js` 文件，并引入 XRegExp 库。

```
let XRegExp = require('xregexp');
```

让我们通过创建一个简单的表达式来测试该库。

```
let regex = XRegExp('(?i)^[ab]*$');
XRegExp.exec( 'aAbB', regex );
```

在这个例子中，你可以看到一个 XRegExp 特性：前导修饰符。这个特性使修饰符更容易阅读，因为你无需滚动到正则表达式的末尾来识别修饰符标志。

执行程序时，你可以看到大写字母和小写字母都被匹配到了。

让我们继续讨论可维护性。创建可维护正则表达式的一个必要条件是能够在表达式周围添加一些空格。我们可以使用 `x` 标志关闭对空白字符的求值。这意味着我们可以以任意方式格式化表达式的标记，而不改变其含义。如你所见，起始锚点、主循环和结束锚点现在位于不同的行中，执行后，该模式仍然正确地匹配了字符串。

```
let XRegExp = require('xregexp');
let regex = XRegExp(`(?ix)
^
[ab]*
$
`);
let result = XRegExp.exec( 'aAbB', regex );
console.log( result );
```

我们已经关闭了空白字符，但我们还可以做更多。我们可以插入一些注释，使表达式更具语义。想想看。有些表达式很长，为什么不逐个标记地解释它们呢？

```
let XRegExp = require('xregexp');
let regex = XRegExp(`(?ix)
^      # 起始锚点
[ab]*  # 任意数量的 a, b, A, B 字符
$      # 结束锚点
`);
let result = XRegExp.exec( 'aAbB', regex );
console.log( result );
```

添加注释后，解决方案仍然有效。

既然我们已经了解了扩展格式，让我们通过添加一些子模式来进一步提高表达式的可维护性。

要添加子模式，我们必须使用 XRegExp 的 `build` 方法，并指定一个对象，其中子模式名称作为键，要插入的值作为值。

```
let XRegExp = require('xregexp');
let regex = XRegExp.build(`(?ix)
^             # 起始锚点
{{charLoop}}  # 任意数量的 a, b, A, B 字符
$             # 结束锚点
`, {
charLoop: /[ab]*/
} );
console.log( XRegExp.exec( 'abAB', regex ) );
```

你可以看到正则表达式构建正确。

实际上，如果你使用正则表达式的 `source` 属性，你可以看到组装好的正则表达式。

```
console.log( regex.source() )
```

这些子模式类似于子程序，在创建较大的正则表达式时通常非常有用。

这是对 XRegExp 库的简短介绍。你已经看到了如何增强正则表达式的可维护性，此外还有更多可用特性。有趣的是，ES2018 的许多更新都基于 XRegExp 中已有的特性，因此从这种意义上说，XRegExp 是一个创新者。Unicode 转义、`dotall` 标志和命名捕获组在 XRegExp 库中都已可用，这也是我们在本章中使用它们的原因之一。

# 使用原子组

不仅循环会低效回溯，多选结构也会。我们可能已经匹配了某个多选分支中的一个节点，结果发现稍后又要检查同一字符，尝试匹配同一多选结构的其他分支。

我可以用个人生活中的一个简单例子来说明原子组。我这个人经常丢三落四。有时我在家里找东西。比如，假设我正在找手机。我会查看`桌子`、我的`口袋`，还有`厨房`。

一旦找到手机，我会检查是否有预约。我周二有预约。如果日期不匹配，我就不再需要手机了。

以下正则表达式首先匹配我找手机，然后检查日期：

```
/(?>table|pocket|kitchen) --> Tuesday/
```

假设在`Wednesday`我在口袋里找到了手机，然后发现今天是`Thursday`，所以我必须回溯。于是我回头再去`kitchen`找手机。这完全没道理！一旦我找到了手机，停止寻找手机才是合理的。这正是原子组要解决的问题。

例如，假设你想要精确匹配`list`、`lost`或`lust`。在 PCRE 中：

```
/^(list|lost|lust)$/
```

假设我们尝试匹配文本`lists`。我们从多选结构的第一个分支开始，完全匹配了`list`。由于我们本应解析完序列但还剩下一个`s`字符，于是我们回溯。现在我们回到了起点，字符串是`lists`，我们尝试用`lost`来匹配它。消耗了`l`字符后，我们不得不回溯。在第三个分支中，同样的情况发生了：我们匹配了`l`字符，结果发现需要的不是`u`而是`i`。

这一次，我们侥幸避免了不必要的回溯成本。但想象一下，如果回溯操作是嵌套的呢？如果在`l`字符的位置有一个复杂的子表达式会怎样？我们可能会浪费大量资源。

这就是为什么用占有式的方式来处理这个多选结构是完全合理的。PCRE 和 Perl 6 都支持创建原子组，也称为占有式分组。在占有式分组中，如果任何一个分支匹配成功，执行过程不会回溯去尝试另一个分支。如果我们试图回溯到占有式分组中，表达式会自动匹配失败。一旦你离开了一个占有式分组，就不能再回溯进去。

```
PCRE:    /(?> a|b)/
Perl 6:  / [ a|b ]: /
```

注意在 Perl 6 中，冒号在循环和多选结构中是一致的。从这个意义上说，Perl 6 似乎比 PCRE 更简洁。在大多数编程语言中，我们仍然要处理 PCRE 语法，所以如果你想使用占有式分组，就必须习惯 PCRE 的语法。

如果你曾经写过 Prolog 程序，那么占有式分组就像截断（`!`）操作。它从定理证明树中裁剪执行分支。

- 当“或”结构中的所有备选项互斥时，请使用占有式分组。

让我们完成上一个例子的执行。我们尝试用正则表达式匹配`lists`。

```
/^(?> list|lost|lust)$/
```

我们在第一个分支并匹配了`list`。我们离开了占有式多选结构。还剩一个`s`字符，而由于我们本应位于字符串末尾，所以我们回溯。由于我们不能回溯到占有式分组中，这个正则表达式无法匹配`lists`。问题解决了。

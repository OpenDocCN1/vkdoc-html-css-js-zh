# 9. 维护正则表达式

在行业中，编写和维护正则表达式常常令人心生畏惧。这是因为随着表达式变得庞大，阅读难度也随之增加。

这让我想起了健身房里的一个词 `Fluessigkeitsliebhaberei`，意思是“热爱流体”。就这么一个词，毫无意义。德语单词很长，有时非常长。

`Rindfleischetikettierungsueberwachungsaufgabenuebertragungsgesetz` 是另一个例子。大多数读者习惯于阅读短单词。然后突然出现这样一个长词，我们所有的速读技巧都派不上用场了。

软件开发人员习惯于阅读代码。但代码通常包含大量空白字符。下面的 `PCRE` 表达式就像是一个超长的德语单词：

```
/^(?=.*[A-Z].*[A-Z])(?=.*[!@#$&*])(?=.*[0-9].*[0-9])(?=.*[a-z].*[a-z]).{8,}$/
```

这远不是我见过的最糟糕的正则表达式，但要解读它仍然需要时间。如果我们能给它周围添加一些空白字符呢？

默认情况下，只有 `Perl 6` 允许使用空白字符进行格式化。不幸的是，在其他方言中，空白字符是匹配自身的字面量字符。

不过，也并非无计可施。在本章中，我们将把那些看似无法阅读、杂乱无章的正则表达式转化为可维护的代码。我们将探讨创建可维护正则表达式的可行方案。

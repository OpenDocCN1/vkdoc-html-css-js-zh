# 扩展模式

PCRE 及部分 ERE 语言支持扩展模式。其语法如下：

```
/(?x) 正则       # 注释行 1
主体       # 注释行 2
处于       # 注释行 3
扩展       # 注释行 4
模式       # 注释行 5
/
```

在扩展模式下，空白字符不匹配任何内容，仅用于格式化。井号（`#`）表示注释的开始，持续到行尾。

`(?x)` 应位于正则表达式的开头。你不能在表达式中间才开启扩展模式。实际上，`(?x)` 是一个正则标志或修饰符。在某些方言或正则库中，除了使用 `/a/i`，你也可以使用 `/(i)a/` 这种结构。将正则修饰符置于前方的优势在于可读性。当表达式较长时，阅读者更希望在阅读表达式本身之前先了解其修饰符。

我强烈推荐开启扩展模式。回顾以下表达式：

```
/^(?=.*[A-Z].*[A-Z])(?=.*[!@#$&*])(?=.*[0-9].*[0-9])(?=.*[a-z].*[a-z]).{8,}$/
```

以下是同一表达式的扩展模式等效形式：

```
/(?x)
^                  # 起始锚点
(?=.*[A-Z].*[A-Z]) # 至少两个大写字母
(?=.*[!@#$&*])     # 且至少一个特殊字符
(?=.*[0-9].*[0-9]) # 且至少两个数字
(?=.*[a-z].*[a-z]) # 且至少两个小写字母
.{8,}              # 字符串长度至少为 8 个字符
$                  # 结束锚点
/
```

信不信由你，这与前面的单行表达式是相同的。

遗憾的是，并非所有方言都支持扩展模式。例如，在 EMACS 和 VIM 中就没有。在 JavaScript 中也不支持扩展模式，但你可以使用 `XRegExp` 库^((53)) 来开启扩展模式。

```
const regex = new XRegExp( '                                   \
^                   # 起始锚点                             \
(?=.*[A-Z].*[A-Z])  # 至少两个大写字母                     \
(?=.*[!@#$&*])      # 且至少一个特殊字符                    \
(?=.*\\d.*\\d)      # 且至少两个数字                       \
(?=.*[a-z].*[a-z])  # 且至少两个小写字母                    \
.{8,}               # 字符串长度至少为 8 个字符             \
$                   # 结束锚点                             \
');
```

使用 `XRegExp` 构造函数时，不要忘记转义反斜杠。为了说明这一点，我使用了 `\\d` 而不是 `[0-9]`。

即使没有扩展模式，如果你能跳出常规思维，也可以让你的代码更易于维护。例如，使用 JavaScript 的 `RegExp` 构造函数并结合 JavaScript 语法，你可以编写出易于阅读的代码。

```
const regex = new RegExp(
'^'                  + // 起始锚点
'(?=.*[A-Z].*[A-Z])' + // 至少两个大写字母
'(?=.*[!@#$&*])'     + // 且至少一个特殊字符
'(?=.*\\d.*\\d)'     + // 且至少两个数字
'(?=.*[a-z].*[a-z])'   + // 且至少两个小写字母
'.{8,}'               + // 字符串长度至少为 8 个字符
'$'                    // 结束锚点
);
```

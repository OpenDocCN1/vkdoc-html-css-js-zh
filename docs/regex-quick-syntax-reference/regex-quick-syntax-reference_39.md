# 正则子程序

少数正则方言提供了子程序。子程序类似于编程语言中的函数。如果你不将整个表达式写成一个整体，而是将表达式的某些部分抽象为子程序，那么你的正则表达式将更具可读性。你的表达式也会更加 DRY（不要重复自己）。毕竟，在同一个表达式中复制粘贴同一个子程序三四次，并不易于维护。

子程序在表达式中的任何位置被调用时都会执行。如果子程序匹配成功，则正则表达式的执行继续正常进行。如果子程序匹配失败，则会发生回溯。

## PCRE 子程序

在 PCRE 的情况下，请查阅你的正则宿主语言的文档。并非所有 PCRE 语言都支持子程序。例如，在 JavaScript 中，我建议使用 XRegExp 库来增强正则表达式的表达能力。

```
var time = XRegExp.build('(?x)^ {{hours}} ({{minutes}}) $', {
hours: XRegExp.build('{{h12}} : | {{h24}}', {
h12: /1[0-2]|0?[1-9]/,
h24: /2[0-3]|[01][0-9]/
}, 'x'),
minutes: /^[0-5][0-9]$/
});
```

`{{hours}}`、`{{minutes}}`、`{{h12}}` 和 `{{h24}}` 这些占位符会在各自的位置插入子表达式。

XRegExp 的子程序看起来有点复杂。通用的 PCRE 子程序语法则相对易读一些。

```
(?(DEFINE)
(?
# 子程序 1 的主体
)
(?
# 子程序 2 的主体
)
)
```

表达式中的 `DEFINE` 部分从不匹配任何内容。它用于声明你的子程序。

在表达式中使用 `(?&SUBROUTINE1)` 来匹配它。

让我们看一个示例，匹配一个货币符号和一个可能包含整数部分和小数部分的价格。我们假设小数部分最多可以有两位数字。

```
/(?x) (?&货币) (?&价格)
(?(DEFINE)
(? [\$\€] )
(?    \d++ \.?+ \d{0,2} )
)
/
```

## Perl 6 子程序

Perl 6 的子程序语法比 PCRE 语法更简洁，但其工作方式与 PCRE 版本大致相同。

你可以通过以下方式声明 Perl 6 子程序：

```
/
:my regex 子程序 1 {
# 子程序 1 的主体
}
:my regex 子程序 2 {
# 子程序 2 的主体
}
/
```

你可以在 Perl 6 表达式中使用 `<子程序 1>` 来调用子程序。

让我们重写你在"PCRE 子程序"部分看到的同一个货币示例。

```
/(?x) (?&货币) (?&价格)
(?(DEFINE)
(?  [\$\€] )
(?     \d++ \.?+ \d**0..2 )
)
/
```

## 扩展模式、子程序和抽象化

*抽象化* 是指识别可重用代码并将其提取到一处。我们可以创建子程序来抽象正则表达式中重复的功能片段，并且可以根据需要多次重用它们。子程序对于编写可维护的 DRY 正则表达式至关重要。

借助扩展模式的优势，你就能告别冗长且难以维护的正则谜题。你甚至可以清晰无比地编写长达数千字符的正则表达式。想象一下，在阅读本书之前，你可能会连一个 20 字符的表达式都读起来费劲。

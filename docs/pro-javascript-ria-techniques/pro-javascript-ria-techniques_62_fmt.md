# 如果文本需要修改怎么办？

你需要重新在图形软件中创建图片。若内容需要定期更新（例如本章示例中的新闻文章标题，如图 6-1 所示），维护工作就会变得频繁、重复且单调。

此外，这种技术还存在两个无障碍性问题。其一涉及视障用户，他们需要放大文字才能阅读（借助额外软件或浏览器的内置缩放功能）。此时文字尺寸会增大，但图片却不会随之缩放。事实上，如果图片被放大，其像素化特性将更加明显，导致可读性降低。无论是视障用户还是普通用户，让文字更难阅读都不是我们的目标。

这种技术的第二个无障碍性问题在于对 `alt` 属性的使用：

```html
<h1><img src="heading-news.png" alt="News" /></h1>
```

当屏幕阅读器朗读这个 `<h1>` 标签的内容时，用户会听到标题内包含一个图片标签，以及其关联的 `alt` 属性值。更推荐的做法是将相同文字直接包含在标题标签中，比如这样：

```html
<h1>News</h1>
```

若按此方式朗读，用户只会听到你希望传达的标题文本，从而降低用户产生混淆的可能性。

同样地，搜索引擎爬虫或其他访问页面内容的远程计算机，并不总能从第一个示例的标记中提取到正确的标题文本——即便能够提取，它们在系统中赋予这段文字的权重也可能不如第二个示例中更简洁的标题。标题文本越简洁、语义化程度越高，对最终用户就越易于理解。

让我们采用更语义化的 HTML 标记来处理标题文本，同时使用 CSS 为标题标签设置背景图片，并将文字隐藏起来。这样我们的标题 HTML 就变成了更理想的形式：

```html
<h1>News</h1>
<h2>New product released: Human Teleporter</h2>
```

现在我们使用 CSS 样式规则，在页面上产生与 `<img>` 标签相同的视觉效果，即风格化标题：

```css
h1,
h2 {
  text-indent: -10000px; /* 将真实文本隐藏在屏幕边缘之外 */
  font-size: 1px; /* 确保标题的大字体尺寸不影响图片尺寸 */
}

h1 {
  background-image: url(heading-news.png);
  width: 257px; /* 图片宽度 */
  height: 65px; /* 图片高度 */
}

h2 {
  background-image: url(heading-new-product.png);
  width: 353px; /* 图片宽度 */
  height: 62px; /* 图片高度 */
}
```

视觉效果与之前完全相同，但我们修复了此前方法的一个无障碍性缺陷：移除了标题标签内的图片标签，代之以每个标题单独的语义化文本表示。

这已经好多了。但维护性问题依然存在——更新标题文本就需要创建新的图片文件。现在让我们看一个更易于维护的解决方案。

## 动态生成文本图像

为了消除手动创建新图片文件的需求（当你需要更改自定义字体中的文字时），你可以动态生成所需字体的文本。这既可以在服务器端完成，也可以在浏览器内实现。让我们看看几种可用的技术及其优缺点，以便你选择最适合应用程序需求的解决方案。

## 直接使用 CSS 嵌入字体文件

作为开发者，我们自然希望能以最简单的方式在页面上使用自定义字体。我们希望将文本内容直接包含在 HTML 页面中，并用 CSS 来自定义字体、颜色和大小——就像使用 Arial、Helvetica 和 Times New Roman 等内置字体一样。

最简单的方法是通过 CSS 直接指定自定义字体，采用标准格式如下：

```css
h2 {
  font-family: "Silom", monospace;
}
```

这里我们指定所有 `<h2>` 标题标签的内容都应使用 `Silom` 字体。如果用户机器上未安装此字体，则会回退到浏览器默认的等宽字体。（在等宽字体中，所有字符占用相同宽度。）当然，真正拥有 `Silom` 字体的用户并不多，因此大多数浏览器会显示默认的等宽字体。

要求最终用户仅为显示你的网页而下载并安装自定义字体并不合适。很多时候，用户甚至不知道如何操作，或者在其工作环境（如企业办公环境）中不被允许。

## CSS Web 字体

理想情况下，我们需要一种方式，让浏览器在通过 CSS 引用自定义字体文件时按需加载。有趣的是，从 IE 4 开始就已经具备通过 CSS 嵌入自定义字体文件的能力，虽然直到最近都被人们遗忘。随着 W3C 规范中 CSS Web 字体的提案提出，这一功能重新获得关注，该规范旨在让所有浏览器厂商采用统一方法来实现这一实用功能。这项新推荐标准（你可以在 `http://www.w3.org/TR/css3-webfonts/` 在线阅读）允许 Web 开发者在页面上声明新字体，并在该字体名称被用于其他 CSS 样式规则时加载对应的字体文件。

> **注意**：CSS Web 字体是 W3C 的新推荐标准，因此并未在所有浏览器中完全实现。由于该技术是 W3C 推荐标准，一旦被浏览器广泛采用，它应被视为 CSS 中自定义字体嵌入的事实标准。

请查看以下针对 `Silom` 字体的 W3C Web 字体格式描述：

```css
/* 为其他 CSS 样式声明一个新的字体 */
@font-face {
  /* 声明新字体在 CSS 文件中的名称 */
  font-family: "Silom";

  /* 定位服务器上的字体文件，并声明其格式为 TrueType 字体格式 */
  src: url(/assets/fonts/silom.ttf) format("truetype");
}
```

然后你就可以像预期那样在 CSS 中引用 `Silom` 字体，方式与之前相同：

```css
h2 {
  font-family: "Silom", monospace;
}
```

只要你的浏览器支持通过 `@font-face` 指令以这种方式加载外部字体，你就会看到 `Silom` 字体生效。不支持该技术的浏览器将使用 `font-family` 样式属性中指定的后备字体——在本例中为浏览器的默认等宽字体。

该技术支持两种字体格式：OpenType 和 TrueType。OpenType 是国际 ISO 标准，旨在替代由苹果公司开发且需要授权使用的专有 TrueType 字体格式。

## 嵌入字体文件的问题

遗憾的是，浏览器对 CSS 网页字体技术的支持程度参差不齐。`Firefox` 3.5 及更高版本支持使用该技术的 TrueType 和 OpenType 字体格式，但在撰写本文时，该浏览器版本尚未拥有庞大的用户安装基数。`WebKit` 引擎团队已实现该技术，`Google Chrome 2` 和 `Safari 3` 浏览器均提供支持。`IE` 4 及更高版本支持该技术，但仅限于使用其专有的嵌入 OpenType (`EOT`) 字体格式，这是 OpenType 格式的一种压缩且受限的版本。

使用 `EOT` 格式时，文件本身包含一个允许使用该字体的可信站点列表。这一限制意味着，任何希望在自己的网站上复制和重用受版权限制的字体文件的人都将无法做到。要生成 `EOT` 字体，你需要使用微软的 Web 嵌入字体工具 (`WEFT`)，该工具可从 `http://www.microsoft.com/typography/web/embedding/weft3/weft01.htm` 获取。

这种方法的另一个问题是，在你的 `CSS` 中提供字体文件的链接可能会让你在版权方面陷入法律灰色地带。你的许多客户，无论是企业客户还是其他客户，都会为其品牌使用特定的字体，通常情况下，他们为此支付了高额费用以获得这些字体的独家使用权。由于你的 `CSS` 是公开可访问的（浏览器必须能访问它才能使用）并且以纯文本形式编写，访问你网站的热心开发人员可能会仔细查看你的 `CSS`。一旦他们发现对外部字体文件的引用，他们可能会通过其 URL 从你的服务器下载该字体文件并使用，而无需为此支付版权费用。这是一个严重的版权禁忌，大多数组织不希望其独家字体被不当使用。

微软正在推动其 `EOT` 规范成为 W3C 推荐标准，主要原因在于其生成的字体文件包装在数字版权管理（DRM）层中。这意味着这些字体只能由许可方在嵌入文件本身的可信网站列表上使用。当然，这类文件仍然有可能被下载，但除了在其设计时的上下文（即创建该文件并计划使用的网站）中使用外，无法在其他地方使用。

另一种名为跨源资源共享 (`CORS`) 的下载限制方法正在考虑成为 W3C 推荐标准（参见 `http://www.w3.org/TR/cors/`），并且 Mozilla 已在它的 `Firefox` 浏览器中实施。这是一种可应用于任何服务器请求内容（而不仅仅是字体文件）的技术。它限制内容仅当请求域名位于服务器维护的允许域名白名单中时，才能被传送到页面。此访问列表使用新的 HTTP 响应头，最值得注意的是 `Access-Control-Allow-Origin` 头，其中包含允许访问请求内容的域名列表。例如，要仅允许 `http://mydomain.com` 域访问，则需在响应中添加以下 HTTP 头：

```
Access-Control-Allow-Origin: http://mydomain.com
```

要允许所有域访问，可以使用通配符代替特定域名：

```
Access-Control-Allow-Origin: *
```

就目前而言，此技术存在两个缺点：

-   请求的字体文件仍将被下载并缓存在浏览器中，这使得心怀恶意的用户可以从其计算机中取出该文件并上传到自己的域名，从而绕过访问控制限制。

-   由于这仍是 W3C 的一项进行中的工作，其浏览器实现目前过于有限，无法发挥太大作用。与其他标准一样，在该技术最终确定并被所有主流浏览器采用之前，你不会想要使用它。

对于目前来说，你可能希望直接对服务器进行编程，使其仅在请求页面与字体文件托管在同一服务器上时，才将字体文件发送给请求页面。你可以通过在发送内容之前检查域名来实现这一点。不幸的是，这需要在服务器上进行一些额外的处理时间，可能会影响页面的性能，尤其是在应用于所有外部文件的情况下。

## 让服务器生成文本图像

与其手动创建每个自定义样式的标题图像，不如让你的 web 服务器动态地为你生成这些图像。假设你的服务器包含一个脚本，该脚本通过其 URL 的查询字符串接受一个文本字符串作为参数，并返回一个图像文件以供页面包含。用于创建渲染标题“News”的样式化标题图像的 URL 可能类似于以下形式，其中`generate-image`是生成图像的脚本文件名：

`http://www.myserver.com/generate-image?text=News`

为了使这在你的特定 web 服务器上工作，你需要使用合适的服务器端技术和预编写的代码组件来下载，或者自己编写。现在，让我们看看几种常见服务器技术所需的基本脚本：`PHP`，`ASP.NET`和`JSP`。

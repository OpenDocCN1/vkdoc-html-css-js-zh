## 将最佳实践付诸实践

所以，你正坐在电脑前，准备按照最佳实践编写一个 HTML 页面。那么，你该如何着手呢？

请记住，你的目标是编写一致且易于其他开发者理解的代码，并最终构建出一个标记正确、可供最终用户访问的网页。

让我们一起来看看一些指导原则和规则，它们应该能帮助你遵循最佳实践。

### 编写整洁有序的代码

代码缩进能增强代码的可读性。根据代码的分组或嵌套层级对代码段进行缩进，会使你的代码更易于阅读和理解。请记住，这里的目标之一就是便于其他开发者进行维护。就像你在客人到来前会整理客厅一样，你也应该保持代码整洁，以备不时之需。

应使用制表符（Tab）来进行缩进，而不是空格。这既能提高可维护性和可读性，又能减少页面的整体体积。在你的开发环境中，你可以配置制表符的间距，使其映射到特定数量的字符空格。

通常情况下，两个、四个或八个字符的空格对于可读性来说已经足够。

位于其他标签内部的代码块应该进行缩进。每嵌套一层，代码就应该向内缩进一个制表符。那些仅包含显示文本内容或内联元素的标签，其内容无需相对于父级进行缩进。请看下面的示例，它展示了一些典型的间距设置。

```
<div id="container">
    <p>A paragraph of content</p>
    <table>
        <tr>
            <th>Name</th>
            <th>Value</th>
        </tr>
        <tr>
            <td>Red</td>
            <td>ff0000</td>
        </tr>
    </table>
</div>
```

### 减少注释

我相信你见过很多网站上散落着 HTML 注释的例子。它们遵循以下格式：

```
<!-- comment goes here -->
```

通常，它们被用来标记页面中特定标签或部分的开始和结束。

虽然这在试图确定后端生成的代码对你的前端输出做了什么时可能有用，但大多数开发环境和内置的浏览器开发工具都允许你定位内容块和部分的起始点与结束点，因此这种注释的使用方式有些多余。

在 HTML 中包含大量注释意味着终端用户必须先通过网络下载更多的标记数据到他们的浏览器，然后才能看到可与之交互的页面。我建议尽量避免使用 HTML 注释，以下情况除外：

- 当某些标记的使用方式在日后可能会让查看你代码的其他开发者感到困惑时。注释可以提供解释并避免混淆。
- 当它能使特定浏览器产生特定行为时。比如在 IE 中的条件注释，我们接下来就会看到。

### 为 IE 使用条件注释

从 IE 5 及以上版本（仅限 Windows）开始，微软添加了一个非常有用的功能，称为*条件注释*。其思路是，如果开发者需要编写专门针对某个特定 IE 版本或针对 IE 本身的代码，可以通过一种特殊格式的注释标签来实现，而无需使用 JavaScript 或服务器端浏览器检测。对于所有其他浏览器而言，此标签的内容显示为标准注释，因此会被忽略。

以下是一个针对 IE 6 及以上版本的条件注释示例：

```
<!--[if gte IE 6]>
<p>You are browsing with Internet Explorer version 6 or above.</p>
<![endif]-->
```

下面这个条件注释仅针对 IE 用户：

```
<!--[if IE]>
<p>You are using Internet Explorer browser.</p>
<![endif]-->
```

最后一个示例，这个条件注释针对的是版本低于 7 的 IE：

```
<!--[if lt IE 7]>
<p>You are using a version of Internet Explorer older than version 7.</p>
<![endif]-->
```

在条件注释中，`lt` 表示小于，`gt` 表示大于，`lte` 表示小于或等于，`gte` 表示大于或等于。

这项技术在导入外部样式表时发挥了重要作用。考虑以下代码，它通常位于 XHTML 文档的 `<head>` 块内。它有条件地为 IE 6 用户加载一个外部样式表。

```
<link rel="stylesheet" href="master.css" type="text/css" />
<!--[if IE 6]>
<link rel="stylesheet" href="master.ie6.css" type="text/css" />
<![endif]-->
```

大多数浏览器在读取这段代码时，会看到一个指向单个样式表 `master.css` 的引用，后面跟着一条注释（位于 `<!--` 和 `-->` 注释标记之间），它们会忽略这条注释。IE 6 是个例外。因为它识别出一个条件注释块的开始，该块指定其中的代码应仅由该特定 IE 版本读取，因此它会选择读取并解析该注释内的代码。

这使得开发者可以为所有符合标准的浏览器维护一个主样式表。但是，对于那些特定 IE 版本不配合的情况，他们可以包含一个指向较小样式表的引用，该样式表只包含针对那些出现问题的元素进行样式修复的代码。将来，当 IE 6 成为遥远的记忆时，开发者只需删除该条件注释及其内部的代码，即可从他们的网站中移除所有特定于版本的代码或样式。

### 正确设置 `<html>` 标签

在每个 HTML 文档的 DTD 声明之后，是 `<html>` 标签，它包裹着文档的其余内容。

对于 HTML 文档，可以只保留标签本身，不指定任何属性；但在 XHTML 的情况下，必须包含某些属性。请看这个来自 XHTML 文档的示例：

```
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en-GB" lang="en-GB" dir="ltr">
```

这个示例包含以下组成部分：

`xmlns`：该属性定义了文档中自定义标签的命名空间（这是必需的，尽管目前在实际应用中很少使用）。

`xml:lang` 和 `lang`：这些属性指定了整个文档的语言，例如 `en` 代表英语（通常还包括地区区域设置，如 `en-GB` 代表大不列颠）。当文档中特定内容的语言发生变化时，例如使用了法语表达 *c'est la vie*，则此文本必须用标签包裹起来进行标记。在许多情况下，你会使用 `<span>` 标签，并为该元素设置 `xml:lang` 和 `lang` 属性。在前面的例子中，这个属性的值将是 `fr-FR`。

`dir`：这指定了文档内内容的文本方向。对于大多数西方语言，该值将为 `ltr`（从左到右）。但是，如果内容的文本方向发生变化，你应该通过在包裹该内容的标签上设置 `dir` 属性来注明这一点。唯一可能的另一个值是 `rtl`（从右到左）。

### 指定内容类型

建议向浏览器或用户代理指定文档的内容类型，以防其无法直接从文件本身读取该信息，因为这可以减少假设，并确保内容以其编写时的格式可读。使用 HTML 文件 `<head>` 部分中的 `<meta>` 标签来完成此操作，如下例所示。



```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" /> 在这行代码中，浏览器被告知内容类型采用`UTF-8`字符集。

这一特定字符集非常灵活，因为全世界大多数字符都可以直接插入到文档中，而无需转换为 HTML 实体代码。这对于标准英文字母以外的字符尤其有用。

## 第 1 章 ▸ 夯实基础

### 设置页面标题

`<title>`标签是任何文档必不可少的组成部分。它应是一个用尽可能少的词语描述文档的单一标题。该标题在搜索引擎结果中用作页面链接的文本，并在浏览器窗口顶部显示。

考虑到这一点，你可能决定在页面标题中透露一些关于页面在网站结构中位置的其他信息，为那些通过谷歌搜索偶然发现你页面的人提供一些上下文。以下格式在可读且相当简洁的同时，似乎足以传达这些信息：

`<title> *页面标题* - *章节名称* - *网站名称*</title>`

在此示例中，`*页面标题*`几乎总是与页面的主标题（通常包含在文档的`<h1>`标签中）一致。当然，你可以在各值之间使用任何你喜欢的分隔符；顺序才是关键部分。

明智的做法是确保网站中每个不同的页面在其章节内都有一个唯一的页面标题，这样在搜索引擎结果或站点地图中就不会出现同名的重复结果。

### 分离表现、内容和行为

将文档内容与实现其设计和布局的代码分离开来非常重要。这种分离程度让你能够轻松进行样式更改，而无需修改标记。你甚至可以相当简单地用另一种布局替换网站的整体布局，而不会影响其内容。

你应该避免在标记中使用内联样式（通过许多标签的`style`属性设置），因为这会使页面的维护变得极其困难。开发人员应知道在样式表文件中查找与样式和布局相关的所有内容，而在 HTML 文档中查找与内容相关的所有内容。两者绝不应混杂。你还应将所有 JavaScript 代码放在 HTML 文档之外。

相反，在 HTML 中，应通过使用`<link>`标签引用样式表，使用`<script>`标签引用 JavaScript 代码。在 HTML 标签中添加`class`和`id`属性应是连接这些文件的唯一方法；`style`属性和 JavaScript 事件处理程序不应与你的内容混杂。

你可以根据你希望这些样式在哪种设备上显示来引用样式表文件。例如，你可能希望为打印机和屏幕包含单独的样式表，如下例所示：

```html
<link rel="stylesheet" href="master.css" media="screen" />
<link rel="stylesheet" href="master-print.css" media="print" />
```

当在`<link>`标签上指定了`media`属性时，只有当该属性包含值`print`时，打印机才会读取样式表；只有当该属性包含值`screen`时，屏幕才会读取样式表。这使你能够根据呈现介质不同地设置内容样式。例如，在打印机上，你可能只需要页面基本内容。你可以创建隐藏导航、页眉和页脚的样式，只保留主要内容体，这通常是大多数打印你页面的人离开浏览器时想要阅读的内容。

### 为整个文档添加包装元素

在页面的`<body>`标签内，你通常希望为整个页面添加某些布局样式。你很快会发现，仅将样式应用于`<body>`标签不足以完成你想要执行的所有定位和布局。作为解决方案，我建议你在页面内容周围添加一个“包装”元素（通常是一个`<div>`标签），并将额外的布局样式放在该元素内，而不是直接使用`<body>`标签本身。

`<div>`标签仅定义了一个内容块，不会为其中的内容增加额外含义。使用`id`属性为该元素设置一个合适的名称，以便关联 CSS 样式，如下所示：

```html
<body>
    <div id="page">
        ...
    </div>
</body>
```

如果你的设计非常简单，也许可以仅使用`<body>`标签。不过还是建议添加一个包装元素，因为你永远不知道你的设计将来会如何变化。

### 帮助 CSS 和 JavaScript 定位特定页面

我提倡的一种做法是：为网站中每个页面的`<body>`标签添加一个唯一的`id`属性。

假设你为一个多页面网站创建了通用样式，并且你希望在一个特定页面上略微不同地应用某一特定样式。在这种情况下，你需要创建一个例外规则。如果网站上的每个页面都有一个唯一的`id`属性，你就可以创建一个仅针对这一个页面的样式。

想象一下，你希望网站上所有段落文本都以白底黑字显示，但在首页上，你希望它反转：黑底白字。首页将拥有一个唯一的`id`属性，如下所示：

```html
<body id="homepage">
```

而段落文本的样式将如下所示：

```css
p {
    background:white;
    color:black;
}

#homepage p {
    background:black;
    color:white;
}
```

此外，通过以这种方式使用`id`属性，你可以使用 JavaScript 的`document.getElementById`方法轻松获取对特定页面的引用：

```javascript
var homepage = document.getElementById("homepage");
```

### 保持一致地命名 ID 和 Class 属性

你应该将正文内容的每个逻辑部分或块包装在各自的`<div>`标签中，并使用合理的、与上下文相关的值作为它们的`id`属性。某些元素在大多数页面和网站中是通用的，包括导航、页眉和页脚。在可能的情况下，这些类型的元素应在页面和项目间保持一致，以利于未来的维护。这使开发人员即使处理不熟悉的页面也能识别元素。

考虑使用类似以下的`id`属性值：

```html
<div id="header">
<div id="content">
<div id="aside">
<div id="footer">
<div id="navigation">
```

你应该根据`id`或`class`属性所包含的内容类型来命名它们的值，而不是根据它们使用的任何样式。例如，这种形式：

```html
<p class="error">
```

比这种形式更好：

```html
<p class="red-text">
```

> **提示：** 在`id`和`class`属性值中使用连字符（`-`）分隔单词使它们更易于阅读。

用与内容相关的信息标记`class`属性意味着，当你的网站设计师更改页面的特定部分时，你无需更改标记；只需要修改样式表即可。这也意味着 HTML 文档本身仅作为对其中内容的描述而独立存在，而不是依赖于任何外部文件、样式或代码。

### 正确排列内容顺序

确保文档中内容的顺序正确与确保内容被正确的标签标记同样重要。请记住，你需要确保当页面被朗读时，最重要的页面内容——页面的主体或主题——被首先朗读，而不那么重要的内容——例如导航链接和版权信息——被最后朗读。屏幕阅读器软件严格按照源代码顺序朗读文档内容，这意味着标记中先出现的内容会被首先朗读。



# 构建坚实基础

为了让屏幕阅读器用户以最有意义的方式获取内容，你应按以下顺序组织标记语言的 `<body>` 内容：

-   页面标题
-   简短跳转链接列表（页面内锚点链接），帮助读者直接跳至页面后续内容
-   主体内容
-   侧边内容（边栏、相关内容或上下文相关链接）
-   主导航
-   页脚与版权信息

你可以使用 CSS 修改页面的视觉布局，使其符合设计需求。本章后续的“样式无障碍指南”部分将对此进行说明。

## 将前景图像与背景图像分离

区分页面中与内容直接相关的图像和与布局或模板相关的图像非常重要。与页面内容直接相关的图像——如图表、图示、宠物照片等——应使用 `<img>` 标签进行标记。所有其他图像，包括公司徽标和图标，则应在样式表文件中通过背景图片引用。这提供了另一种区分页面布局与相关内容的方式。

问问自己：“如果我只打印页面的主体内容，这张图像会显得格格不入吗？还是与内容上下文相关？”实践中，你会发现大多数图像文件将通过 CSS 引用，而非使用 `<img>` 标签标记。

在确实使用 `<img>` 标签的情况下，请记得使用 `alt` 属性，为因故无法在浏览器中查看图像的用户描述图像内容。如果图像较为复杂（如曲线图或图表），可能需要更详细的说明。此时可考虑使用 `longdesc` 属性，指向包含图像所传达信息深度描述的页面 URL。

## 正确使用表格

直到几年前，使用 HTML `<table>` 标签进行页面组件定位仍属常见做法。`<table>` 标签应仅用于表示表格数据，绝不可用于定位页面内容；CSS 完全足以胜任内容定位和页面布局的任务。

你可以通过多种方式为表格数据添加额外的语义信息，所有这些方法都能提升表格内信息的可访问性，因此值得实施。简而言之，这些方法包括：

-   在起始 `<table>` 标签后使用 `<caption>` 标签为表格添加标题。请注意，如果不希望显示标题内容，可随时通过样式表隐藏此标签内容，但为页面添加尽可能多的语义数据始终是明智之举。
-   使用 `<table>` 标签的 `summary` 属性，提供表格内容及其目标的简要概述。该属性可被朗读出来，以概括表格内容。
-   使用 `<thead>`、`<tbody>` 和 `<tfoot>` 标签，将表格的头部、主体和底部区域分组。请注意这些标签必须按特定顺序放置：先放 `<thead>` 和 `<tfoot>`，再放 `<tbody>`。这样浏览器可以在其余内容仍在加载时，先显示表格的头部行和底部行。
-   使用 `<th>` 标签标记表头单元格，使用 `<td>` 标记实际数据单元格。
-   为每个表头单元格赋予唯一的 `id` 属性值。然后，为每个数据单元格将其 `headers` 属性值设为关联表头单元格 `id` 值的逗号分隔列表。

## 优化表单

你应使用 `<fieldset>` 标签将逻辑上相关的表单区域分组，每个 `<fieldset>` 内包含一个 `<legend>` 标签，为该字段组提供标题。例如，信用卡申请表可能包含个人信息、信用记录和银行详情等部分。在这种情况下，可以创建三个 `<fieldset>` 标签，并分别设置 `<legend>` 标签为“个人信息”、“信用记录”和“银行详情”，示例如下：

```
<form method="get" action="/">
  <fieldset>
    <legend>个人信息</legend>
    ...
  </fieldset>
  <fieldset>
    <legend>信用记录</legend>
    ...
  </fieldset>
  <fieldset>
    <legend>银行详情</legend>
    ...
  </fieldset>
  <input type="submit" value="保存" />
</form>
```

确保表单中每个具有关联文本标签的字段都已使用 `<label>` 标签标记。该标签需使用 `for` 属性，其值应与关联字段的 `id` 属性值一致。在默认浏览器行为下，该设置可使 `<label>` 标签变为可点击区域，从而将表单焦点移至关联字段，用户在选择标签时即可与相应字段交互。为了更灵活地对表单字段及其关联标签应用样式规则，请在每个字段周围添加 `<div>` 包装标签，以便通过样式表定位字段并设置间距及其他视觉属性。示例如下：

```
<div class="field">
  <label for="first-name">名字</label>
  <input type="text" id="first-name" name="first-name" />
</div>
```

需特别关注 `<fieldset>` 内 `<legend>` 和 `<label>` 标签中使用的文字。当这些字段标签被某些屏幕阅读软件朗读时，`<legend>` 标签内的文字会作为前缀附加到 `<label>` 标签的文字前，为听众提供额外上下文。你必须确保朗读时这些内容对听众而言是清晰合理的。

## 避免使用框架

你应不惜一切代价避免使用框架集。它们会使网站的内容和布局难以维护，在小屏幕设备（如手机）上使用起来很麻烦，并且给不使用鼠标作为主要输入方式的终端用户浏览内容造成困难。

内联框架（使用 `<iframe>` 标签）应尽量少用，甚至不用。它们可能让终端用户感到困惑，且缺乏单页 HTML 文档固有的无障碍特性。

## 网页内容无障碍指南

如果你不熟悉网页内容无障碍指南（WCAG），请阅读 W3C 的推荐标准，访问 [`www.w3.org/TR/WCAG20/`](http://www.w3.org/TR/WCAG20/)。这些指南定义了网页无障碍合规性的三个不同等级：A、AA 和 AAA，其中 AAA 代表最高级别的无障碍内容。

无障碍指南不仅涉及技术层面，还涉及创意设计、文案撰写和信息架构，这些共同为终端用户提供完整的体验。AAA 合规性是任何网站开发者追求的终极目标，应始终努力达成。然而，AA 合规性通常可以实现，对于受时间或设计限制的开发者来说是一个理想的中间标准。遵循本章指南，你将通过技术手段为提供最优质的无障碍体验迈出坚实一步，但你必须了解不同用户如何与网页交互，因此我鼓励你阅读 WCAG 文档。

# 关于快捷键与网页可访问性的注意事项

## 避免使用 `accesskey`

曾被誉为网页绝佳增强功能的 `accesskey` 是键盘快捷键，允许用户跳转到页面上的特定内容或外部页面。然而，现代观点已将其否定，你应该避免使用 `accesskey`。

键盘快捷键对不使用鼠标的最终用户非常有用。事实上，这些用户通常已在操作系统中设置了他们自己的快捷键。不幸的是，`accesskey` 常常与用户定义的键盘快捷键冲突。当用户认为他们正在使用自己的快捷键，但实际上却触发了 `accesskey` 快捷键，或反之亦然时，他们会感到困惑。

`accesskey` 也可能令人困惑，因为不同网站通常使用不同的键来执行相同的操作。这意味着最终用户必须为每个访问的网站熟悉一套不同的快捷键。这在计算机软件世界中是不被期望的，因为在软件中，某些键盘快捷键通常执行相同的操作，无论程序是什么。

可访问性的黄金法则之一是减少最终用户的困惑。因此，我们必须认为 `accesskey` 理论虽好，但实践不佳。

## 不要被 `tabindex` 迷惑

另一个你应该避免的所谓可访问性增强是 `tabindex`。它设置当用户按下键盘上的 `Tab` 键时，链接、表单字段等元素变为活跃的顺序。不幸的是，无法仅为单个字段添加 `tabindex`。如果你为一个元素指定了 `tabindex`，则必须为每个元素都指定；否则，你将无法控制 `Tab` 键的跳转顺序。维护的艰巨任务及其对可访问性的有限影响，使这一特性成为败笔。

更好的解决方案是确保你的文档结构良好，将重要内容放在页面顶部，并在源代码中按你希望的 `Tab` 键跳转顺序指定链接和表单字段。然后，你可以使用样式表将这些元素定位到屏幕上所需的视觉位置或顺序。

## 不要依赖插件

从定义上讲，浏览器插件本身并不具备可访问性。由于它不是浏览器的一部分，绝不能假设用户拥有任何特定插件。如果最终用户没有特定的插件（例如 Adobe 的 Flash Player），则应提供替代内容，如本章前面所述。

将整个网页封装在 Flash 影片中是不明智的，尽管这在网络上很常见。影片中的内容对某些浏览器的用户以及没有插件的用户来说是不可访问的，并且对大多数搜索引擎不可见。相反，考虑在页面上使用 Flash 组件——例如在 Flash 影片容器中显示的电影预告片，或对导航栏进行特殊的创意处理。然后确保没有插件的用户能够通过其他方式访问内容。例如，你可以包含电影预告片的文字转录，或一个没有创意处理的纯文本导航栏。通过这种方式，你可以在不牺牲可访问性的前提下创建美观、智能的网页。

## 尽可能添加额外语义

一些开放标准正在兴起，用于为文档标记中的某些内容块添加额外含义。其中一种标准称为 *微格式*（microformats）。微格式是在网页中表示人、事件、标签等内容的 HTML 代码块。它们既可供人类阅读，也可供机器阅读，并且只需为某些属性分配某些值即可。

例如，`hCard` 微格式用于标记地址卡片信息，类似于常用于在计算机软件之间交换地址信息的 `vCard` 格式。以下是一个使用 `hCard` 微格式标记姓名、网站 URL 和移动电话号码的示例：

```html
<div class="vcard">
```



# [<a class="url fn" href="http://www.denodell.com/">](http://www.denodell.com/)

丹·奥德尔

</a>

<span class="tel">

<span class="type">手机</span>

<span class="value">+441234567890</span>

</span>

</div>

实际使用的标签并不重要。真正起作用的，是那些能被专门构建的软件（包括某些现有网页浏览器）识别的属性名称。利用样式表规则，可以隐藏页面上不想显示的任何内容片段，并将其作为标记中的纯语义数据保留下来。

**提示** 还有其他微格式可用于标记日历事件（`hCalendar`）、内容评论（`hReview`）等。在本书撰写期间，新的微格式也在不断被推荐。请关注最新进展，并查看更多示例，[详情请访问 http://microformats.org/。](http://microformats.org/)

## 第 1 章 ■ 奠定坚实基础

### 最佳格式化实践：CSS

作为开发者，你很可能打开过别人编写的样式表文件，并在心里嘀咕：“这让我怎么理解？”一旦你将所有布局样式与文档的标记分离，你就会发现，构建一个页面或网站所需的样式定义数量有多庞大！

正是由于布局页面所需的样式定义数量庞大，如果不遵循一些明智的 CSS 文件和样式结构指南，维护布局很快就会变得繁琐。

### 关于设计的像素级完美还原

作为开发者，我们应当始终努力将页面构建得与源创意设计尽可能像素级匹配。然而，有时为了这种像素级一致性所付出的努力，并不值得从中获得的视觉提升。

以表单字段为例。我已经记不清遇到过多少份创意设计，其中展示了带有自定义设计手柄的`<select>`下拉框（*手柄*是指下拉框边缘向下的箭头）。过去尝试对这些下拉框进行样式设计的同仁们——相信我，我也试过——都发现了浏览器之间巨大的差异。

似乎浏览器越现代化，我们对原生控件的控制权就越大。但这对于大多数人来说并无帮助。许多人仍然需要支持像 IE 6 这样的老旧浏览器——无论其表单控件看起来多么古老。

解决方案是采取“尽力而为”的方法。对于支持控件样式的浏览器，提供自定义样式的表单控件；对于无法渲染出预期效果的老旧浏览器，则需要务实对待。

所有主流浏览器都允许你设置背景色、文字颜色、字体和行高（不过高度设置在不同浏览器中可能产生不同效果，因此需要一些实验）。但并非所有浏览器都允许你指定边框样式或颜色，或自定义下拉框手柄的外观。你应提前让客户知晓这一点。否则，你将不得不相应调整设计，以在不同浏览器上实现完全一致的外观。

根据经验以及充分的常识，我们知道大多数终端用户只在机器上运行一个浏览器。此外，大多数用户并不会仔细审视设计元素。通常，他们不会发现某个`<select>`框的边框与页面上其他表单字段不匹配。终端用户主要关心的是，能否快速从你的页面获取所需信息。

以下是几条经验法则，用于判断在使用相同 CSS 时，跨浏览器差异应在何处划定界限：

- 如果为某种设计效果花费的开发时间与视觉提升不成比例，你可以舍弃该页面的某些设计元素。
- 如果未来为支持该布局而对代码库进行修改所需的维护工作过于繁重，你可以舍弃该页面的某些设计元素。


# 第一章：夯实基础

## W3C CSS 标准

早在 1996 年，W3C 就向开发者推荐了`CSS 1.0`。目前大约 99%的常用浏览器都普遍支持该标准。

`CSS 2.1`是当前的推荐标准，虽然它尚未在所有浏览器中得到普遍支持（目前仅限于最常用浏览器中的`Firefox 3`、`Safari 3`、`IE 8`、`Opera 9.5`和`Google Chrome`版本），但这 99%的浏览器中都能找到部分支持。CSS 定位（在`CSS 2.1`成为推荐标准之前也称为 CSS-P）功能已得到支持，可以实现元素在页面上的绝对定位（相对于浏览器窗口左上角）和相对定位（相对于其包含元素）。

目前正在寻求推荐的是`CSS 3`（尽管它已经处于这个阶段很长时间，因为不断有新的增补建议被提出）。迄今为止，`Safari 3`对`CSS 3`的支持最好，但`Firefox`和`Opera`的最新版本对其支持程度也在不断提高。只要你能确保在尽可能多的浏览器中充分呈现你的设计，就不必害怕使用`CSS 2.1`和`CSS 3`的样式规则。

## 样式表指南

通过遵循 CSS 最佳实践，你可以实现使网页完全可访问且代码易于维护的主要目标。本节介绍的指南将帮助你为未来可能需要的任何变更准备好样式表，同时确保满足最终用户的需求。

### 分离通用样式规则

最好在每个页面中只包含渲染该页面所需的 CSS 样式规则。包含未使用的额外样式规则会导致浏览器在识别并丢弃这些数据之前，需要下载和解析额外的数据。然而，必须牢记两点：可维护性和对浏览器工作原理的理解。

考虑一个致力于提供最新体育比分的网站，它由四个页面组成。首页向访问者介绍网站宗旨，并提供指向其他页面的链接。其他页面包括体育比分页面、新闻更新页面和常见问题解答（FAQ）页面。根据上述指南，每个页面上的样式规则应仅包含渲染该特定页面所需的规则。

现在考虑这些网页在屏幕上的外观。大多数网站都有跨页面存在的组件，例如包含网站徽标和导航的页眉部分，以及包含版权信息的页脚。此外，大多数网站设计都基于布局模板，因此每个页面都符合同样的大致尺寸，并采用设计者指定的网格布局。

试想一下，如果网站的四个页面各自对应一个样式表文件，且页眉、页脚和通用页面布局的样式在这四个文件中重复，那么维护这些样式将是一场噩梦。

需要一种更合理的方法来确保可维护性并避免样式规则重复。

所有主流网络浏览器都力求为用户提供最快、最愉悦的浏览体验，并为此采用了许多方法。其中一种方法称为*缓存*，它涉及将用于显示网页的所有 HTML、图像、样式表、JavaScript 文件和其他静态资源的副本，本地存储在最终用户的硬盘上。这意味着当用户点击浏览器的后退按钮或重新访问某个页面时，浏览器只需在硬盘上查找即可检索显示页面所需的数据。这避免了通过相对较慢的互联网连接再次下载这些资源，从而使页面显示速度比以前快得多。

在简单情况下，例如网站徽标图片，当用户访问首页时会被下载一次。只要每个页面都指向网络服务器上相同的图片文件，并且该图片在此期间未更新，网络浏览器就会从其硬盘缓存中获取该图片，而不是浪费时间重新下载。我们可以将同样的原理应用于样式表。

假设你为网站创建了一个样式表，其中仅包含通用页面布局和所有页面共有的通用组件的样式。你在每个页面中都引用这个相同的文件。当最终用户首次访问网站上的某个页面（通常是首页）时，网络浏览器会下载此文件一次；之后在后续页面访问中，浏览器将使用已下载的文件。这加快了页面的渲染速度，因为无需花费时间下载不必要的文件。这还有一个额外的好处，即将所有整个网站通用的页面样式集中在一个文件中，从而避免了页面间样式规则的重复。

你可以将特定页面的样式规则放置在各自独立的文件中，这样每个页面将引用两个外部样式表：一个网站通用，一个页面独有。

### 理解层叠与优先级

讨论样式表时，有两个重要的术语：*层叠*和*优先级*。层叠（CSS 缩写中的字母 C）用于描述样式以叠加方式应用的过程。优先级则描述了特定样式在页面上应用的实例级别。

组织样式规则最合理的方式是从编写通用样式开始，然后随着进度逐渐增加样式的优先级。通常，样式越通用，样式表文件就越高效。尽量避免过度指定样式规则。没有必要列出应用于你所设样式元素的每个标签、ID 或类——保持简洁明了。

例如，考虑一个 HTML 页面，其`<body>`标签包含以下标记：

```html
<body>
  <div id="page">
    <div id="header">
      <h1>我的页面标题</h1>
    </div>
    ...
  </div>
</body>
```

与其对标题标签应用样式时指定如下：

```css
body #page #header h1 {
}
```

不如指定更简单的样式：

```css
#header h1 {
}
```

由于你知道 HTML 中所有`id`属性值必须是唯一的，因此页面上只能有一个`id`值为`header`的元素，所以在样式规则中指定其父级元素是多余的。你也不需要指定`body`标签选择器，因为根据定义，你能够应用样式的唯一标签都在`<body>`标签内。此外，在前面的新样式规则中，你可以将`header`保留为页面的一个独立组件，不受其父元素的限制。如果你决定将`<div id="header">`标签在标记中移动，并将其放置在不同的父元素内，你知道样式规则会以相同的方式应用于它。

让我们考虑另一个例子。假设你想要两个文本段落以相同的字体显示，仅在大小和颜色上有所不同。以下是 HTML：

```html
<body>
  <div id="page">
    <p>那只敏捷的棕色狐狸跳过了懒狗。</p>
    <div class="alternative">
      <p>五个拳击巫师快速跳跃。</p>
    </div>
  </div>
</body>
```

现在来看样式规则：

```css
#page p {
  font-family: Verdana, Arial, Helvetica, sans-serif;
  font-size: 1.3em;
  color: #000;
}

#page div.alternative p {
  color: #f00;
  font-size: 1em;
}
```

最通用的样式规则（即前面代码中两个规则中的前者）中描述的样式将应用于`<div id="page">`标签内的所有段落标签。而后一个样式规则则应用于`<div class="alternative">`标签内更具体的段落标签。

这种叠加效应就是我们所说的*层叠*。



## 同样值得关注的 `!important` 关键字

同样值得关注的是 `!important` 关键字。你可以将其添加至任意样式的末尾，强制该规则在更具体的层面上优先于其他所有规则。你可以在前面的示例中添加这个关键字，如下所示：

```css
#page p {
  font-family: Verdana, Arial, Helvetica, sans-serif;
  font-size: 1.3em;
  color: #000 !important;
}

#page div.alternative p {
  color: #f00;
  font-size: 1em;
}
```

由于更通用样式的颜色已被标记为 `!important`，其样式将优先于该样式更具体的实例。在此例中，颜色 `#000` 会应用于示例页面中的所有段落文本。

在许多情况下，使用 `!important` 关键字来强制执行错误的优先级是不恰当的，这通常是样式表结构设计不佳的迹象。日后需要返回样式表文件找出为什么指定样式未能生效，既浪费时间又令人头疼。如果你发现需要频繁使用 `!important` 关键字，请考虑重构你的样式，以确保正确的规则能应用于目标元素。在某些情况下，这可能意味着需要在页面上添加一点额外标记，以确保样式能够以正确的方式应用。但这总比拥有一个结构糟糕、样式规则混乱的样式表要好。

## 考虑打印机

在构建网站样式表时，大多数开发者（虽然很少是故意的）会忽略打印机。当用户点击浏览器工具栏上的打印按钮时，了解哪些内容会被打印、哪些不会是很重要的。有三点你需要考虑：

-   **宽幅内容**：宽度超过打印页面宽度的内容通常会被截断——根本不会打印出来。有些浏览器允许按比例缩放内容以适应打印页面，但这可能导致文本难以阅读，具体取决于你网站布局的宽度。
-   **背景图像和颜色**：由于你只应将与该页面内容直接相关的图形作为前景图像包含进来，所有其他图像（例如标志）都应该作为背景图像。在很多情况下，页面上的所有图像实际上都是背景图像，通过外部 CSS 样式表文件指定。大多数浏览器不会打印这些背景图像和颜色。这是浏览器厂商为节省墨水、只打印必要内容（即页面文本内容）所采取的明智举措。如前所述，在大多数情况下，用户打印网页是为了阅读其主要正文内容——无论是火车时刻表、书评还是银行对账单。很少有网站访问者希望打印出的页面与屏幕显示完全一致。对于那些希望如此的人，通常可以在浏览器的隐藏首选项设置中启用打印背景图像和颜色，但这些选项默认很少是开启的。
-   **文本颜色**：大多数办公室环境中的用户只能使用激光打印机，通常只能打印黑白内容。大多数家庭用户拥有能够进行全彩、照片级打印的喷墨打印机。考虑到最低共同标准，如果你有黑白打印机，请用它测试打印你的页面；或者选择只用黑色墨水在喷墨打印机上打印。当考虑背景图像时，文本颜色也会发挥作用。假设你的网页在深色背景上使用白色文本。由于背景颜色不会打印，你将得到打印在洁白纸张上的白色文本。当然，打印机没有白色墨水可打印，因此用户实际上会得到一张空白页！

打印出来的网页通常会显示大片的空白区域，那里曾经是背景图像和颜色，有时还会有些内容被切掉，一些浅色文本完全丢失。这几乎不可能是用户希望在打印页面上看到的结果。

你不想成为用户沮丧的源头，因此应该通过指定一个仅供打印机读取的样式表来规避这些限制，使用以下标记：

```html
<link rel="stylesheet" href="master-print.css" media="print" />
```

在这个仅用于打印的样式表中，你需要最小化打印页面上可能出现的空白区域，移除不必要的组件，并确保最终打印的文章中没有内容被截断或隐藏。例如，你可以通过应用以下样式规则来移除导航：

```css
#navigation {
  display: none;
}
```

你可能需要指定一个字体颜色，例如黑色，以覆盖页面上所有其他的文本颜色。这可以通过以下样式规则实现：

```css
* {
  color: #000 !important;
}
```

这会将黑色（十六进制表示为 `#000000`，简写为 `#000`）应用于页面上的所有元素（`*` 通配符用于定位页面上所有元素）。

请注意样式规则末尾使用的 `!important` 关键字。正如我前面提到的，这是一个危险的关键字，因为它强制该样式比文档中的任何其他样式都更重要。然而，它在打印机样式表中非常有用，因为它允许你覆盖由主样式表指定的页面上任何元素的字体颜色，而无需考虑其特异性级别。

## 格式化你的样式规则

以下示例展示了一种久经考验、可读性良好的样式规则布局：

```css
.module-heading,
.module-subheading {
  background: #333;
  color: #f00;
  float: left; /* 内联注释 */
}
```

在这个样式规则中，使用了多个样式选择器，将该样式规则应用于具有两个不同 CSS 类的页面元素。样式选择器被放在单独的行上，而不是放在同一行（这可能会造成混淆）。样式规则在最后一个 CSS 类名所在行的末尾开始，并在所有样式规则之后另起一行结束。样式规则本身相对于样式定义缩进一个制表位。在每个样式属性名称后的冒号与其对应值之间有一个空格。

每个样式属性独占一行，并且每行以分号结束。

如果需要为某个样式规则提供注释以协助未来的开发或维护，此注释应紧跟在规则本身所在行的分号之后。

为了保持样式规则的一致性，你可以选择按样式属性名称的字母顺序排序，或者根据样式属性的类型（文本、颜色、布局等）排序，或者根据适合你的应用的任何其它分组方式排序。

## 为单个页面元素应用多个类名

正如本章前面提到的，在 HTML 标记中指定的 CSS 类名应该描述元素内容所代表的信息，而不是该内容应如何显示。

你可能希望对同一元素应用多个类名，以避免重复你的样式规则。在你的标记中，这可以通过简单地用空格字符分隔每个 CSS 类来实现，如下例所示：

```html
<div class="article main-article">
  <p>Hello, world.</p>
</div>
```

为 `article` 和 `main-article` 类编写的样式规则将从左到右应用于 `<div>` 标签，因此 `main-article` 样式规则中指定的样式将优先于 `article` 样式规则中的样式。

如果你需要为以这种方式包含多个类的元素应用特殊样式，以下 CSS 选择器语法将允许你做到这一点：

```css
div.article.main-article p {
  color: #0f0;
}
```

此样式规则应用于其父标签为 `<div class="article main-article">` 的 `<p>` 标签。请注意 CSS 类名之间没有空格字符。

## 重置浏览器的默认样式



默认情况下，网页浏览器会自带一组默认的样式规则，用于对未设置样式的页面进行渲染。这包括字体、字号、行高、颜色，以及在不同元素和标签上程度各异的填充（padding）和外边距（margin）。

为了让自己的样式有一个公平的起点，我建议你重置浏览器的默认样式。这样可以将对每个元素的精确控制权移交给自己的样式表，从而在不同浏览器之间提供更高的一致性。

在最简单的情况下，以下样式规则会将所有页面元素的外边距和填充都归零，以便你在样式规则中为每个需要指定间距的元素单独设置自己的外边距和填充间距：

```
* {
  margin: 0;
  padding: 0;
}
```

## 掌握简写样式规则

某些样式可以合并或缩短，在可能的情况下，你应该使用这些版本来减小 CSS 文件的体积，并减少从 Web 服务器到浏览器通过网络传输的数据量。

举一个简单的例子，元素上的某些外边距和填充值可以使用冗长的方式指定：

```
p {
  margin-top: 5px;
  margin-right: 7px;
  margin-bottom: 5px;
  margin-left: 7px;
  padding-top: 6px;
  padding-right: 3px;
  padding-bottom: 6px;
  padding-left: 3px;
}
```

或者使用简写方式：

```
p {
  margin: 5px 7px 5px 7px;
  padding: 6px 3px 6px 3px;
}
```

请注意，`margin`、`padding` 和 `border` 的简写值顺序始终如下：

- 上
- 右
- 下
- 左

当 `margin-top` 和 `margin-bottom` 的值相同，并且 `margin-left` 和 `margin-right` 的值也相同时，可以应用进一步的简写形式，如下所示：

```
p {
  margin: 5px 7px; /* 上下 5px，左右 7px */
  padding: 6px 3px;
}
```

其他样式——例如 `font`、`color` 和 `background`——也有各自的简写形式。第四章（专注于提升 CSS 文件性能）提供了关于这些样式简写形式的更多细节。

## 样式无障碍指南

到目前为止，你应该知道，作为 Web 开发者，我们主要关注点之一是无障碍性——确保我们的内容对所有人都可用，无论他们使用何种浏览器、设备或输入方式。主要重点是确保语义化标记，正如本章前面所讨论的，但你还必须确保样式表支持这一原则。不同尺寸和分辨率显示器的用户应该能够清晰地查看你的页面内容。

### 向支持 CSS 的浏览器隐藏内容

如果你不希望某些标记中的标签内容显示在屏幕上，可以使用样式表在视觉上隐藏这些内容。回想一下本章前面的电影评论网站示例，当时你希望确保文本出现在 HTML 中，这样当内容被朗读出来或在没有应用样式的情况下被阅读时，用户能理解评论者对那部电影的评分。现在是时候应用你的 CSS 了。你希望显示一个代表五星好评中四颗星的图片，而不是显示那段文本。

以这种方式隐藏文本应使用 `text-indent` 样式属性，选择能将文本定位到浏览器视口左边缘之外的值，使其不再可见，如下所示：

```
div#hide-me {
  text-indent: -9999px;
}
```

使用任何其他样式属性来隐藏文本都会产生不幸的副作用，即通过 Freedom Scientific 公司（http://www.freedomscientific.com/）制造的流行 JAWS 屏幕阅读器软件，该文本将变得无法阅读。

### 移动内容块以保持正确的标记源码顺序

在本章前面，你了解到标记中内容块的顺序应该是：当页面被朗读时，最相关的页面内容排在前面，次要内容（包括导航和版权信息）排在最后。当然，这种顺序可能不符合你网站的视觉外观，在视觉上你很可能希望导航链接出现在主体内容上方。

如果你的标记中有两个块级元素按顺序排列，而你更希望后一个内容先出现在浏览器中，你可以使用样式属性 `float` 来重新排列这两个内容块。请看以下 HTML 代码片段：

```
<div id="body">
  ...
</div>

<div id="navigation">
  ...
</div>
```

默认情况下，`<div id="body">` 标签会出现在 `<div id="navigation">` 标签之前，但你可以使用 `float` 样式属性反转此顺序，如下所示：

```
#body {
  float: right;
}

#navigation {
  float: left;
}
```

你可能还需要考虑使用绝对定位和相对定位的组合，在页面内重新定位内容块，以实现你需要的布局。

### 使用相对字体大小

有些网站访问者——可能是视力受损者，或者只是将屏幕分辨率设置得较高——可能会调整浏览器中的基础字体大小，以便以最佳方式查看网站。所有主流浏览器都具备此功能。作为开发者，除了考虑网页的设计标准，我们还必须考虑最终用户的需求。

为了应对字体大小调整的可能性，你应该在样式表中使用相对单位。这样，当浏览器的基础字体大小改变时，页面文本也会按比例改变。`em` 单位就是这样一个相对单位，`%`（百分比）也是。你绝对不**应该**在样式表中使用 `px`（像素）或 `pt`（点）值来指定字体大小，因为这些值不会根据最终用户的需求进行缩放。



为了在使用相对字体大小单位时更简便地计算字号，可以尝试将 `<body>` 标签元素的默认字体大小设置为 `62.5%`。在默认浏览器设置下，此比例会使 `1em` 在视觉上等同于 `10px`。这样一来，每个 `0.1em` 的增量就对应着 `1px` 的视觉增加，因此 `1.1em` 视觉上等于 `11px`，`1.2em` 相当于 `12px`。在处理那些通常以像素为单位计量字体大小的创意设计时，这个技巧极为实用。以下是一些示例：

```
body {
  font-size: 62.5%; /* 重置字体大小，使 1em 在视觉上等同于 10px */
}

ul li {
  font-size: 1.1em; /* 视觉上等同于 11px */
}

h2 {
  font-size: 1.5em; /* 视觉上等同于 15px */
}
```

## 注释块

为了便于维护并帮助其他开发者理解你的样式表，明智的做法是将逻辑相关的样式规则分组并组织在样式表文件中。在每组规则前添加一个注释，描述这组样式的用途，并使用一致的符号格式，例如：

```
/* ---------------------------------------------------------------- --
   表单样式
   根据商定设计，用于显示表单控件的样式组
*/
```

应仅在必要时添加内联注释，置于样式规则本身旁边以澄清特定规则。例如，当某个样式规则是为了处理特定浏览器中的边缘情况而添加时，有必要注明这一点，这样未来的开发者就不会认为该规则多余，并在不了解其初衷的情况下将其删除。

在每个样式表文件的最顶部，可以考虑包含一个开头的注释部分，详细说明该文件的作者、文件中样式规则的目的，并按照它们出现的顺序列出文件中的所有逻辑组，使用一致的格式。以下是一个描述整个样式表文件及其用途的注释块格式示例：

```
/* ---------------------------------------------------------------- --
   文件名 common.css
   作者 Den Odell me@denodell.com
   描述 网站基本页面布局和默认样式
   内容
   - 重置样式
   - 页面分栏布局
   - 表单控件样式
   调色板
   #777 中灰色
   #aaa 浅灰色
   #a3d60a 网站通用绿色
*/
```

包含这样一个注释块可以让开发者一目了然地查看文件是否包含他们正在寻找的代码。对于你的通用网站样式表来说，列出网站中使用的一些关键颜色可能是个明智之举。这样开发者就能轻松找到这些颜色，并在需要时复制粘贴这些值。

## 浏览器兼容性解决方案

如果需要包含额外的样式来定位特定版本的 IE，应该使用本章前面描述的条件注释技术，为这些样式包含一个单独的样式表文件。

**注意** 请避免使用那些设置异常样式值，或使用反斜杠、注释和其他奇怪字符组合来混淆和迷惑某些浏览器的 hack。如果无法避免使用某个 hack，务必添加清晰的注释，说明为什么选择保留它以及它的用途，以警告未来可能查看该样式表文件的其他开发者。

在 IE 6 或更早版本中使用 PNG-24 图像时，图像文件的透明部分会显示为灰色/浅蓝色，而不是透明。不幸的是，微软直到 IE 7 版本才引入对此文件格式透明度的支持。不过，你可以使用一个变通方案，使简单的 PNG-24 图像能够在页面上作为背景或前景图像显示。

假设你在主样式表中定义了以下样式规则：

```
#header {
  background: url(my-image.png) no-repeat;
}
```

在使用条件注释引用的 IE 6 专用样式表文件中，可以包含类似如下的样式规则：

```
#header {
  background: transparent none;
  filter: progid:DXImageTransform.Microsoft.AlphaImageLoader(src='my-image.png', sizingMethod='scale');
}
```

这条 IE 6 专用的样式规则会隐藏原始样式表中指定的背景图像，转而使用微软特定的 DirectX 滤镜来引用同一个图像文件。该滤镜能够正确显示图像的透明部分，并将其放置在原背景图像所在的位置。然而，这项技术存在若干限制，包括不支持背景定位和平铺，因此使用时需谨慎。

## 本地化考量

网站面向未来设计的最重要的一个方面，就是要考虑到网站可能需要以其他语言或针对特定国家/地区的版本呈现。不仅网站的文字内容会有所不同，而且样式表的部分内容也极有可能需要作出一些调整。例如，你可能需要替换包含某种语言内嵌文本的图像文件，或者调整其他特定于地区的样式，甚至可能意味着需要为某些文字改变文本方向。

为了确保这种面向未来的设计，从一开始就应该在主要样式表文件中包含所有与地区无关的样式，并包含一个单独的样式表文件来提供特定于区域设置的样式规则，这些规则会按区域覆盖主样式表。这样一来，添加对新语言和区域设置的支持就变得很容易，因为这只是一个从现有区域特定文件创建新样式表文件，并替换其中样式以适应新区域和/或语言的问题。

## 组织文件夹、文件和资源

一个简单但可扩展的文件夹结构为将来添加内容和资源提供了良好的基础，而不会给开发者的维护工作带来更多负担。以下部分提供了一些组织文件夹、文件和资源的指南。

#### 可读的 URL

应创建与项目站点地图相对应的文件夹，这样 HTML 页面和服务器端脚本存储在文件夹中，其 URL 就会变得合理、可读且有意义。通常，每个文件夹中的默认页面或索引页面可以在 Web 服务器配置中指定，这样仅通过文件夹名称即可请求 URL，并默认加载该索引文件。

还应该尝试以类似的方式用文件夹反映站点地图的层次结构，这样 URL 本身也呈现出层次结构。某些搜索引擎可能会将 URL 中的文本以及页面内容作为搜索条件。

例如，这个 URL：

`http://www.mywebsite.com/news/`

比这个更简洁、更易读且更易于记忆：

`http://www.mywebsite.com/news.php`

同样，URL 的各个部分应反映站点地图和合理的层次结构，如下例所示：

`http://www.mywebsite.com/music/rock/`

所有基于文本的文件都应使用`UTF-8`编码类型，因为这允许在文件中直接使用扩展字符和非英文字符集，无需特殊的控制字符和`ASCII`代码。

### 编码风格指南

作为 Web 开发者，你可以通过以一致的方式组织和构建你的 JavaScript 代码，编写代码来解决你的问题或达成目标，而不使代码过度复杂化，从而简化日常编码体验。遵循一些指导方针，可以使你的代码更干净、更清晰、更易于管理、更易于理解、文档更完善，并且更易于阅读。

#### 使用一致的格式

正如你在上一章中看到的，可读代码的标志——无论是 HTML、CSS 还是 JavaScript——都是统一的格式。例如，JavaScript 函数体内的内容应该相对于函数名和花括号缩进一个制表符空间。每条语句应以分号结束，并且每条语句应独占一行，以确保良好的可读性，如下例所示：

```javascript
function myFunction() {
    alert("Hello, world");
    return true;
}
```

类似地，逻辑代码块和循环体内的内容也应该缩进。一条经验法则是，一对花括号（`{` 和 `}`）内的内容应相对于这些花括号缩进，如下例所示：

```javascript
if (x == y) {
    alert("We have a match!");
} else {
    alert("We have a problem!");
}
```

然而，在能使代码更易于阅读的地方，你可能希望使用额外的缩进，如下面代码中的 `case` 语句：

```javascript
switch (prompt("What is your favorite fruit?", "banana")) {
    case "banana":
        alert("Well done. Bananas are full of potassium.");
        break;
    case "mango":
        alert("Exotic and tasty!");
        break;
    default:
        alert("That's not to my taste, but keep it up to get your 5-a-day.");
        break;
}
```

### 使用花括号和圆括号

花括号（`{}`）和圆括号（`()`）在 JavaScript 中广泛用于划分代码块，并减少长语句中的混乱。应尽可能使用它们，以最大限度地减少潜在缺陷并提高可读性，这两者都将有助于未来的代码维护。

下面的例子展示了一段移除花括号和圆括号以缩短代码的 JavaScript 例程。

```javascript
var result = 0;
if (confirm("Would you like to do some math?"))
    result = 10 / 2 * 100 % 30;
alert("OK, the result is: " + result);
```

这在语言语法上是完全有效的，但它使得逻辑稍微难以理解。

下面的形式则不那么令人困惑，因此是一种更稳定、更易读、更易于维护的代码例程。

```javascript
var result = 0;
if (confirm("Would you like to do some math?")) {
    result = ((10 / 2) * 100) % 30;
}
alert("OK, the result is: " + result);
```

注意，使用这种格式，你可以确定 `alert` 语句何时执行。并且你可以看到，当使用圆括号将操作分组时，数学计算例程变得多么易于理解。

### 用大小写增加含义

几条关于变量和函数名大小写的简单规则，能让你一眼就看出它们在代码中的用途。以下是几条你应该在自己的代码中遵循的常见大小写准则：

-   大多数变量和函数名以小写字母开头。
-   对象构造函数名以大写字母开头。（本章后面的“对象、类和构造函数”部分会讨论对象构造函数。）
-   使用*驼峰命名法*，其中每个新单词以大写字母开头，所有其他字符为小写，以标记新单词的开始。
-   使用全大写字符表示常量——即在代码生命周期内不应改变的值。

```javascript
// 对象构造函数 – 含义详见本章后面
var Calendar = function() {
    // 常量使用大写
    var DAYS_IN_ONE_WEEK = 7;

    // 变量或函数名以小写字符开头
    var count;
    function add() {
    }

    // 变量和函数名中的新单词使用驼峰命名
    var currentDate;
    function doSomethingWithCurrentDate() {
    }
}
```

### 使用描述性变量和函数名

为变量和函数选择恰当的名称是构建易于理解的代码库的基础之一。命名变量和函数时，要让它们体现其用途和目的。如果较长的名称能传达信息，不要害怕使用它们。

想象一下，你只看到代码中的变量名和函数名，而没有任何逻辑或值，你能一眼看出它们的用途吗？如果不能，那就是时候开始重命名了。

以下是一些描述性变量和函数名的例子：

```javascript
var currentDate;
function setCurrentDate() {
}

var userName;
function updateUserName() {
}
```

你还应避免使用所谓的*魔术数字*，即计算中用到的、看似凭空出现的数字。以下例子展示了魔术数字的使用：



`var daysInAYear = 52 * 7;` // 稍加思考，你就能算出来

`var seatsOnThePlane = 25 * 6;` // 但这又意味着什么呢？

这些数字从何而来，它们代表什么含义？你应该力求消除代码中所有的疑惑。将含义明确表达出来，这样开发者就不需要逐行审视代码才能理解。下面的版本为前一个示例中使用的数字常量添加了定义。

```
var WEEKS_IN_A_YEAR = 52;
var DAYS_IN_A_WEEK = 7;
var daysInAYear = WEEKS_IN_A_YEAR * DAYS_IN_A_WEEK; // 忽略闰年

var SEAT_ROWS_ON_PLANE = 25;
var SEATS_PER_ROW = 6;
var seatsOnThePlane = SEAT_ROWS_ON_PLANE * SEATS_PER_ROW; // 啊，清晰多了！
```

注意到一切突然变得多么清晰了吗？

#### 保持函数块简短

一个函数应该只做一件事，并且把它做好。尽量避免将不相关的代码合并到一个函数中，如下例所示：

```
function feedbackOnUsersFavoriteFruit() {
    var favoriteFruit = prompt("What is your favorite fruit?", "None");
    var score = 0;
    switch (favoriteFruit.toLowerCase()) {
        case "banana":
            score = 6;
            break;
        case "apple":
            score = 4;
            break;
        default:
            break;
    }
    if (score > 5) {
        alert("You picked one of my favorites too!");
    } else if (score > 0) {
        alert("Credit for choosing a fruit, at least!");
    } else {
        alert("Not sure about your choice of fruit!");
    }
}
```

每个函数越简单，测试和调试就越容易。如果你的函数需要连续执行多个逻辑上不同的操作，请将一个大函数拆分成多个小函数，分别执行每个任务，如下例所示：

```
function getFavoriteFruit() {
    return prompt("What is your favorite fruit?", "None");
}

function getFruitScore(fruit) {
    var score = 0;
    switch (favoriteFruit.toLowerCase()) {
        case "banana":
            score = 6;
            break;
        case "apple":
            score = 4;
            break;
        default:
            break;
    }
    return score;
}

function getMessageByScore(score) {
    var message = "";
    if (score > 5) {
        message = "You picked one of my favorites too!";
    } else if (score > 0) {
        message = "Credit for choosing a fruit, at least!";
    } else {
        message = "Not sure about your choice of fruit!";
    }
    return message;
}

function feedbackOnUsersFavoriteFruit() { // 保留原函数名
    var favoriteFruit = getFavoriteFruit();
    var score = getFruitScore(favoriteFruit);
    alert(getMessageByScore(score));
}
```

尽可能让每个函数只执行一个逻辑动作，根据需要接收输入并产生输出。

## 使用 ScriptDoc 格式的注释作为文档

与其在代码中嵌入大量内联注释，不如确保变量和函数命名准确，并且代码块简短且不言自明。

在代码中布满大量内联注释，反而会降低它们被实际阅读的可能性。

你应该为你编写的每个函数提供文档，方法是在函数之前添加一个注释块，定义函数的功能、预期的输入参数、产生的输出类型，以及一些使用示例。这类注释块具有以下优势：

-   确保所有开发者都理解一个函数应该（和不应该）做什么。
-   帮助你判断一个函数何时执行了过多操作，正如上一节所讨论的那样。如果函数的描述特别复杂，就表明它应该被拆分成几个更小的函数。
-   通过注明函数应能接受的输入范围或类型，有助于定义你可以对该函数执行何种测试。
-   在你的代码中提供视觉分隔。

你应该使用开放的 ScriptDoc 格式（`http://www.scriptdoc.org/`）来记录你的代码。这种格式的设计使其可以跨编程语言使用。由于格式和结构是预定义的，你可以使用诸如 `Aptana` 之类的软件。




[Studio](http://www.aptana.com/) 能够根据代码中特殊格式的注释块，自动生成可读性强的文档。

以下示例展示了如何记录整个 JavaScript 文件的功能。该注释应作为 JavaScript 文件中的第一项内容，以便开发者理解文件中包含的函数的目的。

```
/**
 * @projectDescription 本文件包含执行日期对象操作的代码
 *
 * @author Den Odell me@denodell.com
 * @version 1.0
 */
```

以下示例展示了如何采用 ScriptDoc 格式记录文件中的函数：

```
/**

 *
 * 示例：
 * square(2.5); => 6
 * square(2); => 4
 *
 * @param {Float} number 需要被平方的数字
 * @return {Integer} 返回输入值平方后的四舍五入结果

function square(number) {
    return Math.round(number * number);
}
```

我鼓励你熟悉 ScriptDoc 网站上的规范说明，以及用于正确描述和记录函数的具体选项。使用该规范将极大提升代码的可理解性，并能生成有用的文档，供将来可能要与你的代码协作的其他开发者参考。

#### 用 TODO 标记剩余任务

编码时养成一个有用的习惯：使用包含 `TODO` 一词的注释来标记代码中未完成的部分，示例如下：

这使你之后可以在代码库中搜索该关键词，快速定位任何需要完成的部分。

## 专业级 JavaScript 编程

现在我们已经回顾了 JavaScript 文件中关于格式、文档和清晰度的一些基本准则，接下来让我们了解一些 JavaScript 编码原则。专业人士遵循这些实践，使他们的 JavaScript 代码健壮、可扩展，并建立在对要解决问题的扎实理解之上。

#### 避免解决不存在的问题

编写 JavaScript 代码时，只编写解决当前问题所需的代码。例如，假设你想编写一段 JavaScript 代码，允许网站用户登录个人资料页面，并在用户提供有效凭证时动态刷新页面部分内容。要解决这个问题，你不需要编写能在网站任何页面刷新任何内容的代码——至少在当前尚未成为需求或成为新问题解决方案之前不需要。遵循这一准则，你的代码可以用更短的时间完成，因为你只构建完成任务所需的确切代码，而不是试图构建通常在实践中可靠性较低的通用、过度复杂的代码。之后，当你需要解决不同的问题，并认为已有代码可以改写来完成任务时，那才是重写它的时机。

#### 使用文档对象模型

作为 JavaScript 语言的扩展，W3C 推荐了文档对象模型（DOM），该模型标准化了 Web 开发者与渲染页面中 HTML 元素交互的方式。该语言中增加了通过元素的 `id` 属性或标签名称定位页面元素的方法，支持动态操作元素的属性、CSS 样式属性，甚至移除或添加整个元素。DOM 推荐标准将 HTML 页面中的所有内容定义为通用名称 `node`。页面中可以存在五种类型的节点，如下所示，它们都是页面组件的 JavaScript 表示形式：

- **文档节点**：代表 HTML 页面的最顶层节点，实际上对应于 `<html>` 元素。


# 节点类型与 DOM 操作

## 节点类型

- **元素节点**（`Element node`）：页面上的每个 HTML 标签都表示为一个元素节点。
- **属性节点**（`Attribute node`）：标签的每个属性，例如`<a>`标签相关的`href`属性，都表示为一个属性节点。每个属性始终与一个元素节点关联。
- **文本节点**（`Text node`）：开闭标签之间的文本，例如`<p>`和`</p>`之间的文本，表示为一个文本节点。每个文本节点与一个元素节点关联。
- **注释节点**（`Comment node`）：HTML 注释表示为一个注释节点。

每个元素节点内部可能包含其他元素节点，称为**子节点**。根据 XHTML 的结构，`<html>`元素有两个子节点：`<head>`和`<body>`。

以下示例展示了带有两个子节点的 HTML `<body>`元素：

```html
<body>
<h1>My Page Title</h1>
<img id="chart-image" src="my-chart.jpg" alt="My chart" />
</body>
```

第一个子节点（表示`<h1>`标签）下有一个文本节点，包含文本“My Page Title”。请注意，元素内的文本不被视为元素本身的一部分，而是它的子节点。

`<body>`标签的第二个子节点是另一个元素节点（表示`<img>`标签），包含两个属性节点（分别表示`src`和`alt`中存储的值）。从`<h1>`标签的角度来看，`<body>`标签被称为它的**父节点**，而`<img>`标签被称为它的**兄弟节点**，因为它们在文档层级中处于同一级别。

## 查找元素节点

可以通过两种方法直接在文档中查找元素节点，以下示例演示了这两种方法：

```javascript
// 返回表示 id 属性为 chart-image 的标签的元素节点
var img = document.getElementById("chart-image");

// 返回元素节点数组，所有节点均为 <body> 标签
var bodyTag = document.getElementByTagName("body");

// 返回第一个 <body> 标签内 id 属性为 chart-image 的元素
var img = bodyTags[0].getElementById("chart-image");
```

> **注意**：某些浏览器提供了两种新的元素定位方法，但尚未普及。这些方法是`querySelectorAll()`（基于 CSS 3 选择器定位元素节点）和`getElementsByClassName()`（基于 CSS 类名定位元素节点）。

## 操作元素与内容

一旦找到元素，你很可能想对其执行某些操作。可能是更改其文本或任何属性；也可能是完全从页面中移除该元素，或者在其前后或内部添加新元素。DOM 提供了处理所有这些情况的方法。

### 动态修改 CSS 属性

读取和修改 CSS 样式属性就像在找到的元素上使用`style`对象一样简单。以下演示了如何读取`color` CSS 属性并修改`margin-left` CSS 属性：

```javascript
var navigationEleemnt = document.getElementById("navigation");

if (navigationElement.style.color == "black") {
    navigationElement.style.marginLeft = "50px";
}
```

> **注意**：在 CSS 样式属性名中使用连字符分隔单词的名称，在 JavaScript 中改用驼峰命名法引用。

### 操作元素及其内容

通过 DOM 设置元素内容的最简单（并且在许多浏览器中最快速）的方法是使用元素的`innerHTML`属性。该属性将元素内部所有内容的 HTML 代码表示为一个字符串，可以读取或设置为你想要的任何内容。以下是如何读取和设置元素`innerHTML`值的示例：

```javascript
var pTag = document.getElementsByTagName("p")[0]; // 页面上的第一个 <p> 标签
alert(pTag.innerHTML); // 输出标签当前的 HTML 字符串内容

pTag.innerHTML = "<b>New HTML contents!</b>"; // 重写标签的 HTML

alert(pTag.innerHTML); // 输出 "<b>New HTML contents!</b>"，页面上标签的内容现在以粗体显示
```



尽管这种方法快速简便，但存在引入错误的风险，例如因设置未正确闭合的 HTML 而导致渲染错误。操作元素最稳健的方式是使用内置的 DOM 节点操作方法，这些方法会根据页面当前的 `DOCTYPE`，始终以正确的格式将 HTML 代码添加到页面中。

以下示例演示了如何使用 `createElement()` 方法创建新的元素节点。我们可以通过 `appendChild()` 方法将这个新元素插入到页面中，该方法会创建一个新的水平线元素，并将其附加到 `<body>` 标签所包含的节点列表末尾。它将在 HTML 页面的底部显示出来。

```
var horizontalRule = document.createElement("hr"); // 目前仅存在于内存中
var bodyTag = document.getElementsByTagName("body")[0];
bodyTag.appendChild(horizontalRule); // 使 <hr> 标签显示在页面上
```

相反地，从页面中移除元素只需在要移除元素的父元素上调用 `removeChild()` 方法，如下所示：

```
var horizontalRule = document.getElementsByTagName("hr")[0];
// 上述 <hr> 标签必须是 <body> 标签的直接子元素
var bodyTag = document.getElementsByTagName("body")[0];
bodyTag.removeChild(horizontalRule); // 该元素从页面消失
```

我仅向你展示了少数几个 DOM 方法。我建议你熟悉 DOM。它是通过 JavaScript 访问页面内容的统一方式。Mozilla 维护了一个实用的在线资源，其中包含大量示例和说明，网址为 [`developer.mozilla.org/en/Gecko_DOM_Reference`](https://developer.mozilla.org/en/Gecko_DOM_Reference)。

## 不要混淆 JavaScript 和 HTML

正如我在前一章中指出的，你绝不应该将 JavaScript 代码内联到 HTML 代码中。如果你发现自己正在 HTML 中使用像 `onclick`、`onmouseover` 这样的属性，请立即停止！使用可用的 DOM 方法来定位元素，并将你的代码应用于这些元素。这可以将你的行为代码与内容分离开来，并且使你能够在不严重影响另一方的情况下对各自进行修改。

某些浏览器不支持 JavaScript。一些用户倾向于关闭它。一些用户的工作环境默认禁用了 JavaScript。这些用户不应该需要下载他们所访问页面的所有 JavaScript 代码，因为这会使页面体积增大，却对他们没有任何益处。

你应该致力于将所有 JavaScript 代码放在外部文件中，并通过 HTML 代码中的 `<script>` 标签进行引用，这样不使用 JavaScript 的用户只需下载他们需要的内容，而其他浏览器则通过引用 URL 下载该文件。这也允许浏览器在本地缓存外部文件，这样如果多个页面引用了该文件，它只需下载一次，后续每次请求都从本地副本加载。

#### 将样式与代码分离

你会发现，有时你想要通过 JavaScript 影响页面上元素的某些样式属性。也许你想显示或隐藏页面的一部分，或者当用户执行某个操作时对某些元素应用新的配色方案。请尽可能将样式规则分离到 CSS 中，然后使用 DOM 来切换你想要更改的元素上正在使用的 CSS 类名；浏览器随后会为你处理样式属性的更改。通过这种方式，你在显示样式和行为代码之间建立了更松散的联系。

通过让 CSS 文件负责设计和布局，JavaScript 负责交互和行为，你就知道应该去哪个文件中查找或进行修改。你还可以使用 CSS 创建全新的设计，而无需修改 HTML 或 JavaScript 代码。



# 动态属性修改的例外情况

当您需要动态修改某些无法预先知道具体数值的属性时，此规则存在例外情况，例如根据鼠标从初始位置移动的距离来改变组件的宽度。在这种情况下，可编码的数值太多，无法在 CSS 中穷尽所有选项。因此，应仅通过 JavaScript 修改 `width` 属性，而同一元素的其他所有样式则应在 CSS 文件中定义。

#### 链式函数调用

*链式调用*指在其他方法的结果上执行方法，从而节省冗余代码行。以下示例通过依次执行多个方法（每个方法都作用于前一个调用的结果）来演示这一点。最终返回的值是链中最后一个方法的结果。

```
// 获取 <body> 标签内 id 为 "horizontal-rule" 的元素的宽度
var hrTagWidth = document.getElementsByTagName("body")[0]
    .getElementById("horizontal-rule").style.width;
```

#### 编写健壮代码

编写代码时，某些方法调用可能并不总能返回代码其余部分所依赖的值。如果出现这种情况，就会导致 JavaScript 错误，代码也会停止执行。专业的 JavaScript 开发人员会在对方法的返回值执行进一步操作之前，检查这些值是否为所需格式。

以下示例演示了这一实践，其中使用 DOM 查找了一个元素。

```
var horizontalRule = document.getElementById("horizontal-rule");

if (horizontalRule) { // 如果元素存在，则...
    horizontalRule.parentNode.removeChild(horizontalRule); // ...移除该节点
}
```

此代码检查元素是否实际存在——即其值不为 `null` 或 `undefined`。如果对一个稍后从 HTML 中移除的元素执行操作，则会发生错误，代码执行将停止。

## 优雅处理致命异常错误

JavaScript 语言（与许多其他语言一样）的一个有用特性是，能够将您有理由怀疑可能引发异常（即强制代码停止执行的那类错误）的语句组包装在 `try/catch` 代码块中，从而以优雅的方式处理错误。`try` 部分中的代码会执行；`catch` 部分中的代码仅在 `try` 部分代码导致错误时执行。如果没有发生错误，则忽略 `catch` 部分中的代码。以下是一个 `try/catch` 结构的示例，该结构在代码执行出错时向用户发出警报，而不会因此异常导致 JavaScript 代码执行停止。

```
try {
    // 以下代码无效，通常会导致异常
    document.getElementById("horizontal-rule").propertyName.toString();
} catch (error) {
    alert("发生了一个错误。");
}
```

请注意 `catch` 块如何暴露一个变量，我将其命名为 `error`。此变量包含有关所发生错误的信息。在以下代码中，我尝试找出所发生错误的类型，以便向最终用户或开发者提供更有用的消息。

```
try {
    // varx 不是语言中的关键字，因此会抛出 SyntaxError 异常
    varx x = 0;
} catch (error) {
    // 有六种基本的异常类型，均在此描述
    if (error instanceof TypeError) {
        // 使用的变量类型不符合预期
    } else if (error instanceof SyntaxError) {
        alert(error.message); // 输出描述异常的消息
    } else if (error instanceof RangeError) {
        // 数值变量已超出其允许范围
    } else if (error instanceof EvalError) {
        // JavaScript 的 eval() 函数被错误使用
    } else if (error instanceof ReferenceError) {
        // 使用了无效的引用
    } else if (error instanceof URIError) {
        // encodeURI() 或 decodeURI() 函数被错误使用
    }
}
```

## 定义自定义异常



### 处理 JavaScript 中的自定义异常

除了捕获和处理内置的 JavaScript 异常外，你还可以定义自己的异常类型，并随时在代码中强制触发这些异常。以下示例展示了如何在特定情况下定义并抛出自定义错误。

```javascript
// 定义一种新的错误类型
var domObjectNotFoundException = new Error("DOM 对象未找到");

function getDOMObjectById(id) {
  var domObject = document.getElementById(id);

  if (!domObject) {
    // 如果 DOM 对象不存在，则抛出自定义错误类型的异常
    throw domObjectNotFoundException;
  }

  return domObject;
}

try {
  // 假设我们试图对一个不存在的元素进行操作
  getDOMObjectById("this-id-is-not-on-the-page").style.width = "100px";
} catch (error) {
  if (error instanceof domObjectNotFoundException) {
    alert(error.message); // 输出 "DOM 对象未找到！"
  } else {
    // 捕获其他类型的错误
  }
}
```

### `finally` 块

作为常见的 `try/catch` 块结构的扩展，你可以添加一个由 `finally` 关键字标识的额外代码块。`finally` 关键字允许你添加一组额外的语句来执行，无论是否发生异常，以便将相关代码组织在一起。在以下示例中，无论 DOM 对象是否被找到，都会调用最后的 `alert` 语句。

```javascript
try {
  getDOMObjectById("this-id-is-not-on-the-page").style.width = "100px";
} catch (error) {
  alert(error.message);
} finally {
  alert("就这些了，各位！");
}
```

### 编写具备本地化意识的代码

本地化是已构建好的 RIA 应用中较为常见的需求之一。想象一下，你构建了一个大型动态 Web 应用，却发现自己需要重构所有代码，才能对其中使用的文本字符串进行本地化处理。

将文本字符串分离到变量中，并将它们集中放在代码中的某个位置。这样，后续如果需要，你就可以轻松地覆盖它们的值。采用这种方法，在后续需要向 JavaScript 代码中添加特定区域文本字符串时，能为你节省宝贵的时间。

你可以考虑将这些变量移到一个单独的文件中——或许每种语言一个文件——这样 HTML 页面就能引用它所需的特定语言文件，而应用的其他部分则正常使用这些变量。这将语言选择工作转移到了 HTML 页面，这似乎是个明智的选择，因为页面内容中已经包含了语言相关的文本。

### 面向对象的 JavaScript

自诞生之初，JavaScript 编码已经取得了长足进步，如今许多前端 Web 开发者发现自己以一种与传统软件工程师并无二致的方式编写复杂代码。随着时间的推移，开发者们通过应用一些传统程序员所使用的面向对象原则，力求减少错误、提高代码复用性并简化代码理解。

通过将相关代码分组到可复用的组件（即*对象*）中，每个组件拥有自己的变量和函数，你可以促进代码复用，并提供一层抽象，帮助你和你的同事更好地理解代码。曾经 JavaScript 文件是长长一串函数列表，彼此间关联甚少且难以导航的日子已经一去不复返了。

> **注意**：JavaScript 最初并非设计为面向对象的编程语言，若将其视为此类语言可能会导致一些困惑。部分面向对象代码设计原则确实适用，但并非全部。如果你熟悉这些原则在其他语言中的用法，请仔细阅读本节内容，以便理解其中的差异。

本节将帮助你养成使用面向对象原则和技术编写 JavaScript 代码的习惯，就像专业开发者所做的那样。



#### 对象、类与构造函数

面向对象编程的两个重要概念是对象和类。接下来你将了解它们的含义，以及它们与 JavaScript 语言的关系。

## 什么是对象？

*对象*是一种特殊类型的数据，其中包含函数和变量。JavaScript 内置了多个核心对象，包括 `Math`、`Array` 和 `String`。这些对象提供了一组函数，用于对特定类型的数据执行操作。以下展示了调用这些对象方法的一些示例。

```
alert(Math.round(9.9)); // 输出 '10'

var cityList = new Array("New York", "London", "Stockholm");
var sortedCityList = cityList.sort(); // "London", "New York", "Stockholm"

alert(sortedCityList.join()); // 输出字符串 "London, New York, Stockholm"
```

请注意，你可以通过在对象名称和要调用的方法名称之间使用点号（`.`）来访问对象中的方法。

## 什么是类？

*类*是对对象的定义。除了作为创建对象的基础之外，它本身永远不会在代码中使用。在 JavaScript 中定义类就像编写一个函数一样简单。以下示例展示了使用 `function` 关键字定义类的两种方法。

```
function EmailMessage() { // 定义了一个名为 EmailMessage 的类
}

var EmailMessage = function() { // 定义同一个类的另一种方法
}
```

这两种定义类的方式都是有效的。你可以根据自己的喜好选择任何一种方式在代码中使用。

## 作为类实例的对象

再看一下使用对象的示例：

```
alert(Math.round(9.9));

var cityList = new Array("New York", "London", "Stockholm");
var sortedCityList = cityList.sort();

alert(sortedCityList.join());
```

观察 `Math` 对象和 `Array` 对象在用法上的区别。请注意，`Math` 对象可以直接使用，但 `Array` 对象前面需要使用 `new` 关键字。`Array` 对象定义了一个与数组列表相关函数的模板，根据我们之前的定义，这使它成为一个类。

要从一个类中创建可在代码中使用的内容，你需要使用 `new` 关键字，它会创建该类的一个*实例*。实际上，这允许你创建一个或多个对象，每个对象都包含类中定义的所有函数和变量，并且它们之间互不干扰。以下展示了几个将对象创建为类实例的示例。

```
var oceans = new Array("Atlantic", "Pacific", "Indian", "Arctic", "Antarctic");
var myMessage = new EmailMessage(); // 使用之前定义的类
var anotherMessage = new EmailMessage(); // 独立于上面的 myMessage
```

## 构造函数

*构造函数*是一段可选的代码，在使用 `new` 关键字从类创建对象的瞬间执行。在 JavaScript 中，只需向定义类的函数中添加代码即可实现，如下所示：

```
var EmailMessage = function() {
  // 实例化类时应执行的操作
  alert("新消息已创建。");
}

var myMessage = new EmailMessage(); // 输出 "新消息已创建。"
var anotherMessage = new EmailMessage(); // 输出 "新消息已创建。"
```

就像 JavaScript 语言中的普通函数可以传递参数供函数内部使用一样，类的构造函数也可以传递参数。以下是一个接受一个参数的类构造函数：

```
var EmailMessage = function(message) {
  alert(message);
}

// 输出 "Return to sender"
var myMessage = new EmailMessage("Return to sender");
```

在类中使用 `this` 关键字来引用实例化对象的作用域，稍后将对此进行更详细的讨论。

## 方法

属性定义了与类或对象关联的变量，而方法则定义了所有对象实例均可使用的可执行函数。下面的示例演示了如何向类添加方法，以及如何从该类实例化的对象中执行该方法。

## `prototype` 关键字

在类定义之外，向类分配属性和方法的另一种方式是，在类定义后，针对类名使用 `prototype` 关键字。下面演示如何以这种方式向类添加属性和方法：

```
var EmailMessage = function(subject) {
    this.subject = subject;
}
EmailMessage.prototype.from = ""; // 动态地向类分配新属性
EmailMessage.prototype.send = function() { // 动态地分配新方法
    alert("Message from " + this.from + " sent!"); // 'this' 的行为仍如常
}
var myMessage = new EmailMessage("My new website");
myMessage.from = "me@denodell.com";
myMessage.send(); // 输出 "Message from me@denodell.com sent!"
```

除了允许你在类定义后向其添加额外的属性和方法外，你还可以使用 `prototype` 关键字向已从这些类创建的对象分配新的属性和方法。这允许你动态地为已存在的对象实例添加新功能。下面的示例演示了这一原理。

```
var EmailMessage = function(subject) {
    this.subject = subject;
}
// 从 EmailMessage 类实例化一个对象
var myMessage = new EmailMessage("Coming to visit...");
// 向类添加一个新方法
EmailMessage.prototype.send = function() {
    alert("Message sent!");
}
// 这个新方法存在于该方法添加之前创建的对象上！
myMessage.send(); // 输出 "Message sent!"
```

#### 继承：从现有类创建新类

**继承**允许你创建从其他类派生的类，从而以某种方式对该类进行特化。原始类称为*父类*，从中派生出的新类称为*子类*。

JavaScript 中的继承同样是使用 `prototype` 关键字来执行的。在定义了子类之后，将父类赋值给子类的 `prototype`，这样父类的属性和方法就会立即对子类可用。

然后，子类可以根据需要覆盖或扩展父类的任何方法或属性。清单 2-2 演示了如何使用 JavaScript 执行基本继承。

**清单 2-2.** *JavaScript 中的基本继承*

```
var EmailMessage = function(subject) {
  this.subject = subject;
  this.send = function() {
    alert("Message '" + this.subject + "' sent!");
  }
}

// 创建一个新的空类
var EventInvitation = function() {};

// 继承 EmailMessage 类的属性和方法
EventInvitation.prototype = new EmailMessage();

// EventInvitation 认为自己就是 EmailMessage 类，因此修正这一点...
EventInvitation.prototype.constructor = EventInvitation;

// 为 EventInvitation 类的所有实例定义主题
EventInvitation.prototype.subject = "You are cordially invited to...";

// 创建 EventInvitation 类的一个实例
var myEventInvitation = new EventInvitation();

// 输出 "Message 'You are cordially invited to...' sent!"
myEventInvitation.send();
```

## 封装：每个类各司其职

当使用继承来创建现有类的变体或特化时，父类的所有属性和方法都对子类可用。你不需要在子类中声明或定义任何额外的东西就能使用父类的属性和方法。这被称为**封装**。子类只需包含那些在父类属性方法基础之上新增的属性和方法的定义。

## 多态：重定义继承的属性和方法

你已经看到，在创建继承自父类的新子类时，子类拥有父类的所有属性和方法。现在假设你希望子类包含一个与父类同名的方法，并在子类中执行该方法内的代码，而不是使用父类的方法。这就是**多态**。清单 2-3 演示了多态，其中子类包含一个与其继承的父类同名的方法。

**清单 2-3.** *多态实战：替换父类的方法*

```
var EmailMessage = function(subject) {
  this.subject = subject;
  this.send = function() {
    alert("Email message sent!");
  }
}

// 让 EventInvitation 类继承自 EmailMessage
var EventInvitation = function() {};
EventInvitation.prototype = new EmailMessage("You are cordially invited to...");
EventInvitation.prototype.constructor = EventInvitation;

// 重写继承来的 send 方法
EventInvitation.prototype.send = function() {
  alert("Event invitation sent!");
}

var myEmailMessage = new EmailMessage("A new email coming your way.");
var myEventInvitation = new EventInvitation();
myEmailMessage.send(); // 输出 "Email message sent!"
myEventInvitation.send(); // 输出 "Event invitation sent!"
```

现在假设你想重写子类中的一个方法，使其在父类方法的基础上执行额外的代码。也就是说，不是替换父类的方法，而是希望以某种方式扩展它，同时仍然使用父类提供的同名方法。清单 2-4 演示了这一原理。

> **注意** 任何你想要像清单 2-4 那样扩展的方法或属性，都必须在父类中使用 `prototype` 关键字声明；否则，它们将无法从子类内部找到。

**清单 2-4.** *多态实战：扩展父类的方法*

```
var EmailMessage = function(subject) {
  this.subject = subject;
}

// 我们希望以后能扩展这个方法，
// 因此它必须使用 prototype 关键字进行声明
EmailMessage.prototype.send = function() {
  alert("Email message sent!");
}

// 让 EventInvitation 类继承自 EmailMessage
var EventInvitation = function() {};
EventInvitation.prototype = new EmailMessage("You are cordially invited to...");
EventInvitation.constructor.prototype = EventInvitation;

// 重写继承来的 send 方法
EventInvitation.prototype.send = function() {
  // 为 EventInvitation 的 send 方法添加代码
  alert("Event invitation sent!");
  // 找到并执行 EmailMessage 类中的 send 方法
  // this.constructor.prototype 指向 EmailMessage 类
  this.constructor.prototype.send.call(this);
}

var myEmailMessage = new EmailMessage("A new email coming your way.");
var myEventInvitation = new EventInvitation();

// 输出 "Email message sent!"
myEmailMessage.send();

// 先输出 "Event invitation sent!"，然后输出 "Email message sent!"
myEventInvitation.send();
```

## `this` 关键字

构建任何基于对象的 RIA 的一个基本部分，是理解 JavaScript 中的 `this` 关键字。在本章的代码示例中，你已经在将属性和方法与类关联时，以及在子类内部调用父类方法时，看到了它的使用。了解如何正确使用这个强大的关键字将提升你的编码技能，并让你更好地掌握 JavaScript 语言本身。

`this` 关键字指向包含它的函数的**所有者**。如果它出现在类的方法中，则指向类本身，或者更准确地说，指向代码执行时创建的类的对象实例。在类的上下文之外，`this` 通常指向页面的全局 `window` 对象。请看清单 2-5，它展示了一些 `this` 关键字在不同上下文中基于同一个函数运行时的示例。

**清单 2-5.** *`this` 关键字实战*

```
var showSubject = function() {
  // 输出与这个函数拥有相同所有者的 subject 属性
  alert(this.subject);
}

// 输出 "undefined"，因为 this 关键字指向全局 window 对象，
// 而它没有名为 subject 的变量
showSubject();

// 设置一个全局的 subject 属性
this.subject = "Global subject";

// 现在属性已被设置，输出 "Global subject"
showSubject();

// 定义 EmailMessage 类
var EmailMessage = function(subject) {
  this.subject = subject;
}

// 复制并将 showSubject 函数赋给 EmailMessage 类，
// 使 EmailMessage 类成为该函数的所有者。
// 注意函数名后没有圆括号，这表示复制的是函数的代码而非立即执行它
EmailMessage.prototype.showSubject = showSubject;

// 创建该类的一个新实例
var myEmailMessage = new EmailMessage("I am the subject.");

// 输出 "I am the subject."，因为该函数的所有者是该类
myEmailMessage.showSubject();

// 再次输出 "Global subject" 以演示 this 没有被丢失
showSubject();

// 现在让我们向类中添加另一个方法，以不同方式调用 showSubject
EmailMessage.prototype.outputSubject = function() {
  showSubject();
}

// 输出 "Global subject"，因为此方法调用的函数
// 是与 window 对象关联的
myEmailMessage.outputSubject();
```

如果你希望调用一个函数或方法，并确保 `this` 关键字指向特定的对象，可以使用 `call()` 或 `apply()` 方法。



# 使用 `apply` 和 `call` 实现不同的对象引用

当你需要强制函数内部的 `this` 关键字指向一个与默认引用不同的对象时，有两个函数可以做到这一点：`apply()` 和 `call()`。两者在实现上的区别非常细微。`apply()` 期望你传递给函数的任何参数都以数组形式提供，而 `call()` 则不需要。清单 2-6 展示了这两个函数的实际应用，它们改变了一组可重用函数中 `this` 关键字的值。

**清单 2-6.** 使用 `apply` 和 `call` 改变 `this` 关键字的值

```
var showSubject = function() {
    alert(this.subject);
}

var setSubjectAndFrom = function(subject, from) {
    this.subject = subject;
    this.from = from;
}

// 针对全局 window 对象执行
showSubject(); // 输出 "undefined"
setSubjectAndFrom("Global subject", "me@denodell.com");
showSubject(); // 输出 "Global subject"

// 创建 EmailMessage 类
var EmailMessage = function() {
    this.subject = "";
    this.from = "";
};

// 实例化类
var myEmailMessage = new EmailMessage();

// 执行 setSubjectAndFrom 函数，强制函数内的 this 关键字
// 指向 myEmailMessage 而非 window 对象。参数
// 在作为拥有者的对象之后以序列形式传递，将 subject 设置为
// "New subject"，并将 from 属性设置为 "den@denodell.com"
setSubjectAndFrom.call(myEmailMessage, "New subject", "den@denodell.com");

// 作为演示，我们现在使用 apply 代替 call 来做同样的事情；
// 与 call 不同，apply 期望参数以数组形式提供。
// 你可以在代码中自由使用 apply 或 call
setSubjectAndFrom.apply(myEmailMessage, [ "New subject", "den@denodell.com" ]);

// 输出 "New subject"
showSubject.call(myEmailMessage);
```

## 属性和方法的访问权限

大多数编程语言允许你定义对象中特定属性或方法在整个应用程序范围内的访问级别。到目前为止，所有示例中创建的类的属性和方法都是公开可用的，也就是说，它们可以从代码库中的任何位置访问。创建类的新实例允许对该实例中的任何属性进行读写访问，并允许执行任何方法。

但是，如果你要为类创建一个只在类内部可用的属性或方法（称为*私有*）呢？或者，假设你想从类定义外部对私有属性进行只读访问；你可以称之为*特权*属性。

> **注意：** 不要在此处将 *public*、*private* 和 *privileged* 这些术语与其他语言中的类似名称混淆。在此上下文中，我们仅讨论从类外部对类内部属性和方法的访问。

清单 2-7 演示了类属性的不同类型访问方式。

**清单 2-7.** 限制对类属性和方法的访问

```
var EmailMessage = function(subject) {
    // 公开可访问的属性和方法

    this.send = function() {
        alert("Message sent!");
    }

    // 私有属性和方法。
    // 使用 var 而非 this 关键字来设置属性意味着该
    // 变量的作用域被限制在其所在的函数内部，并且
    // 无法从外部访问
    var messageHeaders = "";
    var addEncryption = function() {
        // TODO：添加加密方法

    // 通过创建私有属性和公共方法实现
    var messageSize = 1024;
    this.getMessageSize = function() {
        alert(messageSize);
    }
}

var myEmailMessage = new EmailMessage("Save these dates...");

myEmailMessage.send(); // 输出 "Message sent!"
```


```javascript

```

```

#### 对象字面量与 JavaScript 对象表示法

JavaScript 语言中的**对象字面量**本质上是一个列表或集合，包含任意数量的属性名称及其对应的值。对象字面量的值可以是字符串、整数、浮点数、布尔值、数组、函数，甚至是其他对象字面量，并以特定格式表示。

对象字面量的格式通常被称为 JavaScript 对象表示法（JSON）。

对象字面量的开始和结束由花括号`{`和`}`表示。花括号内列表中的每个项用逗号分隔，每个名称与其值之间用冒号分隔。

在语言中，对象字面量用于将相关属性和方法分组在一起，类似于类的用法。然而，对象字面量只有一个实例，并且在创建时无法像类定义那样执行任何代码语句。清单 2-8 展示了一个包含多种类型值的对象字面量。

**清单 2-8.** *包含多种类型值的对象字面量*

### 创建命名空间和层次结构

在全局的`window`对象中创建过多的变量通常被称为**污染全局作用域**。这种做法很危险，因为您定义的变量可能与网站上运行的第三方脚本使用的变量重名。JavaScript 不会在变量被这样覆盖时发出警告，因此您可能依赖的值已被外部不可控因素覆盖。

解决这个问题的方法是在全局作用域中创建一个单独的变量，作为对象字面量或单例，包含应用程序的所有代码。这在许多编程语言中被称为**命名空间**。您可以在该全局对象内创建其他对象字面量或单例，以维护命名空间的层次结构，将相关代码分组在一起。以下是一个命名空间层次结构的示例：

```javascript
var MyCompany = new function(){
    this.MyClient = {                 // 对象字面量
        WebMail: function() {        // 构造函数
            alert("正在创建 WebMail 应用程序……");
        }
    };
}();    // 创建 MyCompany 作为单例

// 现在可以通过点号表示法访问层次结构。
// 输出 "正在创建 WebMail 应用程序……"
var myWebMail = new MyCompany.MyClient.WebMail();
```

# JavaScript DOM 就绪与事件处理

JavaScript 程序员的一个主要困扰是，当执行的脚本需要访问 DOM 时，DOM 有时尚未可用。如果脚本被引用在 HTML 页面的 `<head>` 部分，它将在该页面的 `<body>` 加载之前执行，这意味着此时它将无法定位页面元素。以前，开发者会将整个代码添加到 `window.onload` 事件中，这意味着它将在整个页面（包括任何外部图片、CSS 和 JavaScript 文件）加载完成后才执行。页面上的图片越多，用户等待脚本执行的时间就越长。

最终，一些浏览器厂商与 W3C 共同引入了 `DOMContentLoaded` 事件，该事件在页面元素加载完成并可通过 JavaScript 访问时触发。此事件在 `window.onload` 事件之前触发，也在外部文件完成加载之前触发，这意味着开发者可以让脚本针对 DOM 执行，而无需等待整个页面内容加载完成。

不幸的是，`DOMContentLoaded` 事件尚未在所有常见浏览器中实现，尤其是 IE 6、7 和 8。为了平滑这种不一致性，并在支持该事件的浏览器中提供支持，在不支持的浏览器中提供变通方案，你需要编写自己的方法，在 DOM 准备好使用时执行你的代码。清单 2-10 展示了在你的 `$` 库中，在所有浏览器中实现此行为的一种方法。

**清单 2-10.** *在 DOM 准备好访问时执行代码*

```
$.prototype.onDomReady = function(callback){ // callback 应为一个函数
    if (document.addEventListener) {
        // 如果浏览器支持 DOMContentLoaded 事件，
        // 则在该事件触发时将回调函数分配给其执行
        document.addEventListener("DOMContentLoaded", callback, false);
    } else {
        if(document.body && document.body.lastChild){
            // 如果 DOM 已可访问，则执行回调函数
            callback();
        } else {
            // 重新执行当前函数（由 arguments.callee 表示），
            // 等待一个短暂的纳秒时间，以免锁定浏览器
            return setTimeout(arguments.callee, 0);
        }
    }
}

## 使用 Ajax 按需加载内容

大多数 RIA 的一个基本功能是无需刷新页面即可直接与 Web 服务器通信。这使得 Web 应用程序的行为更像桌面应用程序，可以在后台加载和保存数据，并独立地更新页面的各个部分。

`异步 JavaScript 和 XML`（简称 Ajax）通常是指通过 JavaScript 从远程 Web 服务器下载或发送内容的实践。尽管名称中提到了 XML，但该技术实际上并不依赖 XML 格式的数据进行通信；实际上，任何类型的内容都可以传输或接收。术语*异步*意味着，在加载内容时，脚本的其余部分仍可继续执行——代码不会停下来等待内容加载完成后再继续。

> **注意** 作为一种安全措施，使用 Ajax 技术时，浏览器只允许你访问与当前执行代码的页面位于同一域名下的内容。许多开发者通过在其 Web 服务器上包含一个服务器端脚本来解决这个限制，当向该脚本传递一个 URL 作为查询字符串参数时，它会加载该 URL 的内容并将其传递回页面上的 Ajax 请求。

别忘了在编写代码时，如果你通过此技术提供了执行操作或加载某些内容的方法，那么在相关情况下，同样的操作必须能够仅通过 HTML 完成。例如，如果你正在创建一个 Web 邮件客户端，你应该先构建一个能够通过 HTML 正常运行的应用程序，然后再添加 JavaScript 和 Ajax 技术，将其转变为 RIA。

  // 并在事件触发时执行一个分配的方法

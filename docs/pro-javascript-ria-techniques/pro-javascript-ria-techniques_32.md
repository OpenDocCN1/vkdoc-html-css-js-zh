# V8 基准测试套件

*V8 基准测试套件*：该测试套件由谷歌创建。V8 是谷歌 Chrome 浏览器中使用的 JavaScript 引擎的名称。谷歌的开发者采用了一种新方法来应对 JavaScript 效率问题，即有效地将 JavaScript 代码解释为机器码级别——也就是你电脑中硅芯片能够理解的代码。虽然这使得 Chrome 在核心 JavaScript 性能方面非常高效——这也是 V8 基准测试所专门关注的——但在试图通过 DOM 与网页交互时，这几乎毫无意义，因为 DOM 依赖于 JavaScript 引擎和渲染引擎之间的高效交叉通信。

正如你所见，基准测试中涉及了政治因素。例如，你可能会怀疑 SunSpider 包含了一些在基于 WebKit 的浏览器上运行时能给出有利结果的测试，因为同一个团队同时构建了该浏览器和测试工具。当然，没有哪个基准测试的创建者声称偏爱某个特定的浏览器。然而，明智的做法是将所有基准测试工具的结果都考虑在内。让所有四个测试套件的综合结果来影响你对哪个 JavaScript 引擎性能最佳的判断。

每个测试套件都可以通过 Dromaeo JavaScript 性能网站（`http://dromaeo.com/`）运行，该网站将所有基准测试工具整合到一个集中的 JavaScript 性能测试中心。

每个基准测试套件会连续多次快速运行许多不同的测试，测量在给定时间范围内完成了多少测试，然后取结果的平均值，从而得出每个浏览器在每个测试套件上的最终性能数据。这些测试往往集中在 JavaScript 的两个主要方面：代码执行的原始处理能力和通过 DOM 与网页的交互。如果不测试这两个方面，你无法为网页中 JavaScript 的真实使用情况给出一个性能数据。

## 网页请求的剖析

你是否曾想过，从你在地址栏输入网址到完整页面出现在浏览器中之间发生了什么？在本节中，你将了解将一个 URL 转化为浏览器可以显示的内容所涉及的过程。

### HTTP：网络背后的通信标准

你的浏览器与目标网络主机之间的通信语言称为超文本传输协议（HTTP）。在这种语言或协议中，浏览器被称为*客户端*，网络主机被称为*服务器*。从你点击链接或在浏览器地址栏输入新 URL 开始，到页面在屏幕上加载完毕，客户端和服务器之间会来回发送消息。在这种语言中，请求消息从客户端传递到服务器，响应消息从服务器返回给客户端。

> **注意** 在浏览器地址栏中当前页面的网址前面，你会看到用于访问该 URL 的协议名称。在大多数情况下，它显示为 `http://`，代表 HTTP。但是，如果你正在浏览某些网站或页面，它可能会显示为 `https://`，代表 HTTPS，这是一种用于发送敏感数据的安全 HTTP 形式。其他协议包括 `ftp://` 和 `feed://`，分别用于浏览文件传输协议（FTP）站点和 RSS 新闻源。

在浏览器的地址栏中输入 `www.google.com`，让我们看看点击“转到”按钮后会发生什么。

### HTTP 请求消息

当你的浏览器请求一个 URL 时，会创建一个纯文本的 HTTP 请求消息，该消息将发送到服务器，请求服务器返回一个页面或文件。清单 3-1 展示了一个 HTTP 请求消息的示例。

**清单 3-1.** *针对 `www.google.com` 的 HTTP 请求消息示例*

```
GET / HTTP/1.1
Host: www.google.com
User-Agent: Mozilla/5.0 (Windows; U; Windows NT 5.1; en-GB; rv:1.9.0.3) ➥
Gecko/2008092417 Firefox/3.0.3 (.NET CLR 3.5.30729)
Accept: text/html,application/xhtml+xml,application/xml;
Accept-Language: en-gb,en;
Accept-Encoding: gzip,deflate
Accept-Charset: ISO-8859-1,utf-8;
Keep-Alive: 300
Connection: keep-alive
Cookie: PREF=ID=64637ffc707d92f4:TM=1222191214:LM=...
```

如果你不熟悉 HTTP，这可能看起来有些令人困惑。让我们分解一下，逐一了解请求消息中的每个*头*或条目，以便你理解发生了什么。该头的第一部分定义了用于发送此请求的操作或方法。

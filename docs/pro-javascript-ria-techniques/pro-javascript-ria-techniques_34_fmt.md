# HTTP 响应消息

当服务器接收到请求消息并处理其数据后，会创建一个 HTTP 响应消息来包含处理结果。**清单 3-2** 展示了针对**清单 3-1** 中请求消息的服务器响应消息。

**清单 3-2.** *[www.google.com 的 HTTP 响应消息示例](http://www.google.com)*

```
HTTP/1.x 200 OK
Cache-Control: private, max-age=0
Date: Fri, 27 Mar 2009 12:42:14 GMT
Expires: -1
Content-Type: text/html; charset=UTF-8
Content-Encoding: gzip
Server: gws
Content-Length: 2520

<html><head>
... 谷歌主页的其余 HTML 内容 ...
</body></html>
```

接下来我们逐一讲解这些头部，确保你完全理解浏览器从服务器接收了什么信息，以及它如何使用这些信息。

### `HTTP/1.x 200 OK`

响应中的第一个头部让浏览器客户端知道，用于格式化消息其余部分的 HTTP 协议版本是哪个。在此例中，只要版本为 1 且任何次版本号都能理解该消息。版本号之后是一个状态码和简短描述，用于告知浏览器请求的结果是什么，这决定了消息其余部分的数据类型。这些状态码对于理解浏览器在收到响应消息时的行为至关重要，下一节将对其详细说明。

### `Cache-Control: private, max-age=0`

浏览器维护着一个本地文件缓存，会将近期请求过的文件存储在访问这些文件的计算机上，以避免重复下载，从而让终端用户的体验更流畅。`Cache-Control` 头部为浏览器提供了关于当前请求文件的某些参数，例如，告诉它缓存该文件多长时间。在此例中，`private` 告诉浏览器以及位于 Web 服务器和客户端之间的任何代理服务器，该文件是特定于请求它的用户的，也许是因为该文件已为该用户进行了个性化处理。如果没有这个设置，代理服务器可能会将其他用户的个性化主页发送给当前请求用户，造成严重混乱。`max-age` 属性告诉浏览器或代理服务器将文件缓存多长时间，单位是秒。在此例中，值为 `0` 确保每次都会从服务器请求一个全新的文件副本，这对于像谷歌主页这样的个性化网站是最佳的。其他文件，例如图片、CSS 和 JavaScript，理想情况下可能会设置更长的 `max-age` 值，以确保它们在每次请求新页面时都不需要被重新请求。

> **注意：** 将 `Cache-Control` 设置为 `no-cache` 会告诉浏览器不要将该文件存储在缓存中，从而强制每次请求时都从服务器重新下载相同的文件。

### `Date: Fri, 27 Mar 2009 12:42:14 GMT`

`Date` 头部的值仅指示响应消息发送的日期和时间。

### `Expires: -1`

`Expires` 头部指定了所发送文件被视为过期（或陈旧）的日期和时间，届时应下载新副本。值为 `-1` 表示内容已经太旧，从而强制浏览器下次从服务器下载全新的副本。

### `Content-Type: text/html; charset=UTF-8`

`Content-Type` 头部指定了此请求中发送内容的 MIME 类型。`text/html` 表示发送的内容是 HTML。如果是基于文本的内容，还可以在此头部中指定字符集。

### `Content-Encoding: gzip`

`Content-Encoding` 头部指示了应用于响应中发送内容的内容编码类型。服务器会监听之前提到的 `Accept-Encoding` 请求头部，并且只应以客户端支持的编码格式发送回内容。

### `Server: gws`

`Server` 头部将 Web 服务器软件的名称发送给客户端。值为 `gws` 表示使用了谷歌自己的 Web 服务器软件来生成响应。

### `Content-Length: 2520`

随此响应消息发送的文件内容大小（以字节为单位）在 `Content-Length` 标头中指定。

```
<html><head>
... Google 首页的其余 HTML 代码 ...
</body></html>
```

响应消息的最后部分包含服务器针对所请求 URL 返回的实际文件内容。清单 3-1 请求了一个 HTML 页面，因此清单 3-2 返回了 HTML 标记。如果请求的文件类型是图像，您会看到所请求图像文件中存储的二进制数据的文本表示形式，该表示形式随后会在客户端内转换回二进制数据，从而正确显示图像。

#### HTTP 状态码

HTTP 状态码是三位数字的代码，表示服务器对请求的响应，指明请求是否成功，或者客户端现在是否需要执行其他操作才能成功定位所请求的数据。在此，我将描述 HTTP 响应消息中返回的一些常见状态码。如需所有 HTTP 状态码的完整列表，请访问 [`en.wikipedia.org/wiki/List_of_HTTP_status_codes`](http://en.wikipedia.org/wiki/List_of_HTTP_status_codes)。

#### 200+（成功）

状态码在 200–299 范围内，表示请求已被服务器接收、理解并处理，并且客户端应期待当前响应消息中会包含某种类型的内容。表 3-5 列出了此范围内的常见状态码。

**表 3-5.** *表示成功响应的 HTTP 状态码*

| 状态码 | 描述 |
| ----------- | ----------- |
| 200 OK | 请求成功。响应消息包含所请求的数据。 |
| 201 Created | 根据请求中的 `POST` 或 `PUT` 操作，在服务器上创建了一个新资源。 |
| 204 No Content | 请求成功，但所请求的 URL 没有内容可发送回客户端。 |
| 206 Partial Content | 响应消息包含更大请求的部分内容。这允许浏览器恢复因网络故障或用户取消下载而中断的大文件下载。 |

#### 300+（重定向）

状态码在 300–399 范围内，表示为了成功完成请求，客户端必须执行额外步骤，重定向到另一个 URL，或者不期望任何内容。表 3-6 列出了此范围内的常见状态码。

**表 3-6.** *表示需要重定向的 HTTP 状态码*

| 状态码 | 描述 |
| ----------- | ----------- |
| 301 Moved Permanently | 所请求的 URL 已被永久移动，客户端不应再尝试使用该 URL，即将其列入黑名单。客户端在未来所有请求中应使用响应消息中返回的 URL。 |
| 302 Found | 所请求的 URL 已被临时移动，可通过响应消息中给出的 URL 访问。不进行黑名单操作，因为这只是临时重定向。 |
| 304 Not Modified | 所请求的 URL 之前已被请求过，并且自上次请求以来未发生更改。客户端应改用所请求 URL 文件的本地缓存副本，以节省带宽并更快地向最终用户提供文件。 |

#### 400+（客户端错误）

HTTP 状态码在 400–499 范围内，表示发送给服务器的请求消息中存在错误，导致服务器无法返回所请求的文件。这表明错误在于客户端，而非服务器。表 3-7 显示了此范围内的常见状态码。

# 最佳实践

现在你已经理解了 CSS 的基础知识。本章作为最后一章，将退一步来审视样式表开发的良好编码实践与标准。遵循这些指南可以帮助你编写易于维护、复用和扩展的健壮 CSS 代码。

## 可复用的代码

管理样式表的一个关键思想是避免重复代码。类（Classes）有助于实现这一目标，因为它们是可复用的，并且可以通过不同方式组合，从而为你提供易于演进的灵活设计。

每当你发现页面元素共享样式属性时，就应该考虑组合这些重复的模式。这使得代码更易于复用和更新，同时也有助于保持网站样式的一致性。思考以下简单示例：

```
.module {
  width: 200px;
  border: 1px solid #ccc;
  border-radius: 3px;
}
.widget {
  width: 300px;
  border: 1px solid #ccc;
  border-radius: 3px;
}
```

这两个类有两个共同的样式，可以被移入第三个类以避免不必要的重复。这个过程使得类更具通用性，因此也更易于复用。

```
.box-border {
  border: 1px solid #ccc;
  border-radius: 3px;
}
.module { width: 200px; }
.widget { width: 300px; }
```

在优化类以实现复用时，考虑其粒度非常重要。目标是找到介于过宽和过窄之间的类。过宽的类会导致不必要的重复；过窄的类则会使设计难以更改。

## 全局修饰符

有些样式属性非常常用。与其将这些样式添加到每个其他类中，有时更好的做法是创建一个包含该单一样式的通用类，然后将其应用于需要它的元素。例如，将元素向左或向右浮动就是这样一个常见操作。这些样式非常适合用作全局修饰符。

```
.left  { float: left; }
.right { float: right; }
```

当你希望一个元素向右或向左浮动时，可以简单地将这些类之一添加到该元素上：

`<div class="left">...</div>`

当只需要单个样式属性时，诸如此类的全局修饰符非常有用。但是，你应该避免组合多个这样的修饰符，因为如果所有页面元素都由如此小的类构成，调整设计将会变得困难。

## 样式表结构

通过组织样式表，你可以让自己和其他开发者更容易快速理解 CSS 的结构。网站规模越大，参与的开发者越多，保持良好组织的需求就越大。但无论网站规模大小，始终保持样式表结构良好总是一个好习惯。

样式表的顶部通常包含有关文件及其作者的信息。这些元数据应包括作者的姓名和联系方式。这样，如果对文档有任何疑问，当前负责该网站的开发者就知道该问谁。其他可能有用的元数据包括文件的创建日期、最后修改日期、版本号、标题和描述。

```
/*
 * 标题：我的主题
 * 版本：1.2.3
 * 作者：我的名字
 */
```

至于样式规则，它们应该被分组到不同的章节中，每个章节都应带有辨识度高的注释标签。这种分组和标签能使你更快地找到所需内容。所需的章节取决于网站本身，以下是一些示例章节：

```
/* === 标准化 === */
/* === 主要布局 === */
/* === 二级布局 === */
/* === 三级布局 === */
/* === 导航 === */
/* === 文本相关 === */
/* === 链接和图片 === */
/* === 通用样式 === */
/* === 通用类 === */
/* === 杂项 === */
```

章节名称后的等号有助于在视觉上将各章节与其他注释区分开来。它们也充当了一个标记，你可以通过搜索来轻松遍历各个章节。

对于大型样式表，可以在元数据下方列出章节名称作为目录，这有助于开发者快速了解文件的组织方式。

```
/* 目录
* ----------------
* 标准化
* 主要布局 (body, 主要 divs)
* 二级布局 (header, footer, sidebar)
* 三级布局 (页面区域)
* 导航 (菜单)
* 文本相关 (段落, 标题, 列表)
* 链接和图片
* 通用样式 (表单, 表格等)
* 通用类 (.clear, .center 等)
* 杂项
*/
```

在每个章节内，你应该先声明最通用的规则，然后依次是特异性递增的规则。你的元素可以继承样式，并且在需要时更容易覆盖特定样式。

另一个需要考虑的是如何组织规则内的属性。一种流行的方法是根据类型对属性进行分组。你不必像下例那样为每个组添加标签，但如果能在整个样式表中保持分组顺序的一致性，将有助于你更快地扫描规则以查找特定属性。

```
.myclass {
  /* 定位 */
  position: absolute;
  top: 0;
  right: 0;
  /* 盒模型 */
  display: inline-block;
  width: 100px;
  height: 100px;
  /* 颜色 */
  background: #ccc;
  color: #fff;
  /* 文本 */
  font-size: 1em;
  line-height: 1.2;
  text-align: right;
  /* 其他 */
  cursor: pointer;
}
```

请记住，这些只是指南；选择一种适合你的结构，并力求保持一致。

## 命名约定

为类和 ID 命名时，阐明其预期用途会很有帮助。这种结构化命名约定意味着，名称应描述该类或 ID 的用途，而不是它的外观或其在网页文档中的位置。

这种命名约定的好处在于，它能让更改网站外观变得更加容易。例如，将一个 ID 容器命名为 `#main-content` 比命名为 `#center-column-500px` 更好。除了能直观理解该 ID 的用途外，第一个名称在你日后可能需要调整其应用元素的位置或大小时，更具通用性。

```
#main-content {
  width: 500px;
  margin: 0 auto; /* 居中 */
}
```

名称应具有语义性，但也不能语义性过强以至于限制了它的复用。例如，将一个类命名为 `.header-top-margin` 就没有命名为 `.small-top-margin`（或 `.small-tm`）来得灵活。日后回想起这个类主要用于页眉区域是很容易的；例如，你可以在网页浏览器中查看页面源代码时，使用搜索功能来搜索该类名。

```
.small-top-margin { margin-top: 1em; }
```

除了传达预期用途外，类名还可以展示其与其他类之间的关系。例如，如果一个容器类名为 `.post`，那么该容器的标题可以命名为 `.post-title`，以表明该类应仅在应用了 `.post` 类的元素内部使用。

```
.post {
  margin: 1em 0;
}

.post-title {
  font-size: 1.2em;
}
```

标题类本来也可以写成 `.post.title`，以确保 `.title` 类只能在使用了 `.post` 类的容器内部使用。然而，`.post-title` 这种命名方式有助于避免命名冲突，并且不会增加特异性，因此这种命名约定通常是更可取的。注意，规则之间的关系通过缩进得到了进一步的强调，这能显著提高代码的可读性。

## 规范化

不同的浏览器对某些元素的渲染会略有不同，这主要是由于其默认样式表的差异。为了获得一个共同的基准线，通常会包含一组规则来规范化这些浏览器之间的不一致性，并设置合理的默认值。这方面最流行的选择是 GitHub 上的 `Normalize.css` 项目。¹ 通过在样式表顶部包含这些规则（或根据网站需求包含其子集），你就能在所有浏览器中拥有一个一致的起点，并在此基础上进行构建。`Normalize.css` 样式表包含了大量的注释，解释了它所解决的每一个浏览器不一致性问题。

## 调试

有许多有用的调试工具可以极大地简化网页开发者的工作。Firefox 的 `Firebug` 扩展是这些工具中最强大的之一。它允许你在任何网页上实时编辑和调试 CSS、HTML 和 JavaScript，以供测试之用。你还可以自由开启或关闭样式，并找出精确应用于所选元素的样式。要了解更多关于 `Firebug` 的信息，请访问 `Firebug` 官方网站。²

与 `Firebug` 类似的功能在 Chrome 上可通过内置于浏览器中的 Chrome 开发者工具实现。你可以使用快捷键 `Ctrl+Shift+I`（Windows）或 `Cmd+Opt+I`（Mac）调出 DevTools 窗口。或者，你也可以右键点击页面上的某个元素，然后选择“检查元素”，从而在元素检查模式下调出相同的窗口。

## 验证

检查你的 CSS 是否符合 W3C 标准是一个好习惯。不规范的代码可能会导致你的网站在不同浏览器中出现意料之外的显示效果。此外，拥有无错代码也是一个高质量网站的象征。

W3C 提供了它自己的在线 CSS 验证工具。³ 它会检查提交的页面，并返回页面上发现的任何错误和警告，供你修正。它还有一个类似的用于验证 HTML 文档的工具，⁴ 这样做同样重要。为了让验证更加便捷，你可以下载一个为你检查页面代码的浏览器插件，例如 Chrome、Firefox 和 Opera 上可用的 `Web Developer` 插件。⁵

## 单一样式表

出于性能考虑，最好将网站的样式规则包含在一个单一的外部样式表中。这样做可以最大限度地减少加载网站所需的 HTTP 请求数量，同时允许 CSS 文件被缓存，以便访问者的浏览器只需下载一次。

在大型网站的开发过程中，通常更倾向于将样式规则分散到几个更易于管理的 CSS 文件中。为了两全其美，这些开发文件可以在网站的构建过程中合并成一个单一的文件。`Bundle` 工具就是为此目的而设计的一个有用工具。⁶ 当你的网站设计稳定后，该工具还可用于压缩你的 CSS。

## 代码压缩

代码压缩是指从代码中移除不必要的字符以减小其大小的过程。当压缩一个 CSS 文件时，空白字符会被移除，并且规则会被优化和重组以加快加载速度。这种压缩可以极大地减小文件大小，从而以牺牲代码可读性为代价来提高网站性能。由于可读性降低，最好使用未压缩的样式表进行工作，并在每次更新 CSS 文件时重复进行压缩步骤。压缩可以自动完成（例如，使用前面提到的 `Bundle` 工具），也可以使用像 `Clean CSS` 这样的在线工具手动完成。⁷

压缩工具无法完成的一项优化是查找并移除未使用的 CSS 规则。一个有助于你执行此任务的有用 Firefox 插件是 `Dust-Me Selectors`。⁸ 这个插件可以逐个测试页面，也可以扫描整个网站以查找未使用的选择器。

## 跨浏览器测试

即使你的代码经过了规范化和验证，不同浏览器（尤其是旧版本）在渲染网页时仍可能存在一些差异。因此，有必要在你希望网站支持的所有浏览器版本中进行测试。

为了简化这一测试过程，你可以使用 `BrowserStack`，⁹ 这是一个用于检查浏览器兼容性的在线工具。它可以向你展示你的网站在你选择的不同版本浏览器上的显示效果。你还可以查看你的网站在移动设备和平板电脑上的显示效果。

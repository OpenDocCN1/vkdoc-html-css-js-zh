# 使用模板字符串格式化字符串

## 引言

你是否曾尝试在 JavaScript 中创建需要同时插入多个变量的动态字符串？我似乎总会在 `+` 和引号的使用上出错。更别提还要按照特定格式处理换行和缩进。而且，一旦写完，我们最好永远不要再去修改它，对吧？

在本章中，我们将永久告别字符串拼接，转而使用模板字符串。它允许我们以清晰且声明式的方式编排包含变量和表达式插值的字符串。我们还将探索标签函数，它可以用来在 JavaScript 中创建领域特定语言。我向你保证，在本章结束时，你会迫不及待地重构代码库中的所有字符串，以使用模板字符串。你甚至可能会获得一些关于如何快速创建自己的 DSL 的灵感！

## 字符串拼接的麻烦

JavaScript 提供了 `String` 原始类型，并支持使用单引号或双引号直接构造字符串。^(³⁵) 然而，虽然这适用于构造静态字符串，但在以编程方式构建字符串时却相当麻烦。考虑以下情况：

* ① 确保在有称呼时插入它
* ② 组合全名，如果没有中间名则省略

```javascript
const salutation = 'Mr.';
const name = 'Edgar';
const middle = 'Allen';
const last = 'Poe';
const fullName = (salutation ? salutation + ' ' : "") ①
+ name + ' ' + middle.trim() + ' ' + last; ②
// 输出 'Mr. Edgar Allen Poe'
console.log(fullName);
```

如我们所见，当我们试图区分字符串中的“静态”或固定部分，以及“动态”或变量部分时，我们想要实现的目标意图已经丢失。当然，如果动态部分恰好包含函数或方法调用、条件语句或循环结构，这个问题会进一步加剧。

许多现代 JavaScript（及单页应用）框架（如 Angular）允许我们将 HTML 嵌入到与 JavaScript（或 TypeScript）相同的文件中。HTML 与我们的 JavaScript 代码一样，只有在正确格式化时才最容易编写，更重要的是易于维护。鉴于我们唯一可用的选项是字符串拼接，我们被迫参与插值和缩进的复杂操作^(³⁶)：

* ① 声明一个变量
* ② 尝试使用字符串拼接构造一个相当复杂的字符串
* ③ 在行内使用该变量

```javascript

function HelloComponent() { };
HelloComponent.annotations = [new ng.core.Component({

'' +

'' + title + '' + ③

''
})];
```

优秀的程序员不会让朋友审查格式错误的代码。因此，我们不仅被迫使用 `+` 运算符换行，还需要确保代码正确缩进。然而，在这种情况下，我们的编辑器会将其视为 JavaScript，而没有意识到它实际上是嵌入在 JavaScript *内部*的 HTML，如果被要求重新缩进所有代码，它会直接执行（如果它没有自动这样做的话！）。当然，这个问题几乎延伸到所有嵌入式 DSL，其中存在插值变量和格式的混淆。

鉴于我们现有的工具，我们只能诉诸字符串拼接这种古老的插值机制，同时痛苦地在适当的行长度处按下 `Enter` 键，希望我们的 linting 工具不会因为格式不正确的行太多而导致构建失败。

好了，我们的烦恼结束了。ES6 引入了模板字面量，以及作为其扩展的带标签模板字面量。

## 模板字面量

模板字面量引入了更多的语法，即反引号 `` ` `` 作为声明字符串的机制，以及占位符语法 `${}` 来支持变量和表达式的插值。模板字面量使得组合包含字面量字符串和将作为字符串创建一部分被求值的行内表达式变得更加容易。考虑以下情况：

* ① 引入一些常量占位符
* ② 使用带有变量插值的模板字面量组合字符串

```javascript
const greeting = 'Hola'; ①
const name = 'Daniel';
const msg = `${greeting}! My name is ${name}`; ②
```

模板字面量真正地编排了一个字符串，省去了通过精心放置 `+` 运算符而不得不绕的弯路。在 `${}` 内用于插值的命名恰当的变量有助于提高可读性。

插值语法接受任何表达式——无论是函数调用、数学运算，甚至是三元表达式。^(³⁷)

模板字面量也可以用于编排多行字符串。如果以这种方式使用，它们会在求值时保留布局。鉴于许多现代编辑器和 IDE 已经支持 ES6 语法，让它们自动格式化你的代码意味着我们不再会丢失布局。让我们看看重新审视 Angular 组件示例时会是什么样子：

* ① 声明一个变量
* ② 使用模板字面量组合字符串
* ③ 在行内插入一个变量

```javascript
const title = 'Section Title'; ①
function HelloComponent() { };
HelloComponent.annotations = [new ng.core.Component({
selector: 'app-hello-world',
template: `
 ②
${title} ③
`
})];
```

模板字面量保留了我们在反引号内引入的所有格式。在我们的示例中，字符串以换行符开头，后面的每一行都缩进了两个空格。如果我们只是使用 `console.log` 将其打印出来，我们会看到模板字面量信守了它的承诺。再次得益于大多数编辑器现在支持 ES6 语法，我们可以很容易地识别出哪里是直接编排字符串，哪里是使用插值语法。

插值语法有一个限制，那就是我们不能嵌套插值。让我们看一个例子：

* ① 在理想情况下生效
* ② 哎呀！多了一个空格
* ③ 尝试嵌套插值将不起作用
* ④ 我们可以利用模板字面量会求值为字符串这一事实

```javascript
// 为便于说明，用 _ 表示空格
{
const name = 'Edgar';
const middle = 'Allen';
const last = 'Poe';
// 输出 'Edgar_Allen_Poe'
console.log(`${name} ${middle} ${last}`); ①
}
{
const name = 'Emily';
const middle = "";
const last = 'Dickinson';
// 输出 'Emily__Dickinson'
console.log(`${name} ${middle} ${last}`);
// 输出 'Emily__Dickinson' ②
console.log(`${name} ${middle.trim()} ${last}`);
// console.log(`${${name} ${middle}}.trim() ${last}`); ③
// 输出 Emily_Dickinson
console.log(`${`${name} ${middle}`.trim()} ${last}`); ④
}
```

在我们的理想情况下，每个候选人都有名、中间名和姓。然而，在没有中间名的情况下，盲目地拼接字符串而不在正确位置使用 `trim` 会导致多出一个空格。另外，请注意我们尝试 `trim` 中间名的方法也是不恰当的——如果名字本身包含尾随空格，修剪中间名有助于减少冗余空格。但对于空中间名*周围*的空格却没有作用。

我们想做的是连接名和中间名，使用 `trim` 消除任何冗余空格，然后才加上姓。

由于我们不能嵌套插值，我们被迫采取不同的策略。我们可以利用模板字面量会求值为其最终字符串这一事实——因此我们可以在模板字符串中嵌套模板字符串——从而以一种稍微复杂的方式实现插值的嵌套。

尽管有人可能会质疑嵌套模板字符串的可读性，而且这种质疑也完全合理，但在实际中并不少见，尤其是在我们即将讨论的带标签的模板字面量中。

另一个限制是插值语法是 `${}`，这意味着 `$` 和 `{}` 都是必需的。许多语言（如 Ruby）允许在仅求值一个变量时省略 `{}`，但在求值任何表达式时必须使用它们。

如果我们想要将反引号或 `$` 符号作为字面量呢？很简单。只需使用反斜杠进行转义，如下所示：

```javascript
const escapingLiterals = `模板字符串引入了 \`\` 并使用 $\{} 进行插值`;
// 输出 '模板字符串引入了 `` 并使用 ${} 进行插值'
console.log(escapingLiterals);
```

模板字面量优雅地解决了字符串组合的问题——让我们能够简洁地表达字符串如何形成和格式化。但还有更好的消息！ES6 还为我们提供了另一个与模板字符串配合使用的功能，即带标签的模板字面量。接下来让我们深入研究它们。

## 带标签的模板字面量

带标签的模板字面量允许我们使用“标签”或标签函数与模板字面量结合，从而影响生成的字符串，并产生比单独使用模板字面量可能实现的结果更多的东西。

让我们退一步，看看模板字面量是如何工作的。我们可以利用模板字面量的两个方面来改变结果字符串——*如何*拼接以及如何处理模板内插值的变量。考虑一种情况，我们在模板字符串内插值字符串变量——影响结果的方式取决于字符串对象的能力。例如，我们可以调用`toUpperCase`方法并显示一个相当生动的消息，如下所示：

```
const greeting = 'Hello';
const name = 'Sylvia';
const msg = `${greeting.toUpperCase()}! 我的名字是 ${name}!`;
```

如果我们剖析模板字符串的组成部分，可以看到等式有两部分——字符串的“静态”部分和“动态”部分。我们可以将它们想象成两个数组，如下所示：

*模板字符串的静态部分与动态部分*

*   ① 仅插值两个变量的模板字符串
*   ② `-` 表示固定部分，`_` 表示动态部分
*   ③ 字符串中固定的部分表示为一个数组
*   ④ 模板字符串中动态或已求值的部分

```
const greeting = 'Hello';
const name = 'Sylvia';
const msg = `${greeting}! 我的名字是 ${name}!`; ①
//           ___________-------------_______- ②
const fixedStrings = [", '! 我的名字是 ', '!']; ③
const values = ['Hello', 'Sylvia']; ④
```

就像我们在这里所做的一样，我们可以将*任何*模板字符串整齐地拆分成两个数组。此外，如果我们交错这两个数组——从`fixedStrings`数组中取出第一项，与`values`数组中的第一个值拼接，并继续直到所有项都用完——我们就可以自己重新构建模板字符串！

标签函数正是让我们做到这一点。它们通过提供对模板组成部分（固定部分和动态部分）的引用来让我们拦截模板字符串的求值过程，而标签函数返回的任何值都会被整齐地插入到我们调用它的位置。

我们将从一个简单的例子开始，其中我们将实现模板字符串本身提供的功能。这将让我们有机会理解如何使用标签函数，并检查它们的签名：

*   ① 声明一个标签函数
*   ② 调用标签函数，传入一个模板字符串

```
const handler = (strings, ...values) => { ①
const interleave = (arr1, arr2) =>
arr1.reduce((arr, v, i) => arr.concat(v, arr2[i]), []);
return interleave(strings, values).join(");
};
const greeting = 'Hello';
const name = 'Ernest';
const msg = handler`${greeting}! 我的名字是 ${name}.`; ②
// 输出 'Hello! 我的名字是 Ernest.'
console.log(msg);
```

标签函数有一个独特的调用模式，与普通函数必须将参数包裹在圆括号中不同，标签函数直接接受行内的模板字符串。JavaScript 将模板字符串拆分为固定部分和动态部分，分别传递给标签函数——所有固定部分作为第一个参数数组传入，插值部分按它们在原始模板中出现的顺序依次传入。因此，在我们的例子中，`strings`是一个固定部分的数组，我们使用可变参数语法将所有剩余参数捕获到另一个数组中。

剩下的就很简单了——只需交错这两个数组，从`strings`数组的第一项开始，接着是`values`数组的一项，直到`strings`数组的末尾，然后返回结果。

如果你在控制台中尝试，你会看到可以为它提供任何模板字符串，它会像被 JavaScript 求值一样返回该字符串。

到目前为止，我们实现的东西 JavaScript 已经为我们做了，所以你可能还不相信为什么标签函数是个好主意。让我们尝试一个稍微更复杂的例子——有一个非常流行的编辑器扩展叫做 [Emmet](https://emmet.io/)。安装后，它可以通过提供高度简写的语法，将文本展开为有效的 HTML 代码，从而让你极其快速地编写 HTML（和 CSS）。Emmet 更进一步，在展开后将光标放置在正确的位置，让我们可以输入内部 HTML。考虑以下示例，其中注释表达了开发者在支持 Emmet 的编辑器中输入的内容，然后按`Tab`键，看看 Emmet 会将文本转换为什么（其中`_`表示 Emmet 放置光标的位置）：

```
 TAB -->
_
 TAB -->
_
 TAB -->

```

Emmet 语法显然受到 CSS 选择器的启发，例如`document.querySelector`和 jQuery 接受的语法。Emmet 是一种交互式媒介，因为它可以将光标放置在适当的位置，以便开发者输入代表元素`innerHTML`的文本。

如果我们想以编程方式做类似的事情，即提供受 Emmet 启发的语法，然后我们的代码将其展开为相应的 HTML，会怎么样？当然，我们需要一种表达元素`innerHTML`的方式，因为我们实际上要写出所有的 HTML，并且没有方便地放置光标的奢侈条件，所以我们将采取一种巧妙的方法。我们将使用模板字面量和标签函数，但有一个限制——元素的`innerHTML`必须作为插值变量在模板字符串的末尾提供。换句话说，`h1.title${someVar}`是有效的，但`h1.title.content${someVar}#main`是无效的。这将让我们知道哪些部分组成 HTML 元素，以及将什么文本放入`innerHTML`中。

最后，给定`h1.title${someVar}`，其中`someVar`求值为`some text`，标签函数应返回`<h1 class="title">some text</h1>`。准备好了吗？

*   ① 我们符合 Emmet 的标签函数
*   ② 假设提供的字符串中第一个内容就是元素名称
*   ③ 使用正则表达式获取所有类/ID 标记
*   ④ 如果只是一个没有任何属性的普通元素，则无需操作
*   ⑤ 获取`id`，如果提供了多个 id，则取最后一个
*   ⑥ 构建`id=""`字符串
*   ⑦ 筛选出所有以`.`开头的属性
*   ⑧ 构建`class=""`字符串
*   ⑨ 构建包含 id/class 的起始标签字符串
*   ⑩ 写出完整的元素（包括其`innerHTML`）并返回它

```javascript
function ele([strings], ...values) { ①
const str = strings.trim();
// 假设第一个 . 或 # 之前的内容是元素名称
const [element] = str.split(/[.#]/); ②
// 使用 . 或 # 作为分隔符，将字符串的剩余部分拆分为多个部分
// 这会抓取位于 '.' 或 '#' 与下一个 '.' 或 '#' 之间的所有内容
const attrs = str.match(/.#/g); ③
let idStr = "；
let classStr = "；
if (attrs) { ④
// 查找所有提供的 id
// 如果提供了多个 id，仅使用最后一个
const id = attrs
.filter(a => a.startsWith('#'))
.pop(); ⑤
// 如果没有提供 id，则不拼接 id 字符串
idStr = id
? `id="${id.substring(1, id.length)}"` ⑥
: "；
// 查找所有提供的 class
const classes = attrs
.filter(a => a.startsWith('.'))
.map(v => v.substring(1, v.length)); ⑦
// 如果没有提供 class，则不拼接 class 字符串
classStr = (classes.length > 0)
? `class="${classes.reduce((acc, v) => `${acc}${v} `, ").trim()}"` ⑧
: "；
}
const adornedElement = [element, idStr, classStr]
.reduce((acc, v) => `${acc} ${v}`.trim(), "); ⑨
return `${values.join(")}`； ➉
}
const heading = 'Hello Template Handlers'；
// 输出 'Hello Template Handlers'
console.log(ele`h1 ${heading}`);
// 输出 'Hello Template Handlers'
console.log(ele`h1#main ${heading}`);
// 输出 'Hello Template Handlers'
console.log(ele`h1.title ${heading}`);
// 输出 'Hello Template Handlers'
console.log(ele`h1.title.content#main ${heading}`);
// 输出 'Hello Template Handlers'
console.log(ele`h1.title.content#main ${ele`div${heading}`}`);
// 输出 'Hello Template Handlers'
console.log(ele`h1.title.content#main ${ele`div.banner${heading}`}`);
```

这里涉及的内容很多，所以我们一步一步来。考虑到我们对标签函数使用方式所施加的限制，我们知道包含元素描述的数组将是一个单元素数组。因此，我们通过解构来获取这唯一的元素，并调用 `trim` 方法去除所有多余的空白字符。我们还知道，该字符串由一个元素名称以及类选择器（`.`）和 ID 选择器（`#`）组成，因此我们可以使用 `split` 方法获取第一个选择器出现之前的内容，并将其视为我们要生成的 HTML 元素的名称。

接下来，通过一些正则表达式魔法，将元素名称之后提供的所有选择器抓取到一个数组中。因此，如果用户提供 `h1.title.content#main`，则此正则表达式会将其拆分为一个形如 `['.title', '.content', '#main']` 的数组。我们首先过滤该数组，找到用户提供的所有 ID，如果提供了多个 ID（这是非法的），我们只需取最后一个提供的 ID，从而模拟 Emmet 的行为，并拼接出 `id=` 字符串。然而，多个类（class）*是*允许的，因此我们过滤数组以获取所有提供的类，并拼接出 `class=` 字符串。

剩下的就很简单了——只需将元素名称、id 和 class 字符串组合在一起，确保插入 `innerHTML` 内容（作为插值变量提供），并返回完全组合好的元素。

关于我们的实现，有几点必须强调。首先，我们在函数*内部*使用模板字符串来构建其他字符串。就标签函数而言，除了拥有一个显式的签名外，它们与普通函数并无二致。其次，正如我们在示例中所看到的，我们可以嵌套调用其他（标签）函数，从而创建嵌套的元素结构。由于 JavaScript 在组合字符串之前必须先计算每个插值表达式，实际上，对我们标签函数的嵌套调用会导致最终的字符串由内而外构建——最内层的调用先执行，然后向外层推进。

诚然，我们的实现短期内不会获得任何奖项。它无法处理兄弟元素（Emmet 通过 `+` 运算符支持）或同时创建 `n` 个元素（Emmet 通过 `*` 运算符实现）。然而，它确实让我们得以一窥模板字面量和标签函数的强大之处，以及它们真正能够实现的功能。

标签函数与模板字符串一起提供了多种用例，包括辅助国际化与本地化、语言翻译以及用户输入的清理，其核心本质是将字符串从一种形式转换为另一种形式。我们甚至可以扩展我们的 Emmet 标签函数，以模拟 React 中 JSX 等模板语言所表现出的行为。像 `styled-component` 和 `html-tagged-template` 这样的库为我们提供了绝佳的思路和启发，促使我们在许多常见的日常用例中考虑使用模板字面量。

你能想到在哪些情况下可以通过引入这样的 DSL（领域特定语言）来消除代码中的冗余吗？或者，在为了调试目的而漂亮地打印对象时呢？又或者，在以特定格式显示数据时，例如特定于区域设置的日期和/或货币？

# 总结

生成包含变量插值的字符串一直是一件繁琐的事情，而模板字符串旨在通过提供一种不仅使插值更容易、而且还支持多行字符串的字面量来缓解这一痛点。另一方面，标签函数允许我们拦截模板字符串的构建过程，从而实现一些相当有趣的用例。

在下一章中，我们将把注意力转回对象和数组。对象和数组到目前为止表现得很好，但那些来自其他语言的开发者常常会怀念诸如映射（`Map`）和集合（`Set`）这样的数据结构，以及 JavaScript 中缺少此类数据结构的情况。这将是下一章的主题。同时，我们还将看到`展开运算符`和`解构赋值`是如何与它们协同工作的。

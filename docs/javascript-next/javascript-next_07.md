# 4. 使用对象和数组解构分而治之

JavaScript 允许我们使用对象和数组轻松创建“数据包”，使我们能够流畅地封装数据并在代码中传递。然而，我们用来“触及”这些数据结构的语法往往冗长、命令式且容易出错。在 ES6 和 ES9 中，JavaScript 采用了另一种函数式构造——解构语法，以改善我们解包数据的体验，使其与我们最初封装数据的方式达到一致。

在本章中，我们将了解对象和数组的新解构语法如何提供一种优雅的机制来访问数据结构。我们还将学习将其与我们已掌握的默认参数和剩余参数知识相结合，并了解这两个特性如何协同工作，以定义能清晰表达其预期同时更灵活的函数。在本章结束时，我们将能够使用清晰、简洁且极具表现力的语法安全地查询对象和数组，同时改善我们详细描述函数签名的方式。

## 在结构化与解构之间寻求对称性

JavaScript 为我们提供了两种类似集合的对象——数组和键值对对象。^(²⁵) 使用 `Object` 构造函数、`Object.create` 或字面量对象语法（即 `{}`）创建的对象都是 `Object` 的实例。它们可以被视为关联数组或字典对象。对象本质上是一组键值对。如果要求对象查找某个键的值，它将返回与该键关联的值，如果该键在对象中不存在，则返回 `undefined`。

另一方面，数组提供了一种顺序数据结构，具有高效的随机元素查找功能。JavaScript 中的数组是 `Array` 类型的实例，它们同样具有关联性，只不过它们的键是整数，并且只能是作为它们所指向条目的索引的整数。

对象和数组都为我们提供了“深入”访问它们的方式。对象提供了“点”表示法，允许我们获取自身内部某个键关联的值，以及“括号”（或“下标”）表示法（即 `[]`）也能达到同样效果。而数组只提供括号表示法作为在数组中特定索引处查找元素的手段。与对象非常相似，查找数组中不存在的索引会返回 `undefined`。

对象和数组都可以嵌套，通常相互嵌套。这可能导致相当复杂的查找，迫使开发者内联变量来解释他们试图实现的目标。请看：

- ① 使用明显的语法
- ② 重构代码以使意图更清晰
- ③ 如果地址对象没有 `zip` 属性会发生什么？

```javascript
const user = {
  name: 'douglas',
  profession: 'developer',
  address: {
    street1: '1 Ad Infinitum Drive',
    street2: '',
    city: 'Cupertino',
    state: 'CA',
    zip: [
      '95014',
      '1234',
    ],
  },
};
const zipCode = user.address.zip[0] + '-' + user.address.zip[1]; ①
console.assert(zipCode === '95014-1234');
// 重构后的版本
const zip = user.address.zip; ②
const code = zip[0]; ③
const extended = zip[1];
const final = code + '-' + extended;
console.assert(final === '95014-1234');
```

思考一下，如果我们没有创建原始对象，而是获得了它的一个引用，我们如何确定其结构。我们必须进行一些脑力体操，通过逆向解析查找过程来“重建”原始对象的结构。当函数期望接收一个对象或数组时，这更加令人沮丧——作为调用者，如果不查看函数实现或阅读文档，根本无法判断该函数真正关心参数的哪些“部分”。

雪上加霜的是，这种语法在沿途并没有提供任何 `undefined` 检查机制！如果中间某个属性的查找失败，这种失败会级联影响到所有依赖该属性值的内容。一些语言提供了“安全导航”运算符，或者在查找失败时设置默认值的方式，但可惜的是，JavaScript 对这两种方式都不支持。

核心问题在于我们定义对象和数组（创建*结构*）的方式与访问它们（*解构*它们）以获取特定值的方式之间缺乏对称性。如果查找语法能够镜像构造语法，那么“重新组装”原始对象（或数组）将变得轻而易举，因为赋值语句的左侧将和右侧一样具有表现力。

解构支持缺失的另一个方面是无法展开或“打散”对象；换句话说，就是获取集合中的所有条目，无论是数组的元素还是对象中的键值对。开发者不得不强行遍历整个集合，无论是显式地使用 `for` 循环，还是隐式地使用像 `forEach` 这样的方法，这两者都有很大的改进空间。

进入展开运算符和新的解构语法。我们将从展开运算符开始，然后是解构语法。

## 数组的展开运算符

考虑一个简单的用例——一个计算三角形周长的函数和一个存储各边边长的数组。让我们看看如何将两者结合使用：

- ① 我们从一个数组开始
- ② 我们提取数组中的每一个元素提供给函数

```javascript
const perimeter = (a, b, c) => a + b + c;
const sides = [9, 8, 3]; ①
// 打印 20
console.log(perimeter(sides[0], sides[1], sides[2])); ②
```

鉴于函数期望三个参数，我们被迫使用下标表示法从数组中分解出这些值。这感觉很繁琐。理想的情况是我们可以将数组的各个元素作为参数“应用”到函数中。

好吧，现在我们可以了！我们现在可以使用展开运算符，它通过 `...` 语法来表达。观察同样的例子是如何变成下面这样的：

- ① 我们从一个数组开始
- ② 我们使用展开运算符将数组的所有元素提供给函数

```javascript
const perimeter = (a, b, c) => a + b + c;
const sides = [9, 8, 3]; ①
// 打印 20
console.log(perimeter(...sides)); ②
```

演示的展开运算符语法使用 `...` 作为其语法结构。它接收一个数组，并将其“展开”为独立的元素，将每个元素作为单独的参数传递给函数。这立即消除了我们必须使用下标语法强制提取元素的需要。

在我们的代码中有几个地方允许使用展开运算符——首先，正如我们所见，是在函数调用时，其次，是在数组构建时，我们将在下一节中看到。

### 深入解析`展开操作符`的微妙之处

最好先单独研究展开操作符。以我们的老朋友`console.log`为例。`log`是一个多参数函数，即给定`n`个参数时，它会将每个值用空格分隔后写入控制台。我们直接用其来观察展开操作符的效果：

-   ① 从一个数组开始
-   ② 直接打印数组——显示`[ 12, -3, 15, 44, 15, 36 ]`
-   ③ 使用展开操作符——显示`12 -3 15 44 15 36`
-   ④ 用`console.log`模拟展开操作符的工作方式

```javascript
const arr = [12, -3, 15, 44, 15, 36]; ①
// 打印 '[ 12, -3, 15, 44, 15, 36 ]'
console.log(arr); ②
// 打印 '12 -3 15 44 15 36'
console.log(...arr); ③
// 要实现与使用展开操作符相同的结果
let temp = "";
for (const i in arr) {
  temp += arr[i];
  if (i != (arr.length - 1)) {
    temp += ' ';
  }
}
console.assert(temp === '12 -3 15 44 15 36'); ④
```

我们可以得出结论：将数组作为参数调用`console.log`实际上是只传递了**一个**参数。然而，使用展开操作符作用于数组进行调用时，则会传递`n`个参数，其中`n`是数组的长度。

当我们思考如何将数组的*每个*元素打印为一个空格分隔的字符串时，对比会更加明显。如果没有展开操作符，我们别无选择，只能强制性地遍历数组，每次拼接到临时字符串中，然后将该字符串传递给`console.log`。

展开操作符使我们能够从命令式思维（我们的意图常常迷失在`for`循环和固定模式中）转变为以清晰的方式表达意图。

展开操作符的一个普遍用例是连接数组。请记住，数组有一个`push`方法，用于将元素添加到数组末尾。事实证明，`push`也是一个多参数函数。然而，与某些`Math`操作符和`console.log`类似，如果要将一个数组的所有元素连接到另一个数组，此方法几乎无用。^(²⁶)

展开操作符的另一个用例是从现有数组创建新数组。现在我们研究这两个用例：

-   ① 使用展开操作符将数组复制到新数组
-   ② 从三个数组开始
-   ③ `push`会原地修改数组
-   ④ 创建一个连接了元素和一个数组的*新*数组
-   ⑤ 创建另一个连接了两个数组的数组

# JavaScript 数组与对象的展开操作符

## 数组的展开操作符

```javascript
const one = [12, -3, 15];
const otherOne = [...one]; ①
const two = [44, 15, 36]; ②
// 修改操作
one.push(...two); ③
console.log(one);
// 或者内联进行连接
const concatenated = [12, -3, 15, ...two]; ④
// 打印 '[ 12, -3, 15, 44, 15, 36 ]'
console.log(concatenated);
// 创建一个新数组
const newArr = [...otherOne, ...two]; ⑤
// 打印 '[ 12, -3, 15, 44, 15, 36 ]'
console.log(newArr);
```

我们从数组开始，通过将第一个数组展开到新数组的字面量表示法（`[]`）中来创建新数组。换句话说，`otherOne`是一个新数组，包含与初始数组相同的元素。

与`console.log`一样，`Array`上的`push`方法恰好是一个多参数方法。因此，我们可以再次使用展开操作符，轻松地将一个数组中的多个元素推入另一个数组。但是，`push`会执行修改操作，即它会改变原数组。然而，函数式编程鼓励不可变性，如果这是我们的意图，那么展开操作符便是盟友。^(²⁷)

展开操作符的一个微妙之处在于它**不**执行“扁平化”操作。如果我们展开一个数组的数组，最终结果将是各个组成数组。展开操作符不会递归地展开嵌套数组。

使展开操作符工作的底层机制依赖于数组是“可迭代的”。我们稍后会介绍可迭代对象和迭代器；不过可以这么说，数组遵循迭代器协议，因此可以在展开操作符中使用。字符串、`Map`和`Set`（我们很快也会看到它们）也是可迭代的，因此可以被展开。^(²⁸)

使用展开操作符构建新数组的最大好处往往也是最容易被忽视的一点，即它的语法迫使我们将现有数组展开到一个新数组中。我们可以通过将现有数组`push`到一个空数组上来实现相同的行为，但这并非`push` API 的意图。相反，它的意图是修改现有数组，这与函数式编程的原则背道而驰。

## 展开与剩余——极性相反的双胞胎

读者会注意到剩余参数和展开操作符的语法相同，但它们的行为却完全相反。剩余参数将提供给函数的所有未说明参数“收集”*到*一个数组中，而展开操作符则将数组中的所有元素提取*出来*。`...`语法的作用取决于调用上下文。`...`仅在发生赋值时充当剩余参数，否则，它充当展开操作符。这种矛盾既有趣又令人不安：

-   ① 在将整个数组附加到返回值之前，先对剩余参数进行排序

-   ② 对剩余参数进行排序，并将其展开以将其元素附加到返回值中

```javascript
const onlyRest = (teacher, ...students) => {
return [teacher, students.sort()]; ①
};
const restAndSpread = (teacher, ...students) => {
return [teacher, ...students.sort()]; ②
};
// 打印 '[ 'Ada', [ 'Carol', 'Grace', 'Mary' ] ]'
console.log(onlyRest('Ada', 'Mary', 'Carol', 'Grace'));
// 打印 '[ 'Ada', 'Carol', 'Grace', 'Mary' ]'
console.log(restAndSpread('Ada', 'Mary', 'Carol', 'Grace'));
```

我们首先定义两个多参数函数，都期望接收教师姓名，后跟 n 个学生姓名。由于两个函数都声明了一个剩余参数，教师之后的所有参数都会自动打包到一个数组中。两个函数在构建返回值之前，也会对`students`数组进行`sort`排序，返回值也是一个数组。然而，实现方式在此处出现了分歧。对于第一个函数，我们简单地用一个包含教师姓名的数组以及`sort`排序学生数组（返回一个数组）的结果构建一个新数组。结果正如预期，是一个包含两个元素的数组——教师姓名，后跟一个包含排序后学生姓名的数组。

然而，在第二种情况下，我们将`sort`的结果*展开*到返回值中，从而直接返回一个字符串数组，以教师姓名开头，后跟按字母顺序排序的学生姓名。两种实现之间的差异很微妙，但效果却大相径庭。

我们还会看到剩余参数适用的另一个场景，即数组解构——但首先，来看看对象的展开。

## 对象的展开操作符

在 ES9 中引入，`…`操作符也可用于“展开”对象。与我们看到的用于索引集合的`…`操作符非常相似，`…`操作符会将对象“展开”为其各个键值对。然而，在深入探讨展开对象的细节之前，我们必须先讨论对象属性的特性，特别是`enumerable`描述符。

### `Object.defineProperties`

JavaScript 开发者习惯于使用 `{}` 语法直接创建对象，并随意添加键值对。这些键默认是可枚举的，也就是说，如果使用 `for-in` 循环遍历对象中的键，它们都会被列出。

同时，`Object` 类也为我们提供了多种（编程式的）机制来创建对象，以及配置它们的便利方法。其中一个 API 是 `defineProperties`，它可以与一个“描述符”对象一起使用，为现有对象定义函数，甚至 getter/setter。^(²⁹) `Object.defineProperties` 的作用是使用描述符向现有对象（以下简称“目标”）注入属性。

描述符充当一个占位符，用于包含我们想要引入到目标对象的每个键的配置。描述符对象是一个普通的 JavaScript 对象，它的键将被安装到目标对象上。让我们通过一个简单的例子来看看它的用法：

- ① 使用目标对象和描述符对象调用 `defineProperties`

- ② 使用 `value: 'Michelle'` 定义 `name` 键

```javascript
const michelle = {};
Object.defineProperties(michelle, { ①
name: {
value: 'Michelle', ②
},
hobby: {
value: 'Gardening',
},
});
// 输出 'Michelle'
console.log(michelle.name);
// 输出 'Gardening'
console.log(michelle.hobby);
```

第一个参数是我们想要修改的对象，第二个参数恰好是描述符对象，我们可以看到它是一个包含两个键的 JavaScript 对象。描述符对象中每个键的值就是该属性的配置，并决定了它在目标对象中的形式。也就是说，我们要求 `defineProperties` 在目标对象上安装两个属性，即 `name` 和 `hobby`，以及它们各自的值。

前面提到的这个 `value` 属性**并非**任意指定的；它是我们允许使用的少数几个成员之一，详情见 [`https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/defineProperties`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/defineProperties)。这些属性不仅允许我们在目标对象上定义一个结果属性作为值（记住，在 JavaScript 中函数也是值），还允许定义 getter/setter，以及控制键是否为 `enumerable`、`writable` 和 `configurable`。

其中，`enumerable` 对于我们即将讨论的 `Object.assign` 特别重要，所以让我们花点时间探讨它的用法和含义。就像我们使用描述符对象为某个键设置 `value`，并通过 `Object.defineProperties` 安装它一样，我们也可以提供 `enumerable` 设置。如果在描述符对象中没有将 `enumerable` 设置与 `value` 键一起提供，其默认值为 `false`。这与直接创建的对象（`{}`）中键的默认设置（我们已讨论过，默认为 `true`）形成鲜明对比。这意味着，如果我们要遍历结果对象的键，使用描述符对象创建的任何属性都**不会**出现，除非我们*显式*地将 `enumerable` 属性设置为 `true`：

- ① 将 `enumerable` 键设置为 `true`

- ② 由于此处未设置 `enumerable`，它默认为 `false`

- ③ 只有 `name` 会显示出来

```
const michelle = {};
Object.defineProperties(michelle, {
name: {
value: 'Michelle',
enumerable: true, ①
},
hobby: {
value: 'Gardening', ②
},
});
for (const k in michelle) {
if (Object.prototype.hasOwnProperty.call(michelle, k)) {
// 只输出 'name'
console.log(k); ③
}
}
```

这里需要注意的是，任何没有设置 `enumerable` 属性的属性对于 `for-in` 循环都是`不可见`的。如果我们希望所有键都可见，直接使用对象字面量语法创建对象就可以了！也就是说，`Object.defineProperties` 的作用是让我们能够`限制`外界如何看待或影响我们对象中的键。

回到正题，设置某些键的可枚举性会影响任何需要查询对象键的算法，例如 `JSON.stringify`，以及 ES6 引入的两个新功能：新增的 `Object.assign` 和对象展开运算符。

我们将在后续章节中分别介绍 ES6 引入的 `Object.assign` 和 ES9 引入的对象展开运算符。乍看之下，它们做的事情相似，但正如我们将看到的，它们的意图截然不同。

### `Object.assign`

ES6 提供了 `Object.assign`，作为一种将一个对象的所有可枚举键复制到另一个对象的方法。`assign` 接受一个“目标”对象，后跟任意数量的“源”对象，并将源对象的所有`可枚举`键复制到目标对象上。考虑以下示例：

- ① 使用对象字面量初始化一个对象

- ② 使用 `Object.assign` 创建一个新对象，合并所有源对象

```
const michelle = { ①
name: 'Michelle',
hobby: 'Gardening',
};
const rachael = Object.assign({}, michelle, { ②
name: 'Rachael',
profession: 'Auditor',
});
// 输出 '{ name: 'Rachael', hobby: 'Gardening', profession: 'Auditor' }'
console.log(rachael);
```

我们首先使用字面量创建了一个包含两个键的对象。回想一下，对象上定义的所有此类属性默认都是可枚举的。如果使用 `Object.defineProperties` 并将每个键的 `enumerable` 描述符设置为 `true`，我们也可以达到同样的效果。

接着，我们调用 `Object.assign`，传入一个（空的）目标对象，以及 `michelle` 和另一个（内联的）对象字面量。这里需要注意的是，`michelle` 和内联对象都有一个同名的属性，即 `name`。因此，如果要将二者都复制到同一个对象上（按从左到右的顺序），那么最后一个覆盖前面的，对吧？

正如 `console.log` 所示，克隆对象确实包含了各个源对象中属性的并集。*然而*，`name` 的值是 `Rachael`，这告诉我们属性确实是按照从左到右的顺序复制的；换句话说，作为源对象传入的 `michelle` 和内联对象拥有相同的属性，但后者胜出。

可以将 `Object.assign` 理解为将源对象“展开”到目标对象中，如果发生键冲突，则后者的值胜出。此外，我们可以巧妙地利用这一点，通过指定一个空对象作为目标，从现有对象创建新对象，如示例所示。

表面上，`Object.assign` 对对象的作用类似于展开运算符对可迭代对象的作用——它可以帮助将一个对象的键值对“展开”到另一个对象中。然而，它在两个方面有所不足——展开对象的机制（`Object.assign`）和展开可迭代对象的机制（展开运算符）并不对等，因为它们的语法不同。其次，`Object.assign` 之于对象，犹如 `Array.push` 之于数组，它们都会*改变*目标对象。诚然，我们可以提供一个空对象作为目标，但该 API 的意图就是修改目标。

`Object.assign` 在我们的工具包中占有一席之地；然而，如果我们想采用函数式编程思维并拥抱不可变性，那么我们需要另一个帮手。请允许我向您介绍对象展开运算符。

### 展开对象

ES9^(³⁰) 将我们用于展开可迭代对象的运算符（即 `...`）引入，使其可用于对象。我们可以通过回顾之前的示例来演示这一点：

- ① 使用展开运算符

```
const michelle = {
  name: 'Michelle',
  hobby: 'Gardening',
};
const rachael = {
  ...michelle, ①
  ...{
    name: 'Rachael',
    profession: 'Auditor',
  },
};
// 输出 '{ name: 'Rachael', hobby: 'Gardening', profession: 'Auditor' }'
console.log(rachael);
```

我们从简单的对象开始，尝试将一个或多个对象展开到新对象中来构建新对象。除了用展开运算符替代 `Object.assign` 之外，此示例与我们之前的尝试并无显著差异。然而，新的 `...` 对象语法确实使我们与展开可迭代对象的方式达成一致。同样，展开运算符仅复制被展开对象的可枚举属性。

另外请注意，展开运算符与 `Object.assign` 一样，会遵循我们提供源对象的顺序。如果两个或多个被展开的对象恰好包含相同的键，则后出现的键会覆盖前者。

正如我们在上一节中讨论的，`Object.assign` 与展开运算符的重要区别在于是否存在副作用。`Object.assign` 接受一个目标对象（作为第一个参数），后跟任意数量的源对象。接着它会*改变*目标对象，将源对象的可枚举键复制到目标对象中，然后`返回`目标对象。如果提供的目标恰好是一个现有对象，则正是该对象会获得来自源对象的键，从而改变该对象。

相反，展开运算符的语法并未提供此类途径。展开运算符的语法迫使我们只能将现有对象展开到*新的*对象中。换句话说，展开运算符的语法鼓励不可变性。

## 解构

在之前的讨论中，我们探讨了数组和对象在结构化（创建）与解构（提取）之间缺乏对称性的问题。我们提到了现有方法的若干局限性，包括冗长的语法、无法为“缺失”部分设置默认值，以及函数签名在说明其如何使用参数方面缺乏表现力。现在，让我们了解新的解构语法，以及它如何解决这些问题，同时也会涉及一些注意事项。

### 数组解构

数组的解构语法反映了其顺序特性。请注意观察。

- ① 我们从表示粉色 `rgba` 值的数组开始

- ② 使用解构语法从数组中提取值

- ③ 访问数组中没有对应索引的元素会返回 `undefined`

- ④ 如果我们只想访问数组中的特定项，则忽略其他索引

```
const rgba = [239, 15, 255, 0.9]; ①
const [r, g, b, a, nonExistent] = rgba; ②
console.assert(r === 239);
console.assert(g === 15);
console.assert(b === 255);
console.assert(a === 0.9);
console.assert(nonExistent === undefined); ③
const [, , blue] = rgba; ④
const blueAgain = rgba[2];
console.assert(blue === b);
console.assert(blueAgain === b);
```

数组解构语法在表达式左侧（即赋值侧）使用 `[]` 语法。如我们所 见，解构赋值允许我们按位置顺序在作用域内声明变量，就像我们为数组定义元素一样。现在，赋值左侧的语法与右侧对称。该语法还允许我们跳过不需要的索引。

对于仅提取一个元素的情况，使用数组解构的价值可能存疑，因为可以直接使用方括号表示法，这个论点也是合理的。然而，当需要从数组中提取多个元素时，解构的回报无疑使其更值得使用。尽管如此，我们承认方括号表示法或 `length` 等运算符仍然具有相关性，应在适当场合按需使用。

此外，观察赋值语句，我们可以尝试*推断*^(([31])(#fn31))右侧数组的结构。

解构数组元素**不会**违反我们在使用方括号表示法时已习惯的语义。就像请求数组中超出其`大小`的索引处的元素会返回 `undefined` 一样，解构也是如此。

因此，任何对 `undefined` 进行解构的尝试都会导致错误。事实上，解构使用的是与展开运算符相同的可迭代机制。因此，对任何不遵循迭代器接口（我们稍后会介绍）的内容进行解构都会导致错误。^(([32])(#fn32))

与默认参数类似，我们也可以为变量赋值设置默认值，以防数组中不存在所需的索引，如下所示：

- ① 从一个表示四边形的数组开始

- ② 假设为菱形，使用默认值进行解构

- ③ 假设为正方形，使用默认值进行解构

# 数组解构

```javascript
const quadrilateral = [10, 15, 10, 15]; ①
const [q1 = 10,
       q2 = 20,
       q3 = q1,
       q4 = q2] = quadrilateral; ②
console.assert(q1 === 10);
console.assert(q2 === 15);
console.assert(q3 === 10);
console.assert(q4 === 15);
const [sq1 = 10,
       sq2 = sq1,
       sq3 = sq1,
       sq4 = sq1] = []; ③
console.assert(sq1 === 10);
console.assert(sq2 === 10);
console.assert(sq3 === 10);
console.assert(sq4 === 10);
```

就像函数参数中的默认参数一样，我们不仅可以在原始数组中不存在某变量时为其设置默认值，而且右侧的变量还可以引用之前提取元素的值作为默认值！

JavaScript 中的函数调用也会执行赋值操作；方法签名中的参数会依次分配给参数列表中的每一项。事实证明，我们可以直接在方法签名中对数组进行解构，同时还可以为数组中不存在的元素设置默认值：

- ① 为整个数组以及数组中的每个元素设置默认值
- ② 无参数调用触发默认值
- ③ 实际上等同于上述操作
- ④ 计算正方形的周长
- ⑤ 计算长方形的周长
- ⑥ 计算梯形的周长

```javascript
const perimeter = ([s1 = 10,
s2 = s1,
s3 = s1,
s4 = s2] = []) => { ①
return s1 + s2 + s3 + s4;
};
console.assert(perimeter() === 40); ②
console.assert(perimeter([]) === 40); ③
console.assert(perimeter([15]) === 60); ④
console.assert(perimeter([15, 20]) === 70); ⑤
console.assert(perimeter([15, 20, 18, 23]) === 76); ⑥
```

我们之前学到的关于默认参数的所有内容都适用。我们可以像使用默认参数语法那样，对整个参数设置默认值，但如果参数恰好是一个数组，我们可以进行内联解构，同时为每个我们关心的元素提供默认值。

其明显优势在于函数签名更具表现力，代价是略显冗长。适当的格式化在此很有帮助，使用换行将参数的各个部分分解开来，是一种广泛采用的技术。

最后，我们还可以结合数组解构使用剩余参数。^(³³) 这允许我们深入到数组中，抓取所有我们感兴趣的元素，同时将剩余的元素“吸”入另一个数组。

- ① 这里的 `rest` 是一个数组，包含所有未被考虑的元素
- ② 递归处理剩余元素

```javascript
const movies = ['记忆碎片', '蝙蝠侠：侠影之谜', '黑暗骑士'];
const [first, ...rest] = movies; ①
console.assert(first === '记忆碎片');
console.assert(Array.isArray(rest));
const [head, ...tail] = rest; ②
console.assert(head === '蝙蝠侠：侠影之谜');
console.assert(Array.isArray(tail));
```

就像函数签名中的剩余参数一样，解构中使用 rest 模式**必须**是最后一个赋值项。

正如我们所见，这在递归算法中极为有用^(³⁴)：

- ① 边界情况检测
- ② 提取我们感兴趣的元素
- ③ 如果需要则递归

```javascript
const or = (...args) => {
if (args.length === 0) return null;
if (args.length === 1) return args[0]; ①
const [first, ...rest] = args; ②
return first || or(...rest); ③
};
console.assert(or(null, undefined, true, false, '1'));
console.assert(!or(null, undefined, false));
```

最后，数组解构也可用于嵌套数组。我们再次注意到赋值与构造之间的对称性：

- ① 当索引查找失败时，为内部数组查找提供默认值
- ② 嵌套解构

```javascript
const ticTacToe = [
['x', 'o',  'x'],
['o', 'x', 'o'],
['x', 'o', 'x'],
];
const [
[cell01] = [],
[, cell11] = [],
[, , cell22] = [], ①
] = ticTacToe; ②
console.assert(cell01 === 'x');
console.assert(cell11 === 'x');
console.assert(cell22 === 'x');
```

这个例子揭示了一个容易出错的地方。回想我们之前的讨论，访问一个数组中**不**存在的索引会得到 `undefined`。如果我们要查找的值位于顶层，这或许可以接受；然而，如果这是一个嵌套查找，那么这**将**导致错误。考虑到我们试图解构 `undefined`，这是合理的。这里的预防措施可能是在解构之前，先对整个（嵌套）查找设置默认值，正如此处所示。

数组解构的一个用例是让我们可以假装函数`返回`多个值：

- ① `返回`一个数组（在此例中是一个元组）
- ② 通过解构从返回值中获取多个值

```javascript
const distanceAndSlope = ([x1, y1], [x2, y2]) => {
const distance = Math.hypot(x2 - x1, y2 - y1);
const slope = (y2 - y1) / (x2 - x1);
return [distance, slope]; ①
};
const [dist, slope] = distanceAndSlope([4, 3], [10, 12]); ②
console.assert(Number.parseFloat(dist.toFixed(2)) === 10.82);
console.assert(slope === 1.5);
```

JavaScript 中有许多方法返回数组（`RegExp.split` 便是一例），数组解构为我们提供了一种便捷且优雅的方式来使用这类函数的结果集。

数组解构常用于解构剩余参数。正如我们所看到的，剩余参数将所有“额外的”参数捕获到一个数组中，这个数组是可展开的。如果我们希望将剩余参数数组中的第一个元素与其他元素分开处理，这一点尤其有用。我们在递归解决方案中经常看到这种用法，如下所示：

- ① 终止条件
- ② “展平”数组的核心逻辑

```javascript
const flatten = ([first, ...rest]) => {
if (first === undefined) return []; ①
return !Array.isArray(first)
? [first, ...flatten(rest)]
: [...flatten(first), ...flatten(rest)]; ②
};
const flattened = flatten([
[1, 2],
[3], 4, 5, [6, 7],
]);
console.assert(flattened.length === 7);
console.assert(flattened.join() === '1,2,3,4,5,6,7');
```

我们利用了这样一个事实：如果没有提供剩余参数，解构将导致所有元素被评估为 `undefined`。这作为递归的终止条件，否则我们继续递归。

除了巧妙运用解构和展开运算符外，这个例子还强调了 ES6 引入的新语法如何让我们在 JavaScript 中以惯用的方式实现函数式编程。给定一个展平数组的场景，我们的逻辑思路是：查看数组的第一个元素；如果它本身也是一个数组，则先展平该数组，再展平原数组的剩余元素。这个算法在我们的实现中清晰呈现，无需命令式循环和不必要的计数器，我们的真实意图一目了然。

# 对象解构

正如大家所料，对象的赋值运算符是 `{}`。数组通过位置进行索引，而对象则使用键值对。因此，在解构时，我们需要在赋值语句中指定我们感兴趣的*键*。请看：

- ① 我们从一个对象开始
- ② 对象解构的完整形式
- ③ 对象解构的简写形式

# JavaScript 对象解构详解

```javascript
const paip = {
  name: 'Paradigms of Artificial Intelligence Programming',
  author: 'Peter Norvig',
  isbn: 1558601910,
}; ①
const {
  name: n,
  isbn: id,
} = paip; ②
console.assert(n === 'Paradigms of Artificial Intelligence Programming');
console.assert(id === 1558601910);
const {
  name,
  isbn,
} = paip; ③
console.assert(name === 'Paradigms of Artificial Intelligence Programming');
console.assert(isbn === 1558601910);
```

对象解构提供了两种语法变体。当我们在作用域中引入的变量名称**不**与被解构对象中的键名一致时，使用较长的版本。如果新变量的名称与它们要查询的键名相同，则使用简写形式更为方便。

从语法和语义上讲，这与数组解构没有显著区别，唯一的区别在于对象不能按位置索引，而必须指定要查找的键。

数组解构中所有可用的功能在这里同样适用——针对不存在的键返回 `undefined`、默认值、嵌套查找，以及在方法签名中支持解构，所有这些都可以通过对象解构实现。

**不**适用的一点是，新变量无法引用之前已声明的变量，因为“之前”暗示了一种顺序性，而这在关联哈希中是不存在的。

让我们探索所有这些方面：

- ① 我们从一个对象开始
- ② 使用嵌套解构
- ③ 使用长格式和短格式的默认值
- ④ 为整个嵌套查找设置默认值，以防原始对象中缺少该键
- ⑤ 函数参数中的解构与默认值

```javascript
const config = {
  size: 200,
  transitionMs: 750,
  clip: {
    width: 200,
  },
}; ①
const {
  size,
  transitionMs,
  clip: { ②
    width: w = 100, ③
    height = 100,
  } = {}, ④
} = config;
console.assert(size === 200);
console.assert(transitionMs === 750);
console.assert(w === 200);
console.assert(height === 100);
const drawChart = ({
  size = 200,
  transitionMs = 1000,
  clip: {
    width: w = 100,
    height = 100,
  } = {},
} = {}) => { ⑤
  return [size, transitionMs, w, height];
};
// 调用它
drawChart();
```

与数组一样，如果我们尝试查找对象中不存在的键，会返回 `undefined`。同样，明智的做法是在查找嵌套对象中的键*之前*，先为其整个结构设置默认值。

## 结合使用数组和对象解构

当然，我们可以混合使用对象和数组解构。让我们重温之前的例子，看看如何结合两者来提取我们感兴趣的部分：

- ① 解构外部对象
- ② 由于 `address` 本身也是一个对象，我们也对其进行解构
- ③ `zip` 恰好是一个数组
- ④ 同时获取 `zip` 中的两个索引值

```javascript
const user = {
  name: 'douglas',
  profession: 'developer',
  address: {
    street1: '1 Ad Infinitum Drive',
    street2: "",
    city: 'Cupertino',
    state: 'CA',
    zip: [
      '95014',
      '1234',
    ],
  },
};
const { ①
  address: { ②
    zip: [ ③
      zip, ④
      extended,
    ],
  },
} = user;
const final = zip + '-' + extended;
console.assert(final === '95014-1234');
```

我们的目标是提取用户的完整邮政编码，其元素恰好位于一个数组中，该数组嵌套在 `address` 对象内，而 `address` 本身又是一个 JavaScript 对象字面量的属性。因此，我们必须运用嵌套解构的技巧，小心地剖析原始结构，以便精确地检索出我们想要的内容。我们从解构外部对象开始，这引导我们找到 `address` 键，然后再次对其进行解构以获取 `zip` 数组。最后，我们可以使用数组解构语法按索引获取构成邮政编码的元素。呼！

我们终于完成了整个循环。复杂的查找和不必要的变量都已不复存在。剩下的仅仅是我们想要的东西。并且，结构化与解构之间的对称性再次显现。

## 注意事项

最后还有一个与函数签名中的解构相关的局限。如果我们解构传递给函数的参数，就会丢失对整个对象（或数组）的引用。换句话说，我们需要做出选择——要么解构以获取我们需要的部分，要么获取整个对象并在函数实现内部进行解构，这样我们就可以在后续继续使用整个对象。虽然这听起来像是边缘情况，但有时我们需要使用对象的部分属性，然后将整个对象传递给下游做进一步处理。像 Clojure 这样的语言提供了 `:as` 关键字，以便在解构的同时保留对整个对象的引用。不幸的是，JavaScript 没有提供这样的补救措施。

## 一个小区别

适用于可迭代对象的展开运算符和剩余运算符，与适用于对象的运算符不同，因为对象是**不可迭代**的！虽然对于可迭代对象和对象，展开运算符和剩余运算符看起来和行为一致，但它们底层使用的机制却截然不同。我们应该将适用于对象的展开运算符和剩余运算符视为*新的*语法，而不是将其看作是可迭代对象运算符的扩展。

这种差异在我们尝试将展开运算符与多参函数（如 `console.log`）结合使用时也会显现出来。回想一下，如果我们有一个可迭代对象（如数组）并希望将其内容传递给 `console.log`，我们可以简单地使用 `console.log(...arr)` 来调用它。这将“展开”数组，将数组中的元素作为单独的参数传递给 `log`。但这对于对象是行不通的，这再次温和地提醒我们，对象是不可迭代的，并且不能适用于所有可迭代对象的用例。

# 总结

正如我们所看到的，展开运算符提供了一种非常强大的机制，可以一次性获取数组的`所有`元素。这在处理多参函数，以及从其他数组创建或拼接数组时尤其有用。

另一方面，解构语法提供了一种使用`领域特定语言`（DSL）来查询数据的方法，而这种 DSL 的语法与我们最初用来创建对象的语法非常相似。因此，这种 DSL 同样富有表现力，并且通过额外的功能（如为缺失的属性或索引设置默认值），这成为我们 `JavaScript` 工具箱中又一个有用的工具。

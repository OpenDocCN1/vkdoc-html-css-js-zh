# 首次发布与优化技巧

在 npm 注册中心注册账号后，你就可以发布开源模块。完成注册后，只需输入 `npm publish` 即可将模块发布到注册中心。在发布 `lounger` 之前，我想介绍一些优化发布包的好方法。本节将讲解如何从体积和安装时间两个维度优化你的包。

## 优化安装体积

保持安装体积小巧的方法之一是在根目录添加 `.npmignore` 文件。它的工作方式类似 `.gitignore` 文件，npm 不会将其中列出的文件和目录包含在发布的包中。

根据使用模块时不需要的文件类型，我们可以为用户节省大量硬盘空间，同时也能节省大量带宽。

通过排除单元测试、集成测试以及编译文档的源文件，我们可以节省一些空间：

```
/test/
/docs/
build.js
.DS_Store
npm-debug.log
```

## 加快安装速度

另一个显著加快安装速度的好方法是将所有生产依赖都包含在发布的模块中。我们可以通过将它们添加为 `package.json` 中的 `bundleDependencies` 来告诉 npm 将它们与模块打包在一起：

```json
"bundleDependencies": [
  "config-chain",
  "nopt",
  "npmlog",
  "opener",
  "osenv",
  "request"
]
```

打包依赖可以大大缩短安装时间，因为在安装过程中我们省略了每个依赖项及其依赖项的小型 HTTP 请求。使用当前的 npm，宽带连接的安装时间从 20 秒减少到 5 秒。同时，打包依赖还能确保即使某个模块被取消发布，我们的包仍然可以安装。

现在运行 `npm publish`，我们将发布一个高度优化版本的包。
